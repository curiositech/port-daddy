# pd-console zoom controls proof

## What this proves

- The title deck exposes visible zoom-out, reset-percentage, and zoom-in controls.
- The percentage changes across 80%, 100%, 130%, and 200% frames.
- At 200%, secondary title content collapses while the zoom controls and CLI control remain visible.
- Every frame has a visible provenance watermark and comes from pd-console's deterministic, render-agnostic capture path.

![Zoom control sequence](zoom-controls.gif)

## Evidence

- [80%](zoom-80.png)
- [100%](zoom-100.png)
- [130%](zoom-130.png)
- [200%](zoom-200.png)

The proof was generated by the successfully compiled native binary:

```text
CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_DEV_INCREMENTAL=false cargo build \
  --manifest-path core/pd-console/Cargo.toml --offline --features gpui \
  --bin pd-console -j 2

core/target/debug/pd-console \
  --headless-zoom-capture <output.png> --zoom-percent <80|100|130|200>
```

## Provenance boundary

The GPUI app was launched successfully at 130%, and its native window was found by process ID. macOS denied exact-window `screencapture` under the current Screen Recording permission, so no full-screen or unrelated-window fallback was used. The checked-in images and GIF are therefore intentionally labelled as render-agnostic title-deck proofs, not GPUI/Metal framebuffer captures.
