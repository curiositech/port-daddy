# HITL interruptions pane — three contract render states

Provenance: **Block-model offscreen raster** (`headless_capture::render_blocks`
over the pane's real `view_blocks` output, locked DARK theme), NOT a GPUI/Metal
framebuffer capture — the pinned `gpui = 0.2.2` exposes no offscreen Metal
readback (see `src/headless_capture.rs` and
`docs/artifacts/gpui/HEADLESS-CAPTURE.md` for the full analysis). The GPUI face
paints the SAME `Block`s; these PNGs are the render-agnostic contract made
visible, regenerated by `tests/interruptions_unit.rs::renders_the_three_contract_states_to_real_pngs`
(which writes byte-identical sources to `../target/hitl-*.png` on every test
run — the committed copies here are `sips`-recompressed for repo size).

## States (docs/hitl-interruptions.md §4)

- [state-empty.png](./state-empty.png) — honest empty state: a live poll with
  zero open asks renders "no open interruptions" + a resting `clear` chip,
  never a hidden widget.
- [state-open-normal.png](./state-open-normal.png) — open normal/low asks:
  title, urgency, source agent, age per row; deep-link chip to the web
  answer surface.
- [state-open-critical.png](./state-open-critical.png) — open critical ask:
  ALARM-red flag row, explicit `DISPATCH BLOCKED` banner naming the ask, and
  the alarm-toned answer/ack deep link.

The "unknown" (failed-poll) state and the stale-critical fail-closed state are
covered by unit tests in `tests/interruptions_unit.rs` (`failed_poll_renders_unknown_never_all_clear`,
`stale_critical_still_blocks_after_a_failed_poll`).

## Safety

No window, no display, no Screen-Recording (TCC) permission — agent-safe by
construction; the raster never touches the window server.
