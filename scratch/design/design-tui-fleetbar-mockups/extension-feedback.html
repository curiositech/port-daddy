Selection Overlay Logic
Four dark curtains surround the live selection rectangle — no actual cutout or canvas compositing needed. The selected area stays at full opacity by rendering underneath. Crosshair lines are full-viewport position:absolute divs tracking mouse coordinates. Corner handles are 8×8px yellow squares with 2px black borders — unmissable, unmistakably a selection. The live dimension readout uses the terminal palette so it reads as a system annotation, not UI chrome.
Annotation Panel UX
Panel anchors to the nearest viewport edge of the selection — snaps right, flips left if collision. Never obscures the selected element. The preview strip re-renders a scaled capture of the region inline. No canvas required in extension context — use the chrome.tabs.captureVisibleTab API and crop. Five category pills use the same color semantics as PD coordination states: bug → cinnabar, nit → amber, feedback → cobalt, tangent → purple, question → forest. DOM path auto-resolves via document.elementFromPoint on mouseup.
Fleet Integration Wire
On submit, the extension POSTs to localhost:9876/inbox (Port Daddy's existing inbox route) with payload: { type: "viewport-feedback", screenshot, domPath, category, comment, url, viewport }. The waiting fleet agent subscribes via GET /msg/viewport-feedback/subscribe (SSE). When the event lands, it inspects the DOM snapshot, traces the CSS rule to its source file, proposes a fix, and writes a Playwright test targeting the reported selector. The blinking agent log in stage 3 is a live tail of pd notes filtered by the feedback session — no extra infrastructure.
