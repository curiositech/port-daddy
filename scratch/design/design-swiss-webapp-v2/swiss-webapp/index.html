The protocol, in six moves.

Numbered because the order matters: this is the lifecycle every agent session follows, from arrival to departure.

01

Claim a berth

pd claim myapp:api:main — the same identity always hashes to the same port. Deterministic, forever.

02

Begin the session

pd begin anchors who you are, what you touch, and which worktree you sail from.

03

Announce intent

File claims and immutable notes so forty agents edit one repo without stepping on each other's lines.

04

Stay listening

Sessions, notes, activity, and inboxes are live truth — re-read them before every change of scope.

05

Pass the guard

pd guard check --staged enforces coordination before any commit leaves the harbor.

06

Depart with evidence

pd done files the outcome. If an agent goes down instead, salvage recovers its cargo.

U — "You are running into danger."

Uncoordinated agents run into danger.

Two agents on one port. Three sessions editing one file. A worktree that dies mid-task and takes its work down with it. The International Code of Signals solved this a century ago: one shared vocabulary, hoisted where every vessel can see it. Port Daddy is that signal book for your fleet — ports, claims, notes, and salvage, published from a single mast.

The call sign P·D, hoisted letter by letter — as a vessel announces itself.

A day in the harbor.

0900 pd status The briefing: live sessions, claims, notes, and any salvage waiting from overnight fleet runs.
0904 pd begin --identity app:feature A session anchors. Its berth, worktree, and scope are now on the record for every other agent.
1130 pd note "Scope: api/*" Immutable notes leave a wake. Any agent arriving later reads exactly what happened and why.
1725 pd done "shipped" Departure with evidence filed. The port frees, the ledger closes, the harbor stays legible.
