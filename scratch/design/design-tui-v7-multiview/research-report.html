A visual survey of where the menubar control plane actually lives — and what to build when the brief is "Swiss modern + sparse color blocks + fractional borders."

The brief: a FleetBar that runs as a macOS menu-bar app, manages a fleet of Port Daddy agents, and uses Swiss-modern typographic discipline with sparse smart color blocking and fractional borders instead of full chrome.

Three scouts surveyed the space in parallel — menu-bar app conventions, contemporary control-plane UI, and the editorial fractional-border tradition. This report synthesizes their findings and resolves them into a single design language. The page you are reading is built from that language. Read what it is, then look at how it presents itself.

§ 01
Findings at a glance
three streams · one shape
Stream 01 · Menubar
22pt working height. 320–420pt popover.
The geometry is fixed. macOS menu bars are 24pt tall, with 22pt of usable height for menu-bar icons. Popover widths cluster at 320–420pt, with 380pt the most common shipped value. Height is dynamic — content drives, with a 40pt safety buffer to avoid silent clipping.
380pt
Working popover width
Stream 02 · Control Plane
Six states. One dot. No spinner alongside.
Vercel's Geist StatusDot is the strictest published contract: QUEUED · BUILDING · READY · ERROR · CANCELED · DELETED. Animate only on active states. Pair with relative time. Never co-render a spinner. For non-deployment things — workflows, jobs, agents — use Badge instead of StatusDot.
6
Canonical states. Not seven, not five.
Stream 03 · Fractional Borders
Eight patterns. Use two. Mix none.
The taxonomy ranges from L-tick corner brackets to full-bleed color zones. Eight distinct patterns, each communicating something different. The cardinal rule: do not mix more than two in one surface. Three or more reads as decorated chaos — the opposite of Swiss restraint.

Maximum bracket patterns per surface
§ 02
The fractional-border taxonomy
eight patterns · three lineages
Three lineages converge here: register marks from offset lithography, color blocks from Swiss/ITS (Müller-Brockmann, Vignelli, Unimark), and instrumentation from Bauhaus and Braun. The menubar control plane sits naturally in the instrumentation tradition and can borrow restraint from the editorial register-mark tradition. Avoid leaning hard on the poster tradition — full Swiss color confidence reads as advertising, not as a tool.

When this aesthetic fails
The single best diagnostic — if you removed the fractional borders entirely, would the UI still communicate its hierarchy through color, spacing, and type? If yes, brackets add refinement. If no, you're using them to hide the absence of a real system.
Earns its place
  • Brackets are ≥12px and snap to the grid (4px or 8px base unit)
  • Each pattern marks something specific — selection, focus, panel-scope
  • One accent color, max two; against a strict neutral matrix
  • The grid underneath is invisible but real — brackets land on it
  • Removing the brackets would not break hierarchy, only refinement
Dates immediately
  • Brackets shorter than 10px — reads as a render glitch
  • Three or more bracket styles in one view
  • Decoration without semantics — every card has brackets, so none of them mean anything
  • Saturation indiscipline — three accent colors competing on one panel
  • Dashed strokes as persistent UI — always reads as a draft or drag-target
  • Box-shadow stacked under fractional borders — collapses the entire idea

What's load-bearing here.

The 3px left-edge stripe is the only thing that carries state per row. No status icon, no chip, no badge. The dot at left re-states the same color for color-blindness safety and to give the row a fixation point — but the stripe is what scans at 200ms glance distance.

  • Panel-scope brackets (Pattern 2.1) — four 12px L-ticks at the corners of the popover. The panel feels framed but never enclosed. Brackets land on the 4px grid.
  • Left-edge accent stripe (Pattern 2.4) — six semantic colors (cobalt-running, green-ok, amber-warn, red-error, plum-blocked, gray-idle) applied as a 3px inset shadow. The stripe extends 6px short of top and bottom, giving each row a measured silhouette.
  • Midline rules (Pattern 2.3) — between the head, the color zone, the two list sections, and the foot. The rule spans only 64px of the available width, anchored left.
  • Single color zone (Pattern 2.8) — one cobalt block, top of the panel, for the agent that is right now running. There is exactly one running zone. If two agents are running, the second never gets a zone; it stays in the list with a pulsing stripe.
  • Sparkline at the head — direct labeling (no axis, no legend), color matched to the zone, end-of-line dot in warm amber for the actionable readout.
  • No card chrome anywhere — no box-shadow, no border-radius, no nested cards. The matrix and the brackets do all the framing.
The same primitives, scaled up
When an agent row expands, the same four patterns hold. The expanded card gets its own bracket frame, the active step gets a left stripe, and the tools-available chips (borrowed from Langfuse) sit in a midline-ruled strip beneath the current step.

Inline expansion, not modal.

The Raycast List-Item-Detail pattern, applied to agents. Clicking a running row does not push the user to a new screen — it expands inline, with the panel's own bracket scope re-stating around the expanded zone. The agent's possibility space (tools available, last call, next planned step) is rendered as a visible chip row, drawing from Langfuse's November 2025 trace redesign.

  • Brand consistency — the brackets that wrap the expansion are 1px thinner than the panel's outer brackets, so nesting depth is implied without enclosure.
  • Tool chips — five tool affordances shown horizontally. The active tool gets the cobalt left-edge stripe. Others stay neutral with a 12px label and a hairline underline.
  • Current step — rendered as streaming text, not a spinner. The dot pulses, the text updates in place. One animation only.
  • Action affordances — pause / interrupt / kill sit inline as ⌘K-discoverable commands, never as hidden kebab menus. W&B Sweeps pattern.

§ 05
The state grammar
six states · one dot · one stripe
Borrowed from Geist's published StatusDot contract and adapted for agents. The dot says state. The stripe re-states it for color-blindness and to pin the row's silhouette. The relative time anchors duration. No spinner is permitted alongside the dot. The dot animates only when work is actively in flight — never during idle, completed, or terminal states.
State Color Stripe + dot Animation Label form
Running#003FB8 Cobalt 3px stripe + 8px dot Pulse ring, 1.8s ease-out "Indexing src/ — 412/1840"
OK#2E7D5B Emerald 3px stripe + 8px dot Static "14 of 14 passed · 8s ago"
Warn#B8801F Amber 3px stripe + 8px dot Static "3 lint warnings, 1 unused export"
Error#B5392E Cinnabar 3px stripe + 8px dot Static "workers-ai 401 — auth expired"
Blocked#6B3F8A Plum 3px stripe + 8px dot Static "Waiting on operator · PR #91"
Idle#98928A Ash 3px stripe + 8px dot Static · or omit stripe "Idle · last run 28m ago"
Geist's contract, ported
One state, one token. Color is never the sole signal — every row pairs color, label, and relative time. Updates only fire on actual state change, not on every poll tick. Visually this means no constant micro-blinking. The dot's aria-hidden; the row gets aria-live="polite" only on state transition.

§ 07
The build recipe
100 lines of CSS · zero card chrome
Four patterns. Five state colors plus one accent. One typeface plus one mono. Built on a 4px grid with an 8px element gap and Linear's published spacing scale (4/8/12/16/20/24/32/48/64/96/128). If a designer can build the FleetBar popover in 100 lines of CSS, the design language is doing its job. If it takes 400 lines, something is decorative.
In the FleetBar
  • Panel corner brackets (2.1) · 12px L-ticks, 1.5px stroke, at all four corners of the popover
  • Left-edge accent stripe (2.4) · 3px inset shadow, six semantic colors, on every active or in-flight row
  • Midline rules (2.3) · 64px segment on the left of the section boundary, hairline-strong at 32% opacity
  • One color zone (2.8) · cobalt full-bleed for the singular currently-running agent at the top of the panel
  • Pulse ring on running · 1.5px concentric ring, fade-out 1.8s ease-out, transform-only animation
  • Sparkline · direct labeling, end-of-line dot in warm amber for actionable readout
Not in the FleetBar
  • Card chrome · no box-shadow behind any element, no border-radius anywhere
  • Spinners alongside dots · pick one state carrier per object, never two
  • Segmented strokes (2.5) · dates immediately, reads as draft
  • Open-corner frames (2.6) · gaps vanish at popover-scale sizes
  • Multiple accent colors · cobalt is the single system accent · status colors stay on stripes
  • Tiny eyebrows · never below 12px · never below weight 600 · never below 0.10em letter-spacing
  • Pies, donuts, 3D viz · bullet graphs and sparklines do the same job better at small scale
