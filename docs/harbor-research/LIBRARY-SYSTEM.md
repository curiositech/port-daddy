# The Harbor library: how it is built, checked, and edited

This is the canonical description of the research library behind *The Harbor, the
Person, and the Economy*. The twin-location headers in the `.tex` sources, the index
README, and the critique ledger all point here; this file changes slowly, the index
and the ledger change often.

## 1. What the library is

The library is one argument published in two forms and one book.

- **The Book** (`website-v2/public/whitepaper/coordination-papers-mega-volume.tex`, the
  textbook edition) is generated by `scripts/generate-mega-whitepaper.mjs` from eight
  chapter sources and one source of record, `whitepaper/textbook.json`, which fixes
  chapter order, numbering, the four parts, edition metadata, and each chapter's question
  and epigraph. Nothing else states a chapter number.
- **The eight chapters** are the standalone whitepapers under `whitepaper/` and
  `website-v2/public/whitepaper/`; each compiles on its own and declares only its
  `\pdchapterprefix`.
- **The seven research papers** (`docs/harbor-research/tex/paper1.tex` through
  `paper7.tex`) are submission-form write-ups of the executed results R1 to R17, CR, and
  B6. They are byte-stable artifacts: the Book folds their content into chapter prose,
  and the papers do not change except for the twin-location header comment.

**The twin-location rule.** Every result that lives in a paper and in a chapter carries
the same header comment in both files, naming the other file, the sections involved, the
index ids, the three commands that check them, and this document. If a number or a
statement changes in one location it must change in the other in the same commit;
`check_library_index.py` fails the build otherwise.

## 2. The reference index

`docs/harbor-research/library-index.json` is the inverted index: for every result id
(R1 to R17, CR, B6, and folded propositions), its one-breath statement, its standalone
home, its chapter locations, the figures and scripts that back it, the key numbers with
regexes that must match at every location, the mechanization rows, and the site anchors.
`library-index.schema.json` is its shape; `library-index.README.md` explains every field
and how to add an entry; `LIBRARY-INDEX.md` is the generated human-readable render and is
never hand-edited.

The checker, `scripts/harbor-research/check_library_index.py`, enforces: (a) every listed
label and anchor exists; (b) every theorem-family label and environment in the three
corpora is claimed or explicitly allow-listed, and every theorem environment carries a
label; (c) every key number matches, by regex, at the standalone and at every chapter
location; (d) both files of a folded pair carry the twin header and name each other;
(e) each chapter's declared prefix agrees with `textbook.json`; (f) `LIBRARY-INDEX.md` is
fresh (`--write-md` regenerates it, `--check-md` fails on staleness). Its unit tests live in
`tests/harbor-research/`.

## 3. The figure system

Figures are drawn in TikZ to one house grammar (`docs/harbor-research/figures/CONVENTION.md`
and `figures/pd-figure-language.tex`) in the semantic palette of `figures/pd-palette.tex`,
whose light values are held in lockstep with the website's tokens by
`website-v2/scripts/check-figure-palette.mjs`. Every folded result gets exactly two
figures in the program grammar: a relation map for its analogy and a regime diagram for
its boundary. The `harbor-chartwork` skill (`skills/harbor-chartwork/`) holds the diagram
taxonomy, the craft rules, the sourced research notes, and the mechanical QA: a
source-level lint for TikZ fragments, a fragment compiler, a rendered-PDF checker for
overflow, overlap, and dead canvas, and a contact-sheet builder for before-and-after
review. Art plates for the Book (cover, frontispiece, part and chapter openers) are
documented in `website-v2/public/whitepaper/plates/README.md` with full provenance.

## 4. The proof and provenance system

Claims are labeled by kind: **Theorem** (follows from a stated model), **Design
invariant** (intended; backed by implementation and tests), **Model-checked property**
(proved for a bounded or abstract model), **Empirical hypothesis** (needs measurement).
Runtime claims name an assurance mode: Observed, Coordinated, Brokered, Confined, or
Attested. Every number in prose is tagged `[verified]` (recomputable from a closed form or
the literature) or `[internal, script]` (regenerates from a named script and seed; the
program seed is 20260816).

What runs in continuous integration today (`.github/workflows/proofs.yml`):

| Claim | Mechanization | Files | Job |
|---|---|---|---|
| Claim-signaling incentive compatibility, δ* threshold | Z3, TLC, Apalache | `proofs/economics/` | Z3 / delta-threshold; TLA+ / claim-signaling; TLA+ / claim_signaling (Apalache) |
| Bond-ledger conservation | TLC | `proofs/bonded/conservation/Conservation.tla` | TLA+ / bonded Conservation |
| Threat bands | Monte Carlo | `threat-bands.mjs` | Monte Carlo / threat-bands |
| R1 to R17, CR, B6 headline numbers | Python result scripts, seeded | `skills/harbor-results/scripts/` | Harbor results / R-scripts (seed 20260816) |

The ProVerif models under `analyses/`, `proofs/**`, and `docs/adr/models/`, the three Kani
harnesses in `core/harbor-card-rs/src/lib.rs`, and the relay TLA+ configurations are
evidenced today by committed run logs, not by a CI job; wiring them, together with a
single manifest that marks every formal artifact WIRED or RETIRED, is the proof-estate
wave (`whitepaper/corpus.json` and its checker, in progress on this branch). Until that
lands, prose about those artifacts states the bounded truth: the Kani harnesses are
no-panic checks on bounded inputs with the cryptography stubbed plus two concrete
attenuation vectors; the every-hop attenuation property is ProVerif's.

## 5. Drift detection

| Check | Catches | Command | CI job |
|---|---|---|---|
| Textbook source of record | a chapter number, prefix, part, or mirror out of step with `textbook.json` | `node scripts/generate-mega-whitepaper.mjs --check-shared` and `node --test scripts/generate-mega-whitepaper.test.mjs` | library-checks |
| Citations | dangling `\cite`, orphaned or duplicate `\bibitem` | `python3 scripts/harbor-research/check_citations.py` | library-checks |
| Propagated corrections | a correction that landed in one twin and not the other | `python3 scripts/harbor-research/check_propagated_corrections.py` | library-checks |
| Reference index | missing labels, unclaimed theorems, drifted numbers, missing twin headers, stale index render | `python3 scripts/harbor-research/check_library_index.py --check-md` | library-checks |
| Critique ledger | Markdown and JSON out of agreement, malformed status cells | `python3 scripts/harbor-research/check_critique_ledger.py` | library-checks |
| Palette lockstep | a TeX color that disagrees with the light tokens, or unequal twin copies | `npm run test:figure-palette` (website-v2) | whitepaper-metadata, CI |
| Publication metadata and digests | a committed PDF whose pages, size, or SHA-256 disagree with the catalog or `publication-digests.json` | `npm run test:whitepaper-metadata` (website-v2); `--fix` resyncs | whitepaper-metadata |
| Doc citations | a repo path cited in a changed doc that does not exist | `node scripts/check-doc-citations.mjs` | doc-citation-guard |

## 6. Build and publish

The published PDFs are built by `scripts/build-whitepapers.sh` inside a pinned TeX Live
container (`.github/workflows/whitepaper-build.yml`); a same-repository push or pull
request that changes any TeX input, `textbook.json`, the generator, or the plates makes the
workflow rebuild only the affected papers and commit them as
`build(whitepaper): regenerate PDFs from source`. The research papers have the same loop
in `harbor-research-build`. After a bot commit, run `npm run fix:whitepaper-metadata` in
`website-v2` to resync the catalog's page counts and sizes and the digest manifest, and
push. A run that lands in `action_required` is re-run from the Actions tab. Locally,
`tectonic` compiles every chapter and the Book from the same sources; CI's pinned image is
the authority for bytes.

## 7. Editing playbook

The running state of the Textbook Edition build (what has landed, the context budgets for the remaining waves, the token meter, and how to resume) is kept in `docs/harbor-research/exposition/TEXTBOOK-BUILD-LEDGER.md`; update it in the same commit as any wave.

1. Change a result where it lives. If it is folded, change both twins in one commit and
   update the key numbers in `library-index.json`.
2. Run the five library checks in section 5 before pushing; run the chartwork lint and
   fragment compiler for any figure you touched.
3. If you added a theorem, label it, add it to the index or to `unindexed_allow` with a
   reason, and give it a relation map and a regime figure if it is a folded result.
4. If you answered a review item, set its `Status` in `docs/harbor-research/CRITIQUE-LEDGER.md`
   (`DONE <sha>`, `IN-WAVE-<n>`, or `DECLINED -- <reason>`) and run the ledger checker.
5. Never state a chapter number in prose; use `\pdchapref{prefix}{Title}`.
6. Push, wait for the regeneration commit, resync metadata, push again.
