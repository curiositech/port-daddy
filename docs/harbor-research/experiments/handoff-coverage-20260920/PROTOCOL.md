# Protocol: an intact capsule with an incomplete brief

Registered before this sidecar's experiment. This is a bounded, deterministic
source-function test, not a running Port Daddy or provider-resurrection test.

## Question

Can an older, still-binding operator instruction disappear during the existing
producer/sanitizer/renderer path while the resulting capsule has a matching
content hash and the brief reports zero extra tail omissions? Distinguish the
full stored capsule from the actual rendered successor brief.

The narrow hypothesis concerns this source path. The Book already requires
obligation preservation in its replay exercise; it does not claim this builder
implements that invariant. Paper 8 is a prospectus, not implementation evidence.

## Source and isolation

  123–237; toHandoffRole 250–255.
- lib/handoff-capsule.ts: declarations/helpers 7–505; computeIntegrity,
  sanitizeHandoffCapsule and renderHandoffSuccessorPrompt 568–644.

Pin whole-file SHA256 and extracted-range SHA256 before execution. Select these
known, fully inspected ranges; strip TypeScript with Node's built-in
stripTypeScriptTypes. Remove only top-level export modifiers. No canonical
module imports, dispatch/failover calls, transcript-store reads, subprocesses,
network, installed compiler, or package manager. Evaluate those declarations
in an isolated VM context with only Buffer, SHA256, a deterministic UUID,
a fixed clock, and explicit scanner/redactor stubs. Two-second VM execution
limit. VM is a containment convenience for reviewed pure code, not a security
claim about arbitrary malicious JavaScript.

Both scanners return no findings and redaction is identity. All fixture content
is synthetic and secret-free. Therefore clean/scanned labels generated by those
functions are **not tested scanner efficacy**. Do not describe them as a live
security pass. The budget is the source's 6,000 approximate tokens (bytes/4), not
any provider tokenizer measurement. No external scanner is launched.

## Six frozen fixtures

The objective is always “Write the local design note.” The separate instruction
is synthetic text “OBL-01: preserve the existing acceptance criteria.” It is
not included in the objective or injected as a current system instruction.

1. recent: the instruction is a recent operator turn; expect preserved.
2. old: instruction, four later operator turns, eight later assistant messages;
   expect absent from the last-four selection and the last-eight tail.
3. fourth-from-last: instruction, three later operator turns, eight assistant
   messages; expect preserved by the operator-turn list despite leaving the tail.
4. long-item: a single operator turn with 2,050 ASCII filler characters before
   the instruction; expect clipping, with an explicit truncation marker.
5. reaffirmed: old fixture followed by the same operator instruction again;
   expect preserved through a valid later source turn (restoration control).
6. unconstrained: one unrelated operator turn, no required obligation; do not
   manufacture a missing requirement (false-block control).

The frozen obligation ledger is generated from the full fixture, outside the
projection. Each record binds an obligation ID to exact source-turn IDs and
full text. A later identical operator reaffirmation is an allowed source. Only
matching operator-origin records count; a string copied into assistant tail
text is not a valid provenance match. These are synthetic exact-match contracts,
not a semantic parser for arbitrary obligations.

## Records and gates

Save all fixture inputs and per-stage observations in results.json: draft and
sanitized omission counters, required/source IDs, preserved operator IDs,
source-reference visibility, hash recomputation, clipping marker, and missing
obligations in the rendered brief. Report every fixture, including controls.

Keep the candidate only if:

- old loses the required operator record, has draft tail omissions > 0 but
  final omissions 0, and its capsule hash recomputes correctly;
- recent and fourth-from-last preserve the instruction;
- long-item loses the suffix but reports its truncation marker;
- reaffirmed restores coverage; unconstrained produces no false block;
- a fixture-bound coverage oracle rejects every missing requirement, a forged
  source ID, edited text, and an assistant-only copy; restored evidence passes;
- deliberately weaker hash-only and counter-only gates accept the old loss;
  an output-derived requirement set also accepts it, exposing its bad denominator.

CUT the empirical candidate if the old instruction survives the actual rendered
brief through any tested preserved field, the source changes, extraction fails,
or the positive/restoration controls fail. Report that failure; do not tune the
fixture or relax the gate after seeing it. A still-stored transcript reference
is a recovery possibility, not satisfaction of the closed-brief coverage gate.
A separate authorized lookup could satisfy a different contract; it is untested.

## Budget and command

One Node process, six fixture passes, no worker launches, no databases, fixed
inputs/no random sampling, less than 64 KiB input data and 256 KiB result JSON.
No automatic rerun after a failed experimental gate. A source-extraction/tooling
error may be fixed and recorded, without relabeling any earlier output.

From this directory:

```sh
node coverage_experiment.mjs --root /Users/erichowens/coding/tmp/book-figures-reconciled --out run-01
```

The script refuses existing output and output outside this sidecar. It writes
only a new results.json there. This is not a secrecy, behavior, or fidelity-rate
benchmark. Any claim about a real successor following, ignoring, or retrieving
an omitted instruction would require a different, separately authorized study.

## Proposed response to failure

The Book addition teaches a coverage distinction. A future implementation could
retain a trusted manifest of open obligations with authenticated source pointers,
then resolve each before claiming continuation-ready. Merely retaining more
recent turns, hashing the result, or asserting “revalidate” does not implement
that manifest check. Do not change runtime behavior or force a new continuation
policy under this sidecar's authority.
