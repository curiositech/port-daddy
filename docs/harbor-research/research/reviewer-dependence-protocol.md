# Reviewer dependence pilot: preregistration and admission protocol

**Status:** preparation only, 2026-09-28. The companion manifest contains 24 *planned* case slots, not 24 held-out or adjudicated defects. No reviewers, paid models, or held-out oracles have run. Freeze and independently verify the admitted case package before any reviewer sees a case. The local Port Daddy runtime stays off throughout this preparation.

## Question and population

At the same actual review spend, does separating a property author from a blind tester reduce joint misses compared with repeated reviews of one diff? A single stronger reviewer with protected deterministic tests is the simple baseline. The target population is consequential code-change defects in agent infrastructure, sampled across authorization/admission, retry/durability, and evidence/provenance contracts. This is a pilot for effect size and variance, not a reliability certification, a bribery experiment, or proof that model brands have independent errors. The proposed source anchors currently come from one repository, so **project-level generalization is unavailable until independently sourced projects enter the frozen set**.

The unit is one defect candidate plus one matched clean control on the same pinned base/specification and similar patch size. A clean control is a legitimate change, not an empty diff. Recruit 24 adjudicated units, eight per failure class, from at least three projects, with no project supplying more than 12. Reserve one entire project as a prespecified external holdout after recruitment; report it separately, not as a new training or prompt-tuning source. The current 24-slot manifest satisfies only planning cardinality and source anchoring within Port Daddy. Replace or add slots from other projects before execution admission; preserve retired slot IDs and the selection log to expose selection effects.

## Freeze and independent case admission

For each slot, a case builder prepares two immutable trees: a defective candidate and a behaviorally valid matched clean control. They pin the base tree, exact patch, public task/specification snapshot, permitted context, harness revision, dependency lockfiles, deterministic oracle command and expected observations by content digest. The builder records the failure mechanism and an expected minimal witness in a sealed answer file outside every reviewer view. An oracle that merely checks for a known code string is insufficient; require a behavior-level witness, a negative clean result, and a mutation of the oracle itself that makes the witness fail. Use existing tests as *research anchors* only. Remove those anchoring tests, answer files, hidden tests, this manifest, and revealing commit messages from reviewer trees; inspect the resulting view for spoilers. An existing public regression test that names the precise fault disqualifies the case unless the new hidden witness tests a distinct behavior and the reviewers cannot access the regression or its history.

Two adjudicators who neither built the candidate nor review it independently inspect the spec, oracle, both trees, and witness. They record separate decisions and disagreements before reconciliation. Admission requires agreement that the defect violates the frozen spec, the control satisfies it, the oracle is independent of reviewer outputs, and both patches are realistic and comparably legible. A third adjudicator resolves disagreements without seeing reviewer judgments. Reject ambiguous specs, multiple inseparable defects, flaky tests, a clean control with the target fault, unbounded setup, or leakage. Retain every rejection with its reason; do not quietly replace a hard case after observing model outcomes. `check_reviewer_protocol.py` checks this single-repository draft against exact source Git blobs; `--ready` checks structural declarations but intentionally refuses execution admission. Before any run, a separate verifier must confirm artifact bytes, oracle behavior on defect/clean/mutant, signed decisions and distinct adjudicator identities, reviewer-view isolation, and source provenance across real projects. Relabeling Port Daddy slots as other projects fails the draft validator. The current schema cannot validate a second repository: extend and review that verifier when multi-project cases are recruited. For a future frozen selection, calculate `freezeDigest` as SHA-256 of sorted, compact UTF-8 JSON with `freezeDigest` and `randomizationSeed` set to null; draw and record the randomization seed only after this freeze.

## Arms, equal cost, and information boundary

Every admitted pair is evaluated under all three arms with fresh context and no cross-arm communication. Resolve the three **capability roles** against available models and prices immediately before the experiment; freeze provider/model revision, prompt, tool and temperature versions, test runner, and price sheet. No literal model ID is part of this protocol. Calibrate budget and prompt lengths on separate non-heldout cases, then freeze them. Give each arm the same per-pair billed USD cap `B`, including input/output tokens, tool calls, test execution and retries; log actual spend and wall time. Target actual spend within 10% across arms per pair and report deviations. Stop at the cap without replacing a reviewer or topping up a weak arm. If pricing or billing makes parity impossible, stop the comparison and recalibrate only on non-heldout cases with a new protocol version.

| Arm | Reviewer-visible inputs and permitted work | Output before reveal |
| --- | --- | --- |
| A: repeated same diff | Two sequential reviewers each see the same spec and diff, in isolated fresh contexts. Reviewer 2 does not see reviewer 1's output. Split `B` between them by frozen calibration; each may inspect the same allowed files. | Two separately elicited block/allow decisions and concrete findings; fresh contexts do not establish statistical independence. |
| B: separated property and test | The property author sees the spec and base tree **before** the candidate patch; it writes falsifiable behavioral properties and test inputs. Seal and timestamp this artifact. A fresh blind tester then sees the sealed properties, allowed candidate tree and its diff, but no candidate-builder explanation, hidden oracle or other arm's findings. It spends the remaining frozen share of `B` to implement/run its own tests. | Property artifact, test execution trace, and one block/allow decision. |
| C: strong reviewer plus tests | One independently selected stronger reviewer sees the same spec/diff as A. It may run a frozen deterministic **public** test suite; the protected adjudication oracle remains hidden. Reserve test execution spend inside `B`. | One block/allow decision, findings, and test trace. |

For all arms, no access to the case-selection manifest (withheld from reviewer views), hidden labels, adjudication packet, future case files, prior cases' outcomes, web search, repository history beyond the pinned view, or other arms' transcripts. The same deterministic public suite is available in every arm; C must run it, while A and B may choose whether to run it within their cost cap. If A or B independently chooses tests, count their execution against `B` and record it. B's property author must not inspect the candidate diff, including through tool search or test output. Audit transcript and tool access logs; any boundary breach is reported as contamination, never silently discarded.

## Randomization and outcomes

Generate the assignment seed with a public randomness source **after** case/adjudication freeze; record source, timestamp and digest. Within blocks defined by project × failure class × patch-size band, randomize (i) candidate/control presentation order, (ii) the six permutations of arm execution order, and (iii) reviewer identity assignment from eligible role pools. Balance permutations as closely as the block permits; keep a reviewer from seeing both members of a pair and from reviewing the same underlying defect in another arm. If that requires more reviewers than available, freeze nonoverlapping batches and disclose the reduced design. Cases are presented with neutral IDs and no labels. A block is a refusal to merge until a finding names the affected contract and an observable failure; a vague concern is `allow` for the primary binary outcome but retained in the qualitative record. Apply a frozen two-step rubric: arm-blind coders first extract the claimed contract, failure, and requested block from locked outputs without truth labels; after all extraction is locked, separate adjudicators match those claims to the sealed oracle and decide whether they detect the target defect. Disagreements go to a third adjudicator. The truth-matching step necessarily sees the label and must not revise the extraction.

Primary defect outcome per arm is **joint miss**: no valid block from that arm's complete procedure on the defective member. For A, retain both component decisions; for B, retain whether the property author specified the fault-relevant property and whether the tester produced a failing witness; for C, separate reviewer detection from deterministic-test detection. A clean member is **false blocked** when the procedure blocks it. Also report localization correctness, severity, billed cost, tokens, tests run and wall time. Do not treat a reviewer who refuses for an unrelated reason as detecting the target defect.

The primary paired contrast is `Pr(joint miss | B) - Pr(joint miss | A)` on the same admitted defects; a negative value favors information separation. Report B versus C and A versus C as prespecified secondary contrasts, and all clean-control false-block differences. The pilot's practical screen is at least a 10 percentage-point lower observed joint-miss rate for B than A **and** no more than a 5 percentage-point higher observed false-block rate than C, under the 10% cost-parity target. These are decision thresholds for whether to fund a larger study, not a claim of significance or permission to deploy. No power claim is attached to 24 cases. If C is as good or better at equal cost and false blocks, keep C as the preferred simple policy. Report all estimates and intervals even when screens fail.

## Dependence analysis and limits

For ordered reviewers `1,…,k`, let `M_j` mean reviewer `j` misses a defect. Estimate `q_1 = Pr(M_1)` and `q_j = Pr(M_j | M_1∩…∩M_{j-1})` from observed counts, showing numerator and denominator. The requested conditional detection rate is `Pr(j detects | preceding reviewers all missed) = 1 − q_j`, with the same denominator. The identity

`Pr(M_1∩…∩M_k) = Pr(M_1) × Π_{j=2}^k Pr(M_j | M_1∩…∩M_{j-1})`

is the chain rule and needs no independence assumption. Replacing each conditional factor with its marginal `Pr(M_j)` is an empirical independence assumption; report the resulting marginal-product prediction next to the observed joint miss and their difference. For A, the second reviewer gives a directly measurable `Pr(M_2 | M_1)`; for B, the property and tester stages are different tasks, so report stage-conditioned failure without calling them exchangeable reviewers. Do not fit conditional rates if the preceding-miss denominator is zero; label them unestimable rather than zero. Show all 2×2 joint tables and any higher-order table when a later design adds reviewers.

Use paired case-level estimates and a cluster bootstrap that resamples projects, then underlying defect families within projects, preserving each pair and all arms. At three projects the project bootstrap is fragile; show raw project strata, exact denominators, and a sensitivity analysis that drops each project in turn. Give Wilson/binomial descriptive intervals for raw rates and a clearly labeled exploratory paired interval for contrasts. No single-project slot is independent evidence about project drift. A 24-defect pilot cannot establish a rare miss probability or certify a multiplicative assurance factor: zero misses still permits a substantial upper bound, shared misses may be too few to estimate `q_2`, and model, prompt, codebase and defect prevalence shift. Repeat on newly recruited projects and later model revisions before operational use. Missing outcomes, budget truncation and contamination are reported by arm; analyze all randomized cases as assigned in the primary table, with a separate complete-case sensitivity table and explicit reasons.

## Source boundary

The caution against assuming independent failures has a direct historical analogue: Knight and Leveson independently developed 27 program versions and found coincident failures more often than an independence model predicted. Their experiment concerns program versions, not LLM reviewers, and supplies motivation rather than an effect-size prior for this pilot: [*An Experimental Evaluation of the Assumption of Independence in Multi-Version Programming*](https://people.cs.rutgers.edu/~uli/cs673/papers/EvaluationMultiVersionProgramming86.pdf).
