Disagreement #2 — vocab

Pheromone-as-write-surface vs tuple + synthetic pheromone

Pheromone-as-write (bake-in). "Add a deposit(table, id, key, strength) verb." The bake-in researcher's stigmergy plan treats the pheromone table as the structured-write API; everything else is a read view.

Tuple + synthetic (viz agent + vocab v1 §7.2). Operator intent IS a fact, and per the typing rule it belongs in lib/tuples.ts, not lib/pheromone.ts. The right pattern is: operator pins a passage → writes a tuple → cartographer / pheromone-deriver emits a relevance:operator-pinned synthetic pheromone for the heat-strip view.

Steel-man of tuple+synthetic: facts and traces are different ontological layers. Conflating them at the substrate makes garbage collection / decay incoherent (tuples should persist; pheromones should evaporate). This is the more careful answer.

— bake-in (inline) §1.7 implicit · viz (#231) §pre-mortem makes the explicit tuple-first argument
Disagreement #3 — spend

Sandbox v0: $400 single-shot vs $1200-1500 for three runs vs "do composition first"

$400 single-shot (evolutionary recommend baseline). Quickest possible test, sets up harness, expect first run to surface bugs.

$1200-1500 for 3 (evolutionary actually-recommend). First runs always burn half the spend on harness bugs. Three runs lets the first die for harness and the next two be real.

Defer (realism worst-case). Operator builds the wrong abstraction first if they sandbox before symbol claims + composition substrate ship. The honest worst case is "three swarms run, two produce lower-quality output than a single Opus 4.8 call at the same cost." Realism's recommendation: build the composition layer FIRST, sandbox AFTER.

Steel-man of defer: the evolutionary sandbox needs a coordination substrate to evolve over. If symbol-region claims, suggestibility briefing, and ContractNet aren't in place, the sandbox is evolving over a broken substrate and the answers won't transfer when the substrate fixes ship.

05Confession + lessons

I reproduced the very anti-pattern the realism check was warning about.

While I had three architect agents in flight, all three were editing the same git index in the same worktree. Each git add from the realism check was overwritten by git reset from the evolutionary sandbox within seconds, three times in a row. The realism check called it out: literally the "Shared Working Directory" anti-pattern documented in multi-agent-coordination/SKILL.md. The agent stubbed its toe on the failure mode it was writing about.

Symbol-region claims wouldn't fully fix this (the conflict was at git-index level, not file level), but they're the right direction. The cleaner fix is to dispatch parallel agents with isolation: "worktree" — the harness supports it; I should have used it. I owe better coordination on future fans-out.

Filed as PD note 9255: pd guard check --staged --hook exits 1 silently across multiple agents' attempts, while pd guard check --staged (no --hook) exits 0. /guard/status returns 404. Silent-fail guards violate ADR-0045 (loud-fail invariants). Worth a fix in the binary.
