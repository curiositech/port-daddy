## The question

How should Port Daddy help many human and agent ecosystems discover, explain, and legitimately reconcile contradictions without copying private histories into a shared project, confusing evidence with authority, or allowing a late writer to silently erase prior decisions and dissent?

The system must connect human intent, conversations, plans, laws, treatises, ADRs, external work systems, code, reviews, evidence, incidents, roadmap nodes, decisions, supersession, and dissent. It must reason forward from a proposal into likely consequences while stating where retrieval, classification, and inference stop short of proof. It must convene the people and durable roles actually affected, preview the human and product impact of change, and produce an attributable decision receipt before any canonical plan changes.

The attached research thesis adds a sharper distinction:

\[
\text{agent cognition} \neq \text{collective cognition} \neq \text{institutional state}
\]

The project does not know a proposition merely because an agent said it, a document contains it, or retrieval ranked it highly. A candidate project epistemic state must preserve immutable evidence, actor-indexed beliefs, goals, intentions, commitments, arguments, values, and unresolved propositions without collapsing them into one shared-context summary.

## Falsifiable research program

| Hypothesis | Treatment question | Primary outcome |
| --- | --- | --- |
| H1 — institutional state beats shared retrieval memory | Does an actor-indexed, temporally superseded project state outperform ordinary retrieval, Git, issues, ADRs, and chat on longitudinal truth questions? | contradiction recall, provenance correctness, temporal-state accuracy, stale-decision violations |
| H2 — consequence closure exposes latent collisions | Can typed, bounded consequence paths detect independently mergeable but architecturally incompatible work before damage? | material collision recall, false-conflict rate, proof-path validity, detection lead time |
| H3 — controlled epistemic separation improves synthesis | Does independent retrieval and position formation followed by reciprocal steel-manning outperform immediate shared-context deliberation? | decision accuracy, unique evidence, argument diversity, premature consensus, correlated error |
| H4 — execution provenance improves durable reasoning | Does grounding beliefs in Porthole and authoritative API evidence reduce false project state and causal hallucination compared with ordinary memory? | source attribution, causal accuracy, stale-belief propagation, correction rate |

The system-level objective is material conflicts caught before damage per unit of human interruption and compute cost. More alerts are not success. The benchmark must include seeded and naturally occurring longitudinal changes, cross-artifact consequences, supersession, and questions that genuinely require a human.

The 2025–26 literature named in the operator's attachment is neighboring evidence, not yet a verified novelty boundary. This program will cite primary sources, build a citation graph, and state priority claims cautiously.

## Authority boundaries

1. A person's private history, local memory, drafts, secrets, and unrelated-project material remain private by default. Discovery does not grant disclosure.
2. A repository or project is a hard authorization firewall. Cross-project access requires an explicit, attributable, purpose-bound, expiring capability for named material or a sanitized derivative.
3. Team or organization knowledge is not automatically project truth. Its scope, source, retention, and authority must travel with it.
4. Project evidence is append-only input. It can support or challenge a decision but cannot declare itself canonical.
5. Canonical project decisions are signed, scoped projections over preserved evidence. Supersession adds a new decision and receipt; it never rewrites the old one.
6. The existing Chartroom Grand Harbor roadmap authority is the only remote planning authority in scope. This research may specify integration and acceptance criteria but will not create a parallel store, roadmap, or control plane.

## Required outputs

- A constitutional architecture with scope, authority, privacy, provenance, conflict, reconciliation, appeal, and supersession rules.
- A research protocol for the four hypotheses, benchmark corpus, measures, ablations, and falsification conditions.
- A practitioner's guide with intake, classification, stakeholder selection, steel-manning, facilitation, experiment, canonical-update, and recovery decision trees.
- A data model, event taxonomy, APIs, access-control matrix, lifecycle, detector architecture, retrieval policy, cost controls, observability, defenses, and staged acceptance-test DAG.
- Static visual artifacts and worked conflict stories that preview affected outcomes and replacement behavior before a disruptive command is accepted.
- A reusable Port Daddy skill derived from the research and bounded to proposal-only operation until an authorized canonical decision exists.
- An explicit dissent appendix and editorial record.

## Non-goals and collision boundaries

This slice will not implement or edit the live Chartroom/Relay D1 kernel, roadmap writer, Fleetbot publisher, session recovery, retrieval fabric, Porthole runtime, website, pd-console, FleetBar, Squid harness, or active actor source. It will not import private histories, inspect credential contents, mint capabilities, deploy services, mutate roadmap ownership, or claim that semantic similarity proves contradiction.

## Success test

A reader should be able to take a concrete proposal, identify only the evidence they are allowed to inspect, classify its likely relationship to current commitments, compute bounded forward consequences with traceable premises, convene the required stakeholders, compare replacement previews, record steel-manned agreement and dissent, and either issue an authorized decision receipt or stop without changing canonical state.
