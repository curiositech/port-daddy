# Authoring and acceptance contract

This records defects actually found in the campaign, so later batches do not repeat them. All writes remain in an explicitly owned directory under this handoff. Verify the repository root, feature branch and linked gitdir, but treat its source as read only pending Register renewal. Use absolute output paths and assert they are within the owned draft directory before writing. Preserve other workers' changes.

1. Read each entrypoint and every support Markdown file. Record the source tree before changing it. Preserve useful examples, assumptions, edge cases, provenance and distinctions; shortening a large skill into a generic checklist is not an upgrade.
2. Repair claims in place. New references cannot cure conflicting old examples, frontmatter or quality gates. Inspect those three surfaces again before freezing. A symptom suggests a diagnosis; it rarely proves a single cause. Missing evidence is not falsity; a timeout is not proof of no effect; a profile name is not a security boundary.
3. Add topic-specific know-how from actually inspected primary sources. Record source identity/version, retrieval date and access depth. Distinguish paper results, documented platform behavior, original engineering proposals and constructed examples. Do not attribute a modern guarantee to a historical protocol.
4. Declare local policies and constructed numeric examples. Remove unsupported universal thresholds, optimality, prices, limits, safety prescriptions and success rates. Use current authoritative sources for retained external platform claims.
5. Add at least two useful Mermaid diagrams per skill bundle, linked from the entrypoint. Prefer distinct explanatory roles, such as mechanism plus failure/recovery, or comparison plus worked trace. Diagrams must preserve the source's actual logical relations: AND versus OR, multiple dependency types, unknown outcomes and conditional scope.
6. Review ASCII recursively and semantically. A tree with plain hyphens is still a diagram; a graph embedded in an example needs conversion. Code, structured YAML/JSON, actual logs, tables and inline mathematical expressions can remain with reasons. A box-character scan is only a candidate finder.
7. Parse frontmatter, check relative links, render every current Mermaid block and inspect actual images. A successful parser does not prove labels fit or that arrows mean the right thing. Save source and output hashes, plus a complete file manifest and original-to-draft diff. Rerender changed sources after corrections.
8. Freeze a bounded subset before independent review. Do not mutate a frozen subset without telling the reviewer. An accepted receipt applies only to its exact complete bundle. Copying files, adding research, rendering figures or passing a syntax scan is not canonical integration.
9. Flag Book ideas as candidates with an example and evidence boundary. First compare against ASTRA-BOOK-REVIEW.md and BOOK-PLACEMENT-REVIEW.md; do not rebrand an already-covered distinction as a new result. Keep all proposals outside Book prose.

## Retention defect found during B05 review

The review helper now emits omitted-canonical-files.json and includes deletions in its diff. Previously it walked only draft files, which concealed entire omitted references. Every omitted original file requires an explicit disposition, including raw historical material; a clean link check does not establish retention. For each original substantive heading, record where its useful procedure/example/distinction survives or the source-backed reason for correcting/removing it. A short caution with the same filename is not retention. Reference-family labels or an index of links are not a heading disposition ledger.

## Semantic diagram defects found during B03/B05 review

- A new option set can be empty while an existing BDI intention still has an enabled action. Draw the interpreter continuation; do not send an empty option set straight to a halt/wait state.
- Human input and automatic replies are different branches. A nonempty human response is sent directly; only a documented skip reaches automatic computation. A local stop is not an outgoing message. Keep mode-specific termination guards explicit.
- Mermaid node IDs are global within a flowchart. Reusing one ID for direct and managed conversation roles merges their edges even when labels differ. Use distinct IDs for different roles and paths.
- A returned translation capability is not a translated expression. A translated expression is not a passed task fixture or authorized action. Draw unavailable, failed and denied outcomes separately.
- Do not let one-time and recurring commitments share a completed state with outgoing recurrence edges. Rearming retains the recurring commitment; it must not consume an extra trigger.
- Check for patch markers accidentally retained as heading text, copied source-edition names from a different paper, and missing primary citation URLs. An index or author receipt cannot repair conflicting active content.

## Rendering and method retention follow-up

- Mermaid state-transition labels containing semicolons can parse while creating stray states. Inspect all rendered nodes, not just parser success.
- A short synopsis naming old example topics is not method retention. Preserve concrete inputs, steps, outputs and failure branches; the campaign explicitly requires substantive new references as well as entrypoint edits.
- Numeric Unix-style Gantt dates can render misleading calendar axes. Use a declared constructed time origin and actual rendered tick labels, or a resource-lane diagram plus a complete schedule table.
- A CAS success alone never validates a plan proposal: depict separate contract/cycle/resource/authority rejection paths before atomic admission.
