## 1. A verified history can contain a bad health report

**Reader question:** What does a valid proof tell me when the status page says green?

**Placement/how:** A compact worked exercise after single-writer-kernel.tex:1696–1721 (self-attestation), cross-referencing 2150–2158 (verification and threat model). Current I10 already lists unchecked invariants and scopes conjunction; current I9 already says an unverified chain is not a control. Do not present either as missing. Add the concrete independence of observation validity, service objective, freshness/coverage, and retained-history verification. This is different from candidate 2's uncertain external effect and candidate 3's judge dependence.

**Constructed hand example:** Capability C promises a correct answer within declared deadline D. At t0 an authenticated probe records a passing sample. At t1 the same record has a valid inclusion and consistency proof against a retained checkpoint, but is older than the declared freshness limit: history verified, present service state unknown. At t2 a functioning observer measures deadline failure in region A while region B has no sample: known failure plus missing coverage. At t3 the observer crashes before sending a request: observer failure, no service observation. A bad service response with HTTP 200 is a service-objective failure. These cases must remain distinguishable even if one page displays them.

**Source and claim:** RFC 9162 (Experimental, December 2021), §§2.1.3–2.1.4 and auditing discussion, specifies inclusion and append-only consistency evidence for certificate logs. Transferring those evidence distinctions to a status ledger is a local application, not an implementation of Certificate Transparency or a proof of health. Official primary: https://www.rfc-editor.org/rfc/rfc9162.html . The accepted status bundle's observation-and-history-verification.md separately grounds semantic service objectives in Google SRE. This pass opened the RFC; the detailed SRE reading receipt is inherited from that bundle, not independently repeated.

**Uncertainty/evaluation:** No topology has been shown to give independence merely by splitting deployment. Inject service, observer, collector, renderer, archive and notifier faults separately, then one shared credential/DNS failure. Independently retain injected truth. Measure false healthy, false failure, unknown duration, coverage and alert delivery. Compare a single status scalar with the scoped tuple in a comprehension task. A cached-read policy and an effect that requires current evidence can differ; avoid extending the kernel's integrity admission rule into a universal application outage rule.

**Semantic figure brief:** Four horizontal evidence lanes ending in one explicitly scoped report: observed operation, age/coverage, retained history verification, capability-specific decision. Draw no arrow from valid history directly to healthy or authorized. A small 2-by-2 history-verification/current-observation panel can show valid-history/stale-observation and unverifiable-history/observed-failure. Keep mixed coverage explicit. No TikZ port this pass: author review should first decide whether to add this teaching exercise beyond the seven existing ports.

## 2. A witness and an unsuccessful search establish different things

**Reader question:** When may an agent say impossible, rather than not found?

**Placement/how:** Exercise following single-writer-kernel.tex:1578–1616 (finite oracle boundary/OP-5), with a pointer from 1053–1070 (ability versus permission). Current text already distinguishes a passing test from a good refactor. Add scope and completeness of a negative search result, including empty option sets; do not repeat general unknown-effect recovery.

**Constructed hand example:** The declared repair catalog has three plans. P1 is checked and violates a norm; P2 times out before its effects are determined; P3 has not been searched. The result is undetermined, not no feasible plan. If P3 later provides a checked feasible witness, feasibility within the model is established but execution authority remains a separate condition. If a complete, finite declared catalog is exhausted with checked failures, no feasible member exists in that catalog; it does not establish absence of a repair outside it. An empty catalog means no known capability; universal safety over the empty set must not greenlight an effect.

A second small arithmetic check is useful because it defeats an inherited ToT shortcut: four inputs 1,2,3,4 are all below five, yet (1+3)*(2+4)=24. A heuristic can prune the only useful branch; more votes need not repair a shared misconception. Check syntax, allowed operators, input multiplicities and exact arithmetic independently.

**Source and claim:** Tufiș and Ganascia, Normative rational agents – A BDI approach (RDA2 2012), definitions around §3.2.1, https://ceur-ws.org/Vol-885/paper6.pdf , separately define universal and existential consistency. Their predicates overlap; the exclusive operational labels complete-nonempty/all-safe/mixed/none-safe plus undetermined/no-known-capability are local repairs, not quoted source taxonomy. Yao et al., Tree of Thoughts, arXiv:2305.10601v2, §3 algorithms and §4.1, https://arxiv.org/html/2305.10601v2 , uses generated proposals, value heuristics and bounded search. This supplies an instructive application, not an exhaustive impossibility oracle. Live targeted primary passages were read. Móra's abduction boundary is supported by the Luna author-copy receipt; it was not independently reopened here.

**Uncertainty/evaluation:** Build finite catalogs with independently enumerable ground truth. Vary search timeout, omitted alternatives, unknown effects, incorrect witness and complete exhaustion separately. Score false impossibility and false feasibility, as well as success/cost. Explicitly version the domain, transition/effect model, search coverage and checker. Changing the catalog invalidates a negative certificate even when old failed plans remain failed. This links to candidate 4 without treating negative evidence as timeless.

**Semantic figure brief:** A single search state splits into checked witness, complete bounded exhaustion, and incomplete/unknown. Only witness leads to model-feasible; only complete exhaustion leads to no feasible member in the declared domain; both remain separate from effect permission. Prefer an exercise table over a new full-page diagram until the port count is reviewed.

## 3. When is reconsidering a plan worth its cost?

**Reader question:** Which changes deserve another planning pass, and which should leave an existing commitment intact?

**Placement/how:** Extend candidate 4 next to single-writer-kernel.tex:1526–1529, where single-/open-minded commitments already appear. Existing candidate 4 says what evidence must be invalidated when a plan changes. This experiment asks when to pay for deliberation at all. Link legible-swarm.tex:1246–1273 for explicit error/attention costs, without substituting human attention for model computation.

**Constructed hand example:** A worker has a viable repair plan. Three events arrive: an irrelevant style note; a newly available cheaper equivalent repair; a changed acceptance criterion that invalidates the old plan. Compare persistent, every-event and event-triggered reconsideration policies on the same event tapes. Separately inject delayed or dropped events, so the event-triggered arm does not receive an unearned perfect detector. A recorded effect whose outcome is unknown enters reconciliation, not an opportunistic retry.

**Prior art:** Rao and Georgeff, BDI Agents: From Theory to Practice (ICMAS 1995), pp315–316, explicitly leave commitment strategy application-dependent: https://cdn.aaai.org/ICMAS/1995/ICMAS95-042.pdf . Bratman, Israel and Pollack, Plans and Resource-Bounded Practical Reasoning (1988), reconsideration/filter-override discussion, presents the stability/revocation tradeoff: https://www.emse.fr/~boissier/enseignement/defiia/up5/pdf/Bratman-PlansPracticalResoning.pdf . Targeted primary passages read in this pass. Neither establishes a universal bold/static versus cautious/dynamic rule for modern coding agents.

**Uncertain claim and decisive study:** Does a declared event policy move the cost/correctness frontier in this workload? Match information access, model version, wall-clock and spend budgets; include monitor cost, queue delay, useful completion, missed invalidations, needless replans and recovery latency. Report regimes and uncertainty, not a single winning strategy. First use scripted tapes to validate measurement, then actual agent executions. Scripts are not LLM performance evidence. grite/STORM/DriCo boundaries remain those in the earlier prior-art follow-up; they do not establish this comparison.

**Semantic figure brief:** Shared event tape over three policy lanes, with separate markers for ignored observation, paid reconsideration, plan revision and observed effect. Plot a proposed cost/correctness frontier only after measurements; no fabricated curve.
