## Candidate 3: Judge independence needs a measured error structure

Origins: `llm-evaluation-harness`, `recursive-synthesis`, `wu-2023-autogen`, `manager-driven-team-orchestrator`, `dag-result-aggregator`, `dag-convergence-monitor` and the evaluation research report.

**Existing text and placement.** Chapter 5, `website-v2/public/whitepaper/spawn-to-person.tex:1883`, defines conflict-free, influence-free, de-biased judges and a re-audit ceremony. Chapter 4, `whitepaper/legible-swarm.tex:947`, already warns about reviewers sharing an error. Therefore the general warning is present. A worked *measurement procedure* belongs after the judge eligibility/selection protocol, with a cross-reference from adversarial review. Separate financial independence, different evidence, and empirically independent errors; none is a substitute for the others.

**Premise reconciliation from Astra.** Chapter 5 `spawn-to-person.tex:2089–2097` treats distinct architectural weights/principals as supplying disjoint strategic cliques. Later, `:2203–2217` explicitly leaves cross-clique collusion and detection/correlation telemetry outside the priced result. Reconcile those passages: architecture alone establishes neither independent mistakes nor independent strategic capture. Preserve the conditional theorem and its later caveat. Ordinary error covariance must not replace the theorem's strategic clique count. This is an internal premise tension, not an absence of all caveats or a refutation of the conditional theorem. [Exact review and counterreading](ASTRA-BOOK-REVIEW.md#3-judge-dependence-promote-to-premise-reconciliation-plus-measurement).

**New primary-source lead, not a Port Daddy result.** Hossain, Yousefi and Lim, [Agreement Overstates Evidence, v1, 18 September 2026](https://arxiv.org/html/2609.22512v1), §§2.1–2.3, 4.5 and 6, measures judge-error dependence and evaluates calibrated retention rules. Its variance-effective judge count does not predict majority accuracy or specify a smaller interchangeable panel. Rule choice needs held-out validation; the tested specialized filters did not improve the reported factuality/code transfers. The preprint's model/task banks, controlled interventions and reference labels limit transfer. Root opened the full HTML and read these sections; no experiment was reproduced.

**How to add it.** Start with three reviewers who independently cite the same stale source: three votes, one evidence defect. Contrast three distinct evidence routes, each checked by a task-specific oracle. Then define a calibration split with trusted labels, record per-item error vectors, report item-level uncertainty and error dependence, and freeze the selection rule before evaluation. Show a failure case in which agreement rises while task correctness does not. Avoid an automatic “diverse providers = independent” rule.

**Candidate research/product.** A reviewer-selection receipt could preserve eligibility, evidence lineage, calibration domain, rule version, missing judgments and held-out performance. The proposed result is whether evidence-route diversity improves incremental error discovery under matched total cost, beyond merely changing model brands. A factorial study could vary judge bank and access to shared versus disjoint evidence. No market vacancy, optimal selector, new theorem or efficacy is established.

**Figure contract.** `draft/judge-dependence-premises`: an aligned relation matrix for principal links, evidence sources and observed errors, plus calibration/evaluation separation. Do not draw three model logos as proof of independence. Mermaid and standalone Book-style ports are rendered in [the gallery](book-drafts/index.html); [exact-source receipt](book-drafts/judges-revisions-conflicts/RECEIPT.json).

## Candidate 4: Replanning must specify what evidence can survive the change

Origins: `dag-dynamic-replanner`, `dag-mutation-strategist`, `dag-replay-debugger`, `dag-graph-builder`, `dag-dependency-resolver`, `windags-decomposer`, `wave-by-wave-parley`, `work-intake-node-shaping` and `dag-runtime`.

**Existing text and placement.** Chapter 4's versioned roadmap (`whitepaper/legible-swarm.tex:934`) already treats amendments as recorded intent. Chapter 1's model-checked work unit (`whitepaper/single-writer-kernel.tex:1767`) and Chapter 5's checkpoint organ (`website-v2/public/whitepaper/spawn-to-person.tex:848`) supply nearby lifecycle concepts. A compact plan-revision worked example could bridge these; the reviewed passages do not supply this exact typed invalidation procedure.

**Prior art prevents a broad novelty claim.** [Temporal's workflow versioning guide](https://docs.temporal.io/develop/typescript/workflows/versioning) describes deterministic workflow history and explicit handling of incompatible code changes. [Snakemake 9.27.0's CLI documentation](https://snakemake.readthedocs.io/en/stable/executing/cli.html#all-options) provides rerun triggers for code, inputs, parameters, environment and timestamps, and dependency-aware execution. These are precedents for version-bound replay and invalidation, not proof of the proposed agent authorization protocol. Root opened both official sources on 2026-09-24. No feature absence is asserted about either platform.

**How to add it.** Let a plan contain “compile artifact,” “review artifact,” and “publish artifact.” Changing the compiler input invalidates the artifact and dependent review. Changing only publication authority need not erase a still-valid compilation result, but must block the effect until authority is current. If publication was already attempted and its outcome is unknown, a graph rewrite cannot treat it as unexecuted. Type each dependency as data, acceptance evidence, authority or effect status; give each a provenance/version contract. Calculate the affected set under those contracts, then reconcile effects before dispatching the revised plan.

**Receipt contract from Astra.** Bind each receipt to artifact/input digests, producer configuration, acceptance policy and verifier version, authority scope/epoch where relevant, effect key/status and validity interval. Separate direct invalidation from propagation. An acceptance-policy change can invalidate acceptance while preserving compilation; a revoked publication capability blocks the effect without erasing compilation truth. Test against an independent invalidation oracle; do not claim minimal recomputation before formalizing that optimization problem.

**Candidate research/product.** Prototype an explanation of which receipts a revision invalidates and why. Compare conservative rerun-all, ordinary data dependency invalidation, and typed invalidation on preregistered changes with independent acceptance oracles. Measure false reuse, unnecessary recomputation, missed revoked authority and duplicate effects. The attractive question is whether separating these edge types saves work without accepting stale evidence; there is no proven minimal invalidation algorithm or safety result yet.

**Figure contract.** `draft/typed-plan-revision`: before/after small multiples over the same three tasks, with a dependency-type key and receipts marked reusable, stale or unresolved. This must depict a concrete change, not an unqualified graph transformation. The final draft uses an aligned receipt-invalidation table to express these relations. Mermaid and all three standalone Book editions are rendered; see [the receipt](book-drafts/judges-revisions-conflicts/RECEIPT.json).

## Candidate 5: Semantic conflicts need an integration oracle

Origins: `semantic-conflict-prediction`, `runtime-task-overlap-detector`, `dag-capability-ranker`, `dag-context-bridger`, `hypertree-planning` and `multi-agent-coordination`.

**Existing text and placement.** Chapter 1 already distinguishes claim granularity (`whitepaper/single-writer-kernel.tex:739`) and advisory claims from enforcement (`:2040`). Chapter 4's worked afternoon (`whitepaper/legible-swarm.tex:465`) is a suitable home for a counterexample. Prior Astra research already recommends repairing S2 with semantic-preservation oracles. This candidate sharpens that existing experiment plan.

**How to add it.** Agent A changes a producer's units from seconds to milliseconds; agent B independently tightens a consumer timeout in a different file. Their patches have no overlapping lines but violate the shared unit contract. Conversely, two agents editing one generated index may be mechanically overlapping yet semantically compatible. Use a four-cell table crossing textual overlap with harmful integrated behavior under a frozen independent oracle. Keep similarity and duplicated intent as separate signals, not substitute axes. Freeze a known-duration integration fixture before either producer or consumer edit. A similarity score is only a prediction, and a declared file claim is only one coordination signal.

**Evidence and proposed result.** This is a constructed example, not measured performance. Freeze fixtures and acceptance tests before fitting a predictor; include positive and negative controls; compare against changed-line, static dependency and review baselines. Split by repository/task family and report missed harmful conflicts, unnecessary serialization, useful completed work and total integration cost. The candidate is a benchmark/oracle design, not a demonstrated detector or a new theorem.

**Figure contract.** `draft/conflict-four-cells`: a 2-by-2 outcome matrix plus the producer/consumer contract edge. A generic “semantic engine catches conflict” box would conceal the unproven step. Mermaid and three standalone TikZ editions are rendered; see [the receipt](book-drafts/judges-revisions-conflicts/RECEIPT.json).
