## Methods as printed in arXiv v1

The input is a DAG plus an already-computed topological ordering T. A **path** uses a direct arc between consecutive members; a **chain** needs only a directed path between each consecutive pair, so it can skip direct arcs. All these are vertex-disjoint covers of all vertices. Tie-breaking not specified below is deliberately left unspecified by the paper.

1. **CO / Chain-Order, Algorithm 1 (§2).** Scan unused vertices in ascending topological order. Each unused vertex starts a path. Repeatedly choose an unused immediate successor of the current endpoint, add it, and continue until none remains. The paper says “there is an unused immediate successor” but provides no tie rule among multiple candidates. This is a path cover heuristic, not the minimum chain partition theorem.
2. **NO / Node-Order, Algorithm 2 (§2).** Scan all vertices in ascending topological order. If the current vertex is an immediate successor of the last vertex of an existing path, append it to an eligible path; otherwise start a singleton path. The pseudocode does not specify a tie rule when multiple existing paths qualify. It is also a path decomposition.
3. **Concatenation, Algorithm 3, §3.1.** Given any path decomposition D, consider each path p_i, set f_i to its first vertex, and run a reversed DFS from f_i, following incoming arcs, to find a last vertex of another current chain. A successful search returns (R_i,P_i): P_i is the found connecting witness path; R_i is the set of all explored vertices except those on P_i. If P_i is nonempty, let l_i be its destination (the last vertex of another path) and concatenate that endpoint’s chain before the chain beginning at f_i. Then remove R_i from the search graph before the next lookup. If no connector is found, P_i is empty, R_i is every explored vertex, and those failed search regions are removed as no-go regions for later lookups. The paper’s reason is specific: no vertex in R_i is a chain’s last vertex, and all its predecessors are also in R_i, so a later reversed search that encounters this region need not search backward through it. It does not discard or reassign vertices on P_i.
4. **Why witness-path interior is not a new chain assignment.** P_i proves that the last member of one chain reaches the first member of another, so the two ordered member lists can be joined into a reachability-chain. The connector’s internal graph vertices remain assigned to their original path/chain(s); moving them into the merged chain would duplicate vertices or break the original partition. The concatenation merges chain memberships at the two endpoints while using the path only as evidence of comparability. This distinction is especially important where the witness traverses a third chain.
5. **Theorem 3.1 / concatenation cost.** If the starting path cover has k_p paths and the result has k_c chains, each successful concatenation reduces the count by one, so c=k_p-k_c. The stated bound is O(|E|+(k_p-k_c)ℓ), with ℓ the longest DAG path. The proof observes the tighter realized term O(|E|+Σ_i |P_i|). It charges explored non-witness regions to disjoint R_i sets and successful witness-path work to Σ|P_i|≤cℓ. Thus a failed DFS does not cause a fresh full-graph scan: its explored region is amortized and excluded from later search. These bounds are for concatenation given a path cover; add the selected initial path-decomposition cost separately. The paper also observes the broad worst-case bound can be O(n²), while experiments for its generators were near-linear; do not call the bound uniformly linear.
6. **H3 / Algorithm 4, §3.2.** This is a Node-Order variation that chooses, among immediate predecessors that are last vertices of paths, one with *lowest out-degree*. When no such predecessor is available it starts a path. It also tries to consume a forced immediate successor. There is a source inconsistency that must remain visible: the prose immediately before Algorithm 4 says “when we visit a vertex of out-degree 1” add its unique immediate successor; Algorithm 4 pseudocode lines 19–21 instead says add an immediate successor s_i of v_i when **s_i has in-degree 1**. These predicates differ. Algorithm 5 repeats the in-degree-of-successor condition. The report cannot establish which is the intended correction; cite both printed versions and avoid silently changing one into the other. Neither the out-degree choice nor the forced-successor rule specifies a tie-break if multiple candidates qualify.
7. **H3 conc. / Algorithm 5, §3.2.** Integrates H3 with concatenation during the ascending-topological scan. For an unassigned vertex, first choose a qualifying immediate predecessor that is a path endpoint using the H3 lowest-out-degree rule. If none exists, run the same reversed-DFS lookup; on success, use the connector’s destination/chain endpoint, and in either case remove R_i before later searches. Append v_i to that existing endpoint chain or start a new chain. The pseudocode then applies the same successor rule as Algorithm 4 (successor in-degree 1). This is described as integrated construction, not H3 followed by a separate full concatenation post-pass. Its bound remains O(|E|+cℓ), with the actual successful witness lengths determining a tighter realized count. Source statements/experiments describe “very close” or fewer chains, not a universal approximation ratio.

### Small constructed trace for Algorithm 3

Let arcs be c→x, x→a, a→b, and give Algorithm 3 the valid vertex-disjoint direct-path cover D={ [a,b], [x], [c] }. It scans [a,b] with f=a, searches backward and finds c→x→a, where c is the last vertex of singleton chain [c]. It joins member sequences to obtain chain [c,a,b]; the witness x stays in its original chain [x]. The final two chains partition vertices {a,b,c,x}, and successive members of [c,a,b] are ordered by reachability. The number of chains drops from 3 to 2, one for this successful concatenation. This hand-constructed input is chosen to show the witness/assignment distinction; it does not claim any particular CO/NO/H3 tie-breaking outcome or optimality.

For a failed lookup, the source contract is equally concrete: all visited vertices enter R_i, P_i is empty, and G←G\R_i. A robust implementation should represent this as a reusable “known-dead for endpoint search” mark if destructive mutation would damage the caller’s graph. The proof only licenses skipping those regions for this concatenation search; preserve the original DAG for indexing and validation.

## SEA §3 filter is not the full index or exact reduction

The published §3 filter starts from any given chain/path decomposition. For each source vertex and each target chain, keep the outgoing arc to that chain’s **lowest** (earliest/topologically first) target and identify other outgoing arcs into that same chain as transitive. Symmetrically, for each target and each source chain, keep the incoming arc from the **highest** (latest topological-rank) source and identify the other incoming arcs from that chain as transitive. The union finds a large subset E'_tr⊆E_tr in linear time. The remaining E'_red=E−E'_tr⊇E_red retains reachability but is only a superset of the exact non-transitive set. The operation does not promise to remove every transitive edge, and it is not the full transitive reduction.

SEA §4 / Algorithm 1 is a separate, complete index-build recipe:

1. Given a DAG, topological ordering and a supplied vertex-disjoint path/chain decomposition with k_c members, record every vertex’s chain and within-chain position.
2. Allocate an array of length k_c per vertex; initialize all entries to ∞, then set the vertex’s own-chain slot to its own position. This makes self-reachability explicit.
3. Process vertices in reverse topological order. For each vertex, visit its outgoing targets in **ascending topological order**. If target position t_pos<low[v,t_chain], treat that edge as a useful non-transitive successor for the index and elementwise-min merge the target’s array into the source’s. The sorted-successor condition is essential to the proof that a later edge already known redundant can be skipped. If adjacency lists are not in that order, the paper says the work can grow from the reduced-edge-sensitive k_c|E_red| term to k_c|E|.
4. For query u↝v, look up v’s chain j and position p, then answer true exactly when low[u,j]≤p. This is **reflexive**: initialization sets low[u,chain(u)]=position(u), so a query with u=v returns true. To implement strict/non-reflexive reachability, return this answer AND u≠v. Do not label the paper’s relation non-reflexive.

**Initialization complexity correction.** The paper’s Theorem 5 states index-construction work O(|E_tr|+k_c|E_red|), and §4 states space O(k_c|V|). But the displayed Algorithm 1 initializes a length-k_c array for each of |V| vertices, including filling sentinel entries and setting the self slot. A dense array implementation therefore spends Θ(k_c|V|) time just on allocation/initialization. Report the paper’s theorem verbatim as its stated propagation/edge-update bound, and report the concrete dense-array end-to-end index build as at least
O(k_c|V|+|E_tr|+k_c|E_red|)
plus topological ordering, adjacency sorting O(|V|+|E|), and the selected decomposition’s cost. Do not erase initialization because it is asymptotically dominated on some dense/small-width families; for an edgeless DAG the edge-only theorem expression would be zero while the explicit output arrays still occupy and initialize k_c|V|=|V|² cells. A sparse/lazy alternative would need its own representation and complexity analysis.

## Experimental scope to retain verbatim in spirit

arXiv v1 §3.3’s decomposition-quality experiment uses NetworkX ER, BA and WS generators plus a path-based DAG model. It orients generated edges from lower to higher node IDs; uses 5k/10k nodes and average degree 5, 10, 20, 40, 80 and 160; compares CO, CO conc., NO, NO conc., H3, and H3 conc. chain/path counts against exact width from a Fulkerson method. It describes H3 conc. as producing fewer chains in its tables. §3.1 separately reports concatenation timings on ER graphs from 10k through 160k nodes at average degree 10. SEA 2023 §§2 and 4’s separate reachability-index experiment uses generated graph families and 5k/10k node cases; its input assumptions include sorted adjacency and its own implementation/hardware context. These are algorithm measurements on generated graph families, not evidence of task-ordering, resource allocation, worker count or scheduling quality. Quote exact numeric outcomes only with the table, model, size/density and metric attached.

## Chen method boundary

For the chain bundle, Chen 2009 is a separate source. The primary ICEIS 2009 searchable PDF body says it uses three phases—DAG stratification, chain generation and virtual-node resolution—and says its chain generation distinguishes virtual nodes created for actual nodes from virtual nodes generated for virtual nodes. It says resolution builds a “combined alternating graph” so the number of virtual nodes resolved at each level is maximized. It identifies the source it critiques as a *Y. Chen and Y. Chen (2008)* algorithm that can fail to give a minimum decomposition, then proposes a revised procedure with the same O(n²+bn√b)-style bound.

The current environment exposes useful indexed body text but the direct PDF request can return 403; the full operational construction/proofs of the 2009 alternating-graph procedures are not fully verified in this supplement. Retain only those source-stated phase facts unless the author reopens and reads the complete source body. Do not conflate Chen DEXA 2007 metadata/abstract with the 2008 target criticized by 2009, or claim generic adjacent-level maximum matching reproduces either exact procedure.
