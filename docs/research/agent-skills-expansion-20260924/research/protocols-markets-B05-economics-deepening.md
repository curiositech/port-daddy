### 2. \`agent-labor-pricing-function\`

#### Correct the domain before selecting a pricing formula

The skill currently combines product packaging (seller sets subscription/usage price) with marketplace labor procurement and invokes mechanism-design language without requiring the author to identify who has private information, which side chooses/sets price, what is allocated, feasibility, individual rationality, budget constraints, or the truthfulness/stability objective. These are different problems.

Primary-source boundaries:

- Xia and Muthukrishnan, “Revenue-Maximizing Stable Pricing in Online Labor Markets,” HCOMP 2017, [AAAI paper PDF](https://cdn.aaai.org/ojs/13299/13299-64-16816-1-2-20201228.pdf), accessed 2026-09-24. Read abstract, introduction/model and theorem/results sections. The paper models workers with skill vectors and single-skill tasks, each with a skill threshold and maximum task price; worker/task feasibility depends on qualification and price; stability is defined by absence of a blocking worker-task pair under paper preferences. It distinguishes uniform and nonuniform pricing: nonuniform allocation is NP-hard even with two price levels (paper’s 3/2 approximation), while the SMUP randomized uniform-price mechanism is truthful and stable with a \(1+\log h\) revenue-approximation guarantee under its bounded task-price range \(v_j\in[1,h]\). This is not a generic theorem about subscriptions, agent work, or every buyer/seller matching market.
- Myerson, “Optimal Auction Design,” *Mathematics of Operations Research* 6(1), 1981, [publisher DOI/abstract](https://pubsonline.informs.org/doi/fpi/10.1287/moor.6.1.58), accessed 2026-09-24. The abstract scopes the result to a seller auctioning a single object to possible buyers with private willingness-to-pay. It does not establish truthful multi-task labor procurement or a SaaS margin rule.
- Stripe, [current pricing page](https://stripe.com/pricing), accessed 2026-09-24. Standard domestic online card example is 2.9% + $0.30 per successful charge; geography, payment method, product and negotiated rates vary. Use as a dated input, not a universal transaction fee.
- OpenAI, [current API pricing](https://developers.openai.com/api/docs/pricing), accessed 2026-09-24. Current standard short-context gpt-6-luna rate shown is $0.05 / million uncached input tokens, $0.005 / million cached input tokens, $0.25 / million output tokens. Current long-context rate tiers differ; pricing changes, so re-read before quoting. [Prompt caching documentation](https://developers.openai.com/api/docs/guides/prompt-caching) says cached prefixes require an unchanged prefix and cache eligibility/lifetime are model-specific. Cache input still counts as context. This is a provider price schedule, not measured task cost.
- GitHub Copilot pricing/billing is plan- and date-dependent. The official current legacy billing notice says certain old Pro/Pro+ annual plans remain on legacy premium-request billing; do not generalize a single quota/credit model to all customers. [Official legacy notice](https://docs.github.com/en/copilot/concepts/billing/copilot-requests), accessed 2026-09-24.

Current official docs distinguish Standard/Enterprise requests per user/day, agent-mode prompts may issue multiple requests, and quota can aggregate across models. #### A checkable, explicitly constructed unit-economics example

This example tests accounting, not a market price recommendation or forecast. Let one *verified completed task* sell for $5.00. Assume the task makes two gpt-6-luna standard short-context calls on the rates above:

| Call component | Calculation | Cost |
|---|---:|---:|
| Call 1, 12,000 uncached input | 12,000 × $0.05 / 1,000,000 | $0.000600 |
| Call 1, 1,000 output | 1,000 × $0.25 / 1,000,000 | $0.000250 |
| Call 2, 10,000 cached + 2,000 uncached input | 10,000 × $0.005/M + 2,000 × $0.05/M | $0.000150 |
| Call 2, 1,000 output | 1,000 × $0.25/M | $0.000250 |
| Total model tokens | Sum of every call, including verification | **$0.001650** |

Assumptions: the second request has a real cache hit on exactly the unchanged 10,000-token eligible prefix; both calls qualify for standard short-context rates; no uncounted reasoning tokens or other models; provider billing uses these listed rates. A stale cache, altered prefix or long-context rate changes this result.

Now add explicitly constructed non-model costs: sandbox/tool fee $0.06 per attempt; amortized support/infra $0.03 per successful unit; human review 4 minutes at a loaded $30/hour = $2.00. These are scenario inputs, not measured Port Daddy costs. For one successful attempt, pre-payment cost is $2.09165. A $5 domestic card charge costs $5×0.029+$0.30=$0.445 under the cited Stripe example; total variable cost is $2.53665. Contribution is $5−$2.53665=$2.46335, gross contribution margin on gross revenue is 49.267%. If reporting margin against net-of-processing revenue instead, net revenue is $4.555 and margin is $2.46335/$4.555 = 54.08%; label which definition is used.

Failures and retries must remain visible in both economics and customer semantics. For an illustrative failure mix, suppose 15% of billed successes require one extra attempt costing another $0.06165 (same token path plus sandbox, no extra review), with the failed attempt absorbed rather than billed. Expected cost per eventual success rises by $0.15×$0.06165=$0.0092475, to $2.5458975 including the successful attempt’s card fee; expected contribution at $5 is $2.4541025. This tiny retry estimate is deliberately not presented as a measured distribution; a real floor needs observed attempt-level tails, refunds, chargebacks, abandoned work, support, taxes, CAC and failure rates. A terminal error must not silently count as “completed outcome” when outcome billing is promised. Record whether partial work is billable, retried, credited or absorbed before choosing a value unit.

This arithmetic exposes why token price alone is a poor cost-floor proxy for human-backed labor: here model spend is $0.00165 while four minutes of constructed review is $2. Use real task-level call traces and time/tool ledgers before setting prices.

### 3. \`context-economics-for-agent-swarms\`

#### What the sources support

- Liu et al., “Lost in the Middle: How Language Models Use Long Contexts,” TACL 12 (2024), pp. 157–173, [ACL paper](https://aclanthology.org/2024.tacl-1.9/) / [PDF](https://aclanthology.org/2024.tacl-1.9.pdf), accessed 2026-09-24. The paper controlled context length and relevant-information position across then-evaluated models/tasks; performance could vary strongly with evidence position and showed a U-shaped pattern in tested settings, with task/model exceptions. It does not establish that every modern model degrades monotonically with length, a universal safe token threshold, or “n² attention” as the cause of a particular failure.
- OpenAI, [pricing docs](https://developers.openai.com/api/docs/pricing), accessed 2026-09-24: model and token-type rates differ, long-context tiers may differ; cost comparison must include exact model, cache status, input, output and call count. #### Explicit constructed context/cost allocation

Use native context tokens, provider allowance, cash cost, and evidence quality as separate ledgers. The following two-call example is constructed to show the distinctions; it is not a swarm benchmark:

- First GPT-6 Luna call: 20,000 uncached input + 1,000 output → $0.00125 under the cited short-context standard rates. The model context contains 21,000 tokens.
- Second call with a 10,000-token unchanged eligible cached prefix + 2,000 fresh input + 1,000 output → $0.00044. This call’s context still contains 13,000 input tokens plus output-generation activity; cached status changes price, not the fact those tokens occupy the request context.
- Combined model cost is $0.00165. If that 10,000 prefix is not cache-eligible, replace its $0.00005 cached charge with $0.00050 uncached: second call $0.00085 and two-call total $0.00210. Cache benefit for this scenario is $0.00045. No tool, human, or provider subscription costs are included.

For a deliberately constructed compaction alternative, suppose a third call compacts/reconstructs from durable artifacts using 4,000 summary/pointer input + 3,000 rehydrated source input + 1,000 output, all uncached: cost = 7,000×$0.05/M + 1,000×$0.25/M = $0.00060. Add it to the first request; a following compact-context work call at 4,000 input + 1,000 output costs another $0.00045, for a three-call total $0.00230. That cash total exceeds the two-call cached path ($0.00165) in this tiny example, while reducing the later request’s input from 13,000 to 4,000 tokens. Whether the smaller working context improves quality is an empirical task/model question; whether a saved pointer causes retrieval, permission, latency or tool cost is an additional measured cost. Do not call compaction “cheaper” without its generation/reload/fetch costs and the number of subsequent uses. A summary alone cannot replace a linked, authorized source artifact.

A sample allocation policy can reserve per-agent native token budgets without inventing cross-provider “tasks remaining”: planner 12k input/2k output; each of two workers 20k input/2k output; reviewer 8k input/1k output; coordinator 4k input/1k output. These are constructed starting caps for this task, not universal defaults. Track actual by model, attempt, input/cache/output, tool, outcome, and authority receipt. Reserve a local 15% retry/headroom envelope only as a stated policy assumption; observed provider capacity must separately cover it before a real call. An evidence fixture or percentage without a current, attributable source does not mint capacity or call authority.

Failure accounting should distinguish:
- verified complete: close the outcome unit and reconcile all attempts;
- retryable failure with known completed response: count its actual tokens/tool cost, then explicitly authorize/reconcile retry;
- timeout / lost response / unknown tool outcome: retain an unresolved-attempt hold until reconciled; do not assume zero spend or no side effect;
- rejected / permission-denied / cancelled before dispatch: record the reason and whether any provider/tool action occurred; never debit an unobserved action as completed;
- cache miss, stale quota, missing rate-window field, conflicting observations: capacity and cost forecast carry UNKNOWN/range, not a zero or universal conversion.

The current \`subscription-capacity-ledger.md\`, schema, examples, validator and activation test contain a proposed local evidence contract: native-window observations, reservations, holds, aliases, freshness, forecast ownership and execution class. Preserve the rules that unknown/stale/contradictory evidence is ineligible and fake/replay observations fit simulation only; distinguish that local design from provider behavior and enforcement. The file remains a design/test bundle, not runtime-readiness proof. Verify whether the validator marks a ready fixture as just structurally consistent rather than launching-authorized; that distinction should remain explicit.

#### Correct causal claims and retain the full methods

Retain the four separate economic views (cash COGS; working-context occupancy; digest legibility/evidence access; subscription-native allowance). Preserve all three agent roles (planner, worker, reviewer) and their budget allocation heuristic as a heuristic to measure, not a fixed rule; preserve macro pointer/summary overlays, micro tool-output truncation, tool-use/result pair integrity, durable note-taking, worker isolation, and source-linked zoom-back. Keep digest audience variants (human, successor, market ledger), cooperative accounting vs strategic externality framing, subscription capacity holds/forecast p95/unknown handling, failure cascade headings, cost metering, and the existing schema/example/validator contract. For each claim state whether source paper/platform documents it or the bundle proposes it.

Correct active claims:
- Tokens are not the sole way a human or successor sees work: durable files, diffs, database records, UI views and permissioned artifact links carry evidence. Tokens are model-input/output units; compaction is one representation layer, not the entire legibility system.
- “Transformer attention is n², therefore context rot” is not evidence for the claimed behavioral cause. Separate computational architecture/cost from measured task accuracy; run controlled equal-task/equal-evidence position/length experiments before claiming a degradation curve.
- The original Lost-in-the-Middle experiment supports position-sensitive behavior for evaluated models and tasks, not a current universal threshold. A paper’s 2024 result is not a 2026 provider limit.
- Cache discount lowers price for eligible tokens but those tokens still occupy the request’s context; do not budget cached tokens as zero occupancy.
- Provider quota schemas, account plans and observations change. Missing window fields and unknown execution outcomes must not be interpreted as unlimited capacity or no cost. Capacity “eligible” is not launch authority.
- “Human cannot see unless digest token” and privacy/permission claims need a specified transport/artifact access model; artifact pointers still need access checks and do not grant access.

Two useful Mermaid diagrams:

1. **Four-ledger context plan:** each request debits cash (model/tool/human), context occupancy (input/output and cache occupancy), provider-native capacity (exact window and freshness), and evidence/provenance (source pointer + permission). Unknown quota/attempt branches hold or block; cached input changes cash rate only; none of these edges grants launch authority.
2. **Compaction and retry trace:** raw output → durable authorized artifact → pointer/summary overlay with source links → verifier/zoom-back; choose pointer when reconstructable, summary when not; preserve tool-use/result pairs; cache hit/miss and compaction/reload costs feed separate accounting. Add timeout/unknown branch that holds capacity until reconciliation, and permission-denied/unavailable artifact branch that stops factual reuse.

**Novelty candidate:** subscription-native capacity evidence with uncertainty reserves may fit an existing resource-accounting chapter. It is not a novelty claim until compared. The independent contribution, if any, would need a worked empirical protocol showing how native allowance and uncertain attempts change a decision; the schema/validator alone are an engineering proposal.
