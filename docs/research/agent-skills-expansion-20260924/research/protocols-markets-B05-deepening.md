## 1. harbor-results

**Local evidence read:** `skills/harbor-results/SKILL.md`, `references/results-compendium.md`, `references/l3-tacit-lessons.md`, and the cited scripts `sheaf_mechanism_proof.py`, `a3_epsilon_ledger.py`, `sheaf_repair_and_2complex.py`, `sheaf_harness_v2.py`, `a6_no_mint.py`, `a7_experiment.py`. These scripts are the primary evidence for what the bundled claims actually assert; they are not papers or deployed-system evidence.

**Mechanism and correction.** The sheaf repair script operates on a finite graph: local sections are node values, an edge restriction/compatibility check identifies inconsistencies, and repair changes a bounded set of sections. A nonzero first Betti number is a topological cycle count, not by itself a proof that one edge repair is globally optimal. The current CR-4 witness is one 12-node, beta1=1 fixture and an inexpensive bridge choice; the loop can run up to |E| rounds. It does not prove a general `<= beta1` repair bound or global minimum-cost optimum. Treat those as conjectures until an adversarial family or proof discharges them. This is an evidence gap, not a demonstrated universal counterexample. CR-5 synthetic endpoint outcomes do not validate a production classifier.

**Useful rule/example.** For each reported property, bind (a) graph/complex and coefficients, (b) objective and cost function, (c) algorithm, (d) exhaustive or bounded scope, and (e) exact fixture/seed. A hand-check on a triangle: any one edge cut destroys that cycle, but if the objective weights the cut edge cost 10 and an alternate local-value repair costs 1, “fewest cuts” and “minimum-cost repair” are different claims. The current script should be described only according to its implemented objective and tested fixture.

**References/limits:** local scripts above, read directly; no outside publication was used to claim that this implementation works. **Add:** a claim ledger tying each theorem-like statement to code/assertion, assumptions and test scope; an adversarial weighted cycle family with independently computed optimum. **Diagrams:** (1) claim-to-evidence ladder (algebraic statement → script assertion → fixture run → refinement/deployment evidence); (2) one cycle with alternative cut costs and residual inconsistent edges. **ASCII:** convert CR-4 branching/decision ASCII only after correcting the guarantee; keep evidence table as a table. **Book idea:** a compact example showing why cycle rank does not alone imply weighted repair optimality; compare against the manuscript before calling it novel.

## 2. bellifemine-2007-jade-fipa

**Sources read:** JADE official v4.6 API pages, including `jade.domain.FIPAAgentManagement` and `jade.domain.df`; official JADE protocols examples page. Official programmer-guide PDF search/index text was available, but direct PDF retrieval failed in this pass, so implementation-guide details below are not treated as body-verified. Bellifemine et al., *Developing Multi-Agent Systems with JADE* (Wiley 2007) publisher record was checked, book body not accessed. FIPA 00023 canonical endpoints were unavailable; JADE API says its management ontology maps to FIPA Agent Management Spec 23 version H, 2001-08-15.

**Mechanism.** The API provides `DFAgentDescription` records and `DFService` registration/search operations; that is an implementation contract for a local DF API, not proof that FIPA requires a single physical registry or that registration authenticates an agent. JADE examples expose protocol behavior classes such as `AchieveREInitiator/Responder` and `ContractNetInitiator/Responder`; these are JADE callbacks/behaviors layered over message exchanges, not the normative spec itself. Model the operation as: send CFP with deadline; collect `PROPOSE`/`REFUSE`; choose and send `ACCEPT_PROPOSAL`/`REJECT_PROPOSAL`; then await `INFORM`/`FAILURE` as a protocol outcome. A reply timeout is an unknown outcome and must not be silently mapped to remote crash or refusal.

**Useful correction.** Separate four fields in examples: message performative, protocol state, authenticated principal/authorization result, and observed external effect. A valid `INFORM` or protocol-final callback establishes what the implementation reported, not that an external side effect independently occurred. Remove universal timeout/resource thresholds unless a sourced application policy justifies them.

**Sources/access:** [JADE v4.6 management API](https://jade.tilab.com/doc/api/jade/domain/FIPAAgentManagement/package-summary.html) (official indexed API, direct open unavailable); [JADE DF API](https://jade.tilab.com/doc/api/jade/domain/df.html) (official API); [JADE protocol examples](https://jade.tilab.com/documentation/examples/protocols/) (official examples); Wiley book record https://onlinelibrary.wiley.com/doi/book/10.1002/9780470058411 (metadata only). **Add:** label each behavior as FIPA protocol semantic, JADE callback, or local application rule; include the uncertain-timeout state. **Diagrams:** CFP protocol state machine; mapping table/sequence from wire performative to JADE behavior callback to authorization/effect receipt. **ASCII:** replace existing protocol selection tree with predicate-based choices and an “unknown/timeout” exit. **Book idea:** a small conformance mapping exercise across normative FIPA, JADE callback and effect receipt; prior-art assessment pending.

## 3. bordini-hubner-2007-jason

**Sources read:** Jason official site, official FAQ (including failure-handling caveats), the active skill and its `context-driven-plan-selection`, `graceful-failure-and-recovery`, and `goal-subgoal-decomposition` references. The Wiley record for Bordini et al., *Programming Multi-Agent Systems in AgentSpeak using Jason* was checked; the book itself was not accessed.

**Mechanism.** Jason is an interpreter for an extended AgentSpeak language; the relevant operational loop is event selection → applicable/relevant plans → option selection → intention selection → execute one intention step, with new events and belief changes feeding subsequent cycles. Plan context is an executable applicability guard, so `+!recover : obstacle_seen & route_known <- ...` is materially safer than an unconditional catch-all. The FAQ describes failure events for failed actions/subgoals, but explicitly notes that failure handling is not fully formalized by the operational semantics. Do not make a universal claim about retry behavior without pinning interpreter version and selection functions.

**Worked rule.** On `-!deliver(Item)[error(E)]`, first update the belief/diagnostic record, then consider a retry plan only if the error is transient and the retry budget is task policy; select alternate route only if a fresh route belief exists; otherwise leave the goal failed/escalate. Avoid `>3` retry or depth `>10` as purported Jason semantics.

**Sources/access:** https://jason-lang.github.io/ (official current docs/site); https://jason-lang.github.io/doc/faq.html (official FAQ full body); https://onlinelibrary.wiley.com/doi/abs/10.1002/9780470061848 (publisher metadata, no full book access). **Add:** version the runtime semantics and distinguish language event from application recovery policy. **Diagrams:** BDI operational cycle with event/options/intention queues; failure state machine separating retry, alternative plan, escalation and terminal failure. **ASCII:** turn current recovery ASCII into actual Jason event/context syntax plus policy prose. **Book idea:** runnable trace illustrating the gap between language-level failure event and platform/application retry policy; compare with existing formal-semantics material.

## 4. agent-conversation-protocols

**Sources:** FIPA XC00025D primary body could not be fetched (CiteSeer mirror timed out); no conformance claim is made from its title. Full current immutable A2A v1.0.0 specification and proto were inspected; official MCP 2026-07-28 changelog read. Local skill, trace schema, validator and gather/terminal references were read.

**Mechanism/correction.** The local trace schema is a model for recording conversations, not a wire-protocol certification. A2A 1.0.0 distinguishes `taskId` (server-generated) and `contextId` (may be client supplied); Send Message MAY use message IDs for duplicate detection, and Cancel Task is idempotent within its defined behavior, but this is not a universal exactly-once external-effect guarantee. MCP 2026-07-28 changelog says stateless core, removes initialization/session header, puts version/capability metadata per request, moves Tasks outside core to an extension, and on broken streams reissues with a new JSON-RPC request ID. Thus a transport request ID cannot be a durable operation key across replay.

**Rule/example.** Freeze a gather’s participant set and epoch before issuing three review requests. Record request transport ID, stable logical operation key, participant, and causal parent separately. If two return and the third times out, state remains `BLOCKED/INCOMPLETE`, not COMPLETE; cancellation records the local cancellation request and does not assert a remote process stopped. On transport replay, use the stable operation key only if the remote application contract explicitly supports it; otherwise reconcile effect before retry.

**Sources/access:** [A2A v1.0.0 specification](https://a2a-protocol.org/v1.0.0/specification/) (normative versioned body); [A2A v1.0.0 proto](https://github.com/a2aproject/A2A/blob/v1.0.0/specification/a2a.proto) (version-pinned schema); [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) (official released changelog); local validator/schema fully accessible. **Add:** typed distinction among delivery, protocol lifecycle, semantic completion, cancellation, and verified external effect. **Diagrams:** causal DAG vs deterministic replay tie-break; terminal-state fence distinguishing COMPLETE/BLOCKED/CANCELLED/UNKNOWN. **ASCII:** convert existing reducer tree only after preserving these terminal distinctions. **Book idea:** stable operation identity across stateless transport replay; compare with existing distributed-systems/retry treatment.

## 5. agent-discovery-directories-guilds

**Sources read:** official A2A v1.0.0 spec data model, RFC 6763 body sections 4–6; official JADE DF API. FIPA SC00023K primary endpoint unavailable; agent2agent.info discovery guide is community material and is not used as normative evidence.

**Mechanism/correction.** DNS-SD expresses service discovery through DNS records: PTR discovers service instances; SRV locates a target/port; TXT carries service metadata. It provides naming and endpoint lookup, not agent identity verification, authorization, or capability truth. JADE DF register/search is an API implementation; do not infer singleton physical topology, mandatory federation, or protocol-level trust. A2A defines an Agent Card data model while leaving discovery mechanisms open; card publication does not attest the advertised capability.

**Worked rule.** Resolve a service instance → fetch its card → validate expected origin/signature or configured trust binding → check version/capability and authorization → issue a bounded harmless probe/task → accept only task-specific evidence. If trust binding is absent, keep the listing as an untrusted candidate, not an eligible agent.

**Sources/access:** [RFC 6763](https://www.rfc-editor.org/rfc/rfc6763), full body, especially DNS-SD overview and PTR/SRV/TXT sections; [A2A v1.0.0](https://a2a-protocol.org/v1.0.0/specification/) full normative model; [JADE DF API](https://jade.tilab.com/doc/api/jade/domain/df.html), official API; FIPA 00023K not accessible. **Add:** distinct discovery, identity, authorization, capability-evidence gates. **Diagrams:** DNS-SD lookup sequence plus explicit trust gate; topology alternatives (central/federated/multicast) with no implied FIPA mandate. **ASCII:** replace scale cutoffs with measured deployment constraints. **Book idea:** a capability-advertisement verification example across discovery layers; novelty unassessed.

## 6. agent-interchange-formats

**Sources:** A2A v1.0.0 normative spec/proto, MCP 2026-07-28 official changelog, JSON-RPC 2.0 specification; local active skill/examples. A protocol name alone does not establish that an implementation serializes or validates it correctly.

**Mechanism/correction.** Keep roles distinct: MCP is host/client/server for tool and context access; A2A is remote agent messaging/tasks. JSON-RPC supplies request/response/error envelope semantics, not agent identity, capability, or cross-protocol compatibility. A2A proto defines versioned messages and task structures. MCP’s 2026-07-28 core is stateless per changelog; its optional Tasks extension is not universal core behavior. Never infer generated SDK conformance from a schema/proto existing.

**Rule/example.** For an MCP tool that delegates to A2A, define an explicit adapter mapping: caller principal → allowed tool → remote A2A agent/card → task request and stable business key → returned task state → locally verified artifact. Preserve source protocol version and validation result in the receipt. Reject unknown versions/fields only according to that version’s defined compatibility rule; do not silently reinterpret them.

**Sources/access:** [A2A v1.0.0 spec](https://a2a-protocol.org/v1.0.0/specification/), [pinned proto](https://github.com/a2aproject/A2A/blob/v1.0.0/specification/a2a.proto), [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog), [JSON-RPC 2.0](https://www.jsonrpc.org/specification) official text. **Add:** version/role/security/effect matrix plus generated-binding → runtime-validation provenance. **Diagrams:** sequence contrasting MCP tool call and A2A task; schema-to-binding-to-validator provenance graph with failure branch. **ASCII:** simplify current universal selector into a boundary matrix. **Book idea:** protocol bridge as an explicit authority/effect boundary; check manuscript prior art.

## 7. fipa-00037-communicative-act-library

**Primary source fully opened:** FIPA Communicative Act Library Spec XC00037H, 2000/H, archived full 44-page PDF [mirror](https://jmvidal.cse.sc.edu/library/XC00037H.pdf), notably definitions of feasibility preconditions (FP) and rational effects (RE), plus `inform`, `agree`, `request`, `refuse`, and `inform-if` sections. Canonical J endpoint returned 403, so this is H only, not J. The skill and its FP/RE and ability/context references were read.

**Core method/correction.** FP state when an act is feasible for the sender; RE describes the attitude the receiver is expected to adopt under the formal model. Spec text says one cannot assume RE follows simply from sending the message. `inform(p)` does not externally prove `p`; `agree` is an intention to perform a requested action, not completion. Preserve the formal mental-attitude semantics while explicitly separating it from delivery, receiver compliance, truth, and external effect. The spec itself notes the difficulty of unambiguous conformance testing.

**Worked trace.** Sender `request(do(x))`; responder sends `agree` (commitment) or `refuse` (no commitment). Later it sends `inform(done(x))` or `failure`; for a consequential effect, the caller independently reads/verifies the target state. For `inform-if(p)`, the meaningful content may be `p` or `not p`, not a numeric confidence threshold invented by the skill.

**Source/access:** XC00037H full body; canonical XC00037J https://www.fipa.org/specs/fipa00037/SC00037J.html inaccessible (403). **Add:** two-layer semantic table: communicative attitude vs application evidence. **Diagrams:** act FP/RE semantics alongside external truth/effect evidence; request conversation states with refusal, failure, timeout/unknown. **ASCII:** replace confidence cutoffs with the exact preconditions and branches. **Book idea:** “speech act is not effect receipt” hand-checkable example; compare existing trust/authority sections.

## 8. fipa-00086-ontology-service

**Sources:** active skill and all relevant references read. FIPA XC00086D primary body not available; [catalog record](https://ko.cuni.cz/node/2312.html) supplies title/date/revision metadata only. Do not present these metadata as method verification or substitute JADE’s management ontology.

## 9. hong-et-al-2024-metagpt

**Primary source:** Hong et al., “MetaGPT: Meta Programming for A Multi-Agent Collaborative Framework,” ICLR 2024, arXiv v7 (2024-11-01), [full body](https://arxiv.org/html/2308.00352v7), especially framework/SOP description and experiment/ablation sections. Current author repository [README](https://github.com/FoundationAgents/MetaGPT) read for present project state, but `main` is moving and not a release pin.

**Mechanism.** The paper makes SOPs first-class: role-specialized agents receive structured artifacts (requirements/design/tasks/code/test results) through a shared message pool and act when dependencies/role subscriptions permit. Its software-development run includes an Engineer executing unit tests and revising code based on failures, with a bounded retry count in that experiment. This is a practical artifact-grounding loop: hand a failed test/output back to the producing role, rather than treating another model’s prose agreement as validation.

**Evidence boundary.** HumanEval/MBPP/software-development results and ablations are tied to the paper’s models, prompts, tasks and scoring. Report exact table and setup when repeating a number. They do not establish universal “roles reduce hallucinations” or automatic truth. Executability/test scores are evidence only for the tests and benchmark; model-written tests may share blind spots. A test pass is a bounded oracle, not proof of complete requirements.

**Worked rule.** Generate a small artifact, run an independent test harness, attach failing stdout/trace to the repair task, and stop on a specified experiment limit; report remaining failures and test provenance. **Sources/access:** arXiv v7 full body, plus current moving GitHub README. **Add:** method/evaluation table with benchmark, task count, model, metric, ablation, and limitation; preserve real SOP and role-pipeline detail. **Diagrams:** requirement→design→task→code→test artifact pipeline; repair loop with external test oracle, retry cap, unresolved exit. **ASCII:** replace generic confidence mindmap with artifact flow. **Book idea:** mechanically observable artifact handoffs vs role labels; compare with current software-agent chapter.

## 10. wu-2023-autogen

**Primary paper:** Wu et al., “AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation,” arXiv v2 (2023-10-03), [full body](https://arxiv.org/html/2308.08155v2), architecture and evaluation sections. Current official docs at [AutoGen stable](https://microsoft.github.io/autogen/stable/) and [termination tutorial](https://microsoft.github.io/autogen/dev/user-guide/agentchat-user-guide/tutorial/termination.html) are moving documentation; check their version labels before copying API snippets.

**Mechanism.** The historical paper’s conversation-centric design configures agents as LLM, tool or human-backed participants, uses message routing and programmatic termination/reply limits to constrain dialogue, and supports group-chat speaker selection. A useful operational practice is to make control policy explicit: who may speak next, who can invoke tools, how many turns, and what event ends the run. Current docs describe termination conditions as stateful conditions over messages/events and require reset for reuse; e.g., `MaxMessageTermination` bounds message count, while text mention terminates on a matching marker. Such termination is a control event, not a semantic proof of task completion.

**Evidence boundary.** The paper’s 12-task pilot and model/topology comparisons vary by task/model; e.g. its own table reports differences in completion and calls, including termination failures. No global multi-agent superiority claim is licensed. Same model/common context does not create independent corroboration.

**Worked rule.** Use a small max-turn condition to cap cost; separately require a task-specific artifact validator before marking success. If termination fires with no valid artifact, record capped/unresolved, not complete. **Sources/access:** paper v2 full body; current official docs opened, API version drift possible. **Add:** align historical concepts with pinned current API and keep study numbers task-bounded. **Diagrams:** routed conversation with explicit tool authority and termination edges; separate control plane (speaker/termination) from evidence plane (validated artifact). **ASCII:** replace generic multi-agent mindmap with one concrete conversation/termination trace. **Book idea:** semantic completion versus framework termination; compare existing evaluation chapter.

## 11. agent-labor-pricing-function

**Primary source full body:** Xia & Muthukrishnan, “Revenue-Maximizing Stable Pricing in Online Labor Markets,” HCOMP 2017, [AAAI proceedings PDF](https://cdn.aaai.org/ojs/13299/13299-64-16816-1-2-20201228.pdf), 10 pages; definitions/model pp. 1–3, mechanisms and experiments later in paper. DOI 10.1609/hcomp.v5i1.13299. The active skill and decision/unit-economics references, JSON example/schema, and `pricing_stress.mjs` were read.

**Actual model and correction.** Worker-task matching uses skill and reported task requirement/maximum cost. The paper’s stability means no unmatched or currently matched worker/task pair would both prefer each other under its particular preference model. Truthfulness is on the task side; worker skill reports are explicitly outside scope because assumed publicly accessible through ratings/certificates/experience. IR and a maximum task price `h` are model assumptions. The SMUP uniform randomized pricing has expected revenue `(1+log h)` approximation guarantee; nonuniform SMNP has `(3+3 log h)` analytical guarantee, with lower variance in the paper’s experiments; online variant has `(2+2 log h)` guarantee. These are not general agent-labor pricing recommendations and do not address hidden/strategic worker ability in the stated model.

**Worked check.** For two workers and two tasks, enumerate qualification edges, permitted task prices, one-to-one allocation, and blocking pairs. Reject a candidate assignment if a worker and task both prefer their unmatched pair. Then calculate seller/platform margin separately from the paper’s task-market revenue; do not conflate buyer bill, worker payment, processor fees, inference cost, and contribution margin. Truthfulness cannot be asserted from a margin spreadsheet.

**Sources/access:** full AAAI PDF; Myerson 1981 publisher abstract was only checked in earlier report and is single-object buyer-auction setting, not substitute for this labor model. **Add:** first state private types, market sides, allocation feasibility, IR, stability, budget and incentive property; only use theorem if assumptions match. Keep accounting identities distinct from incentive constraints and local pricing heuristics. **Diagrams:** mechanism pipeline from reports→allocation/payment→IR/truthfulness/stability checks; separate cash ledger (buyer/provider/worker/fees/risk) from strategic incentive model. **ASCII:** retain decision guide only after removing unsupported percentage “margin bands”. **Book idea:** a worked counterexample where strategic worker skill reporting invalidates task-side truthfulness; compare market-design chapter.

## 12. context-economics-for-agent-swarms

**Sources read:** active skill, capacity evidence schema/validator, ready/unknown fixtures, subscription-capacity ledger, and relevant protocol references. Liu et al., “Lost in the Middle: How Language Models Use Long Contexts,” TACL 2024, [arXiv record](https://arxiv.org/abs/2307.03172) (position experiments, full HTML accessed at unversioned URL; pin arXiv revision during integration). Official current MCP changelog is version pinned at 2026-07-28. Anthropic’s “Effective context engineering” page is practitioner guidance, not a controlled general result.

**Mechanism/evidence.** Lost-in-the-Middle varies relevant-information position in selected multi-document QA and synthetic key-value retrieval tasks and observes position-dependent performance, often U-shaped. Some model/task combinations degrade when relevant information is in the middle; this does not show every model universally suffers or prove quadratic attention is the cause of all “context rot.” The local validator’s ready/unknown fixtures enforce that claimed provider capacity evidence must have a provenance/status; this is a local data contract, not proof of provider-side reservation or actual token availability.

**Worked evaluation.** Hold model/version, task, prompt content, context length and decoding settings constant; move the same evidence between beginning/middle/end across repeated instances, score against an external answer key, and report per-position results and uncertainty. Separately account for paid dollars, provider subscription/native rate capacity, task quota, context capacity, and evidence confidence; these are different ledgers. If provider capacity is `unknown`, do not label planned tokens as reserved/available.

**Sources/access:** arXiv/TACL paper metadata and body; exact arXiv version must be pinned because URL is currently unversioned. [MCP versioned changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) for stateless protocol distinction. **Add:** label paper results as task/model-specific and distinguish accounting identity from local policy or incentive; replace “tokens are the only way a human sees” because artifacts and UIs expose results. **Diagrams:** five distinct ledgers (cash, provider capacity, task quota, working context, evidence status); transcript→artifact pointer→summary/zoom-back→independent verifier. **ASCII:** remove n-squared causal claims and fixed thresholds unless clearly labeled local hypotheses with test plans. **Book idea:** experimentally test context position sensitivity under agent-budget constraints; distinguish from generic context-window advice.

## Cross-skill evaluation and conversion notes

For B05 evaluations, preserve four separate measures: (1) protocol conformance, (2) message/task lifecycle outcome, (3) independently checked artifact/effect, and (4) cost/latency. A state transition or framework termination condition is not an artifact validator. A repeated conversation with shared model/context is not independent evidence. On economic examples, include inputs and a hand-checkable calculation; distinguish identity (`margin = revenue − listed costs`) from behavioral mechanism claims (truthfulness, IR, stability).

The older B05 report lists ASCII decision trees in JADE, Jason, discovery, interchange, communicative acts, ontology, MetaGPT/AutoGen, pricing, and context material. Convert only diagrams whose predicates and terminal states are corrected first; preserve tables as tables. Two useful semantic diagram concepts are listed per skill above. ## Highest-priority fixes for Terra

1. FIPA performative/FP/RE semantics must not be stated as verified truth or completed effect; separate message, conversation state, principal authority, and effect evidence.

5. MetaGPT/AutoGen findings are scoped to original paper experiments; current platform APIs require version-pinned official docs. Control termination is not task success.
6. Local Harbor/context scripts and schemas are bounded internal artifacts; don't present them as deployed product evidence or general empirical laws.
