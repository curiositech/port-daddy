## Findings and proposed additions

### `stigmergic-diffusion-medium`
The body defines a graph trace field and gives an explicit-Euler step clamp, then describes the medium as replacing message buses. Its own NOT-for clause correctly says the field is lossy and cannot guarantee delivery; reconcile the contradiction. The stated `0.9/(rate*max_degree)` bound only follows for the particular unweighted combinatorial Laplacian and explicit update convention: document graph weights, degree/normalization, boundary behavior, update ordering, decay/diffusion units, and whether deposits are added before or after a tick. It is not evidence of stability for urgency, saturation, resolution damping, or asynchronous concurrent writes. Add a small two-node numerical trace and invariant tests (nonnegative field if intended, mass behavior absent decay, bounded values with decay); label convergence claims only if proven for the implemented operator.

Primary source opened: Hansen & Ghrist, “Opinion Dynamics on Discourse Sheaves,” SIAM Journal on Applied Mathematics 81(5), 2021 ([publisher page](https://epubs.siam.org/doi/10.1137/20M1341088); [preprint](https://arxiv.org/abs/2005.12798)). It develops sheaf-Laplacian models for local/global consistency, not this scalar pheromone algorithm; use it to motivate typed local constraints, not to claim validation of SOMA. **Worked case:** three code modules connected by dependency edges; two agents deposit urgency, a resolution trace is deposited after a tested fix, and a disconnected audit obligation remains invisible absent an edge. Explain that diffusion can prioritize attention but cannot certify completion or deliver a message. **Mermaid ideas:** (1) trace lifecycle: deposit → diffuse/decay → sense → resolution/expiry; (2) graph topology/edge boundary showing why disconnected nodes cannot receive influence. Existing ASCII inventory: none in SKILL.md; support files still need conversion audit. **Book candidate:** compare communication-as-message vs communication-as-field, explicitly labeling this as a design comparison rather than novelty.

### `swarm-invocation-designer`
The skill is a static invocation-contract designer, not a launcher. Preserve its strongest protocol: reservation before attempt, monotonic fencing, persisted dispatch intent, ambiguous transmission held, sealed gather membership, settlement before reuse, effects denied during replay. CloudEvents 1.0.2 provides a useful event identity convention (`source` plus `id` identifies an event; duplicates may recur), but it does not guarantee exactly-once transport or provide this workflow’s reservation semantics ([spec v1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)). Add an explicit mapping from each contract transition to durable event identity, idempotency key, attempt/generation, and evidence owner; distinguish duplicate event suppression from duplicate external effects. **Worked case:** dispatch request reaches a worker but acknowledgment is lost: record `AMBIGUOUS`, retain reservation, reconcile by idempotency key or terminate/fence, never issue an unqualified retry. **Mermaid ideas:** (1) sequence diagram for lost-ack reconciliation; (2) state machine for reservation/attempt/settlement including ambiguous hold. ASCII inventory: no candidates in SKILL.md. **Book candidate:** a careful treatment of “exactly once” as a protocol decomposition (intent, idempotent consume, effect receipt, reconciliation), not a transport guarantee.

### `van-der-aalst-2003-workflow-patterns`
The skill surveys control-flow patterns but makes broad empirical claims (“most systems fail,” “>10x workaround complexity,” “external code needed = wrong architecture”) without a named system sample or measurement protocol. Recast these as local evaluation prompts. The primary paper is van der Aalst et al., “Workflow Patterns,” Distributed and Parallel Databases 14, 2003 ([TU/e record](https://research.tue.nl/en/publications/workflow-patterns-2/); [paper PDF](https://pure.tue.nl/ws/files/2053121/613310.pdf)). It supplies a pattern taxonomy and expressiveness comparison; it does not establish those current-system prevalence or complexity thresholds. Add a conformance worksheet: pattern definition, observable trace, required cancellation/late-arrival behavior, supported / encoded / unsupported classification, version, and reproducible test. **Worked case:** a discriminator accepts the first successful candidate; a later completion must be recorded but cannot overwrite the winner or silently leak a reservation. Define cancellation region and whether late branches are drained or fenced. **Mermaid ideas:** (1) token-flow of AND-split/join versus OR-join; (2) discriminator race with winning and late completion. Bundled diagram files are referenced, but ASCII conversion status requires an independent support-file audit; SKILL.md itself has no ASCII diagram candidate. **Book candidate:** pattern conformance testing as a portable method, separating paper taxonomy from engine-specific behavior.

### `wang-et-al-2025-tdag`
The identifier’s year is inconsistent with its cited paper: arXiv 2402.10178 records “TDAG: A Multi-Agent Framework based on Dynamic Task Decomposition and Agent Generation,” Yaoxiang Wang, Zhiyong Wu, Junfeng Yao, Jinsong Su, submitted 2024-02-15 ([arXiv record](https://arxiv.org/abs/2402.10178)). I accessed the primary record/abstract, not the full paper tables; do not repeat inherited exact benchmark percentages until the paper and table definitions are checked. The paper abstract describes task-adaptive decomposition, generated subagents, and ItineraryBench for travel planning, but cannot support general superiority claims. Replace fixed rules such as “>5 dependencies means dynamic decomposition,” “>20 tools,” and “<40% completion” with decision variables and a measured pilot. **Worked case:** after a hotel-search result invalidates an assumed airport transfer, regenerate only downstream transport and itinerary subtasks, retain completed verified facts, and mark dependent outputs stale. **Mermaid ideas:** (1) initial plan → outcome observation → affected-descendant invalidation → replanning; (2) context/tool capability partition by generated subtask. ASCII candidates: 5 in body; convert conceptual trees to Mermaid and preserve literal code/output only when genuinely code/output. **Book candidate:** compare static decomposition and outcome-triggered replanning on dependency-sensitive tasks, with named benchmark and limits; novelty unassessed.

### `windags-architect`
The skill’s wide architecture blueprint contains unscoped numeric cutoffs and operational assertions (node-count tiers, retries, fixed confidence/cost thresholds, implementation topology). Treat them as illustrative design choices unless tied to a tested release/configuration. Clarify architecture proposal vs implemented runtime and distinguish plan DAG from execution topology and effect authority. Add an “executable gate” table: invariant, owning component, evidence required, fail-closed behavior, and test. Show how a runtime projection can narrow or block a planning edge instead of assuming execution mirrors the plan. **Worked case:** a plan has two independent source reviews, while runtime capacity admits one; the projection serializes them and documents the changed latency/independence property. **Mermaid ideas:** (1) planner → admission/projection → runtime → evaluator feedback with authority boundaries; (2) node state lifecycle including blocked, retry as new attempt, and replan. ASCII candidates: 7 in body; migrate architecture diagrams/decision trees, not literal configuration snippets. **Book candidate:** “planning graph is not runtime graph,” backed by explicit mappings and evidence boundaries.

### `skillful-subagent-creator`
The fixed “2–5 skills” guidance and canned sections should be hypotheses, not universal limits. Design a subagent from the task contract: one independently checkable deliverable, bounded input/context, tools/effects permitted, stop/escalation conditions, and required evidence. Add a worked authorization split: a researcher may read and cite but cannot edit; an implementer receives only approved files and must return validation evidence. Require reference and secret minimization, explicit handling of untrusted retrieved instructions, and no implied authority from assignment. **Mermaid ideas:** (1) task contract → capability grant → work → evidence/review; (2) role-to-tool/effect matrix showing separation of duties. ASCII candidates: 4; migrate conceptual trees. Evidence depth: body reviewed; no cited empirical source validates skill-count limits. **Book candidate:** subagent design as capability allocation and verification, with no claim that more roles automatically improve quality.

### `agent-context-partitioner`
The body’s context IR and authority-before-retrieval posture are useful; its scope should distinguish admissible partitioning from an optimal partition. Preserve obligations and omissions explicitly and ensure incompatible `spaceId` or disclosure scope cannot be repaired by a high semantic score. Add a completion invariant: every required obligation is assigned, deliberately blocked, or explicitly omitted with reason; evidence carries source, validity interval, and authority. **Worked case:** a semantically relevant private note is excluded by repo/disclosure policy before ranking; the partition reports a blocked evidence requirement rather than substituting a nearby public item. **Mermaid ideas:** (1) authority and disclosure filter before lexical/dense rank; (2) obligation-to-context partition with uncovered obligations flowing to BLOCKED. ASCII candidates: none in body. Source basis: current repo-level search policy in AGENTS.md is local policy, not external research; body and one reference inspected, not validator execution. **Book candidate:** context compilation as constrained set-cover with explicit unsatisfied obligations; any optimization guarantee needs a defined objective and solver proof.

### `agent-resurrection-and-body-continuity`
The skill usefully separates durable agent identity from ephemeral body/generation and treats ambiguous side effects as quarantine. Extend its lifecycle with an explicit external-effect ledger and recovery evidence: a new generation can inherit facts and pending obligations, but cannot infer that an old effect did or did not occur. Require compare-and-swap generation fencing at every mutation sink; show which sinks cannot enforce fencing and therefore need human reconciliation. **Worked case:** an old worker’s payment call timed out; the replacement inherits the request ID and unresolved status, checks provider receipt, and does not reissue until reconciled. **Mermaid ideas:** (1) identity → generation → body lifecycle with fenced write; (2) effect-intent/receipt/unknown reconciliation state machine. ASCII candidates: none in body. Evidence limit: design procedure reviewed, no implementation or crash-recovery test run. **Book candidate:** identity continuity vs process continuity; compare recovery semantics across stateful and stateless workers.

### `always-on-agent-inputs`
The body proposes continuous ambient inputs and fixed retrieval/urgency policies. Avoid making capture the default: distinguish explicit user-provided context, authorized source subscriptions, and passive sensors; retain source, consent, expiry, visibility, and deletion controls. Retrieval rank is not permission. Add a freshness/conflict step so an old preference cannot silently override a current instruction; store only task-relevant events under a declared retention policy. **Worked case:** calendar shows an event conflicting with a current user deadline; the system reports the conflict and asks which source governs rather than silently reprioritizing. **Mermaid ideas:** (1) source authorization → minimization → temporal store → task-scoped retrieval; (2) conflict resolution among current directive, stale memory, and ambient observation. ASCII candidates: 4; convert decision trees while retaining actual schema/examples as code. Evidence depth: body reviewed; fixed weights and token budgets have no verified empirical basis in the skill. **Book candidate:** ambient context as a consented, temporal evidence stream, with privacy and correction path.

### `episodic-memory-algorithms`
The body gives concrete ANN/forgetting parameters, but threshold/capacity defaults need task-specific recall, latency, memory, and update benchmarks. Malkov & Yashunin’s HNSW paper describes a hierarchical navigable small-world graph for approximate nearest-neighbor search ([arXiv:1603.09320](https://arxiv.org/abs/1603.09320)); it supports the algorithm family, not the skill’s universal parameter cutoffs or factual correctness of retrieved memories. Add a workload matrix comparing exact search, HNSW, and any compressed index under recall@k, latency percentiles, memory, insert/update, and deletion requirements. Keep semantic similarity separate from temporal validity and truth. **Worked case:** ask “what did we believe as of March?”; filter by valid-time interval, retrieve candidates, surface superseded status and provenance, then answer with the historical source. **Mermaid ideas:** (1) memory encode/index/retrieve/validate/supersede/forget; (2) recall-vs-latency-vs-memory benchmark loop. ASCII candidates: 5; convert conceptual workflows, leave pseudocode literal. **Book candidate:** temporal episodic retrieval and approximate indexing under deletion/freshness constraints; no novelty asserted.

### `trust-typed-context-compiler`
The skill proposes a typed ContextIR compiler; keep its structural guarantees separate from source truth, authorization, and runtime admission. W3C PROV-O provides vocabulary for entities, activities, agents, and derivation ([W3C Recommendation](https://www.w3.org/TR/prov-o/)); it can inform provenance fields but does not authenticate the agent or make claims true. Add provenance IDs, temporal validity, authority decision, transformation lineage, and explicit translation outcomes (`EXACT`, `NARROWED`, `OMITTED`, `BLOCKED`) to compilation output. **Worked case:** a historic preference is included as background with its date and source, but fails the current-directive type check and cannot authorize a destructive tool action. **Mermaid ideas:** (1) untrusted sources → typed compile → proposal → independent admission/effect gate; (2) provenance derivation graph for a compiled context field. ASCII candidates: none in SKILL.md; one reference requires audit. **Book candidate:** typed context compilation as a provenance-preserving intermediate representation, with formal validation claims limited to schema invariants.
