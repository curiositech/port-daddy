# B02 — Agent architecture source research

**Coverage:** all 13 canonical targets in B02 of `catalog/batches.json`. Source inspection is a research pass, not an edit/validation pass. I read each `SKILL.md` in full and the refs relevant to the findings below; ref counts are current directory counts. ASCII counts below are candidate fenced text/diagram blocks only; actual conversion requires visual/semantic inspection. No skills were changed.

## Cross-cutting findings

- Mark empirical findings, source-defined semantics, local design proposals, and unvalidated operating thresholds separately. A primary source about a specific simulator, model, benchmark, or provider does not establish a generic default.
- For all stateful or always-on agents, diagram authority and lifecycle: principal/operator → agent identity → runtime instance → durable state → external side effect → independent receipt. Restart, retry, replay, cancellation, and identity continuity need distinct semantics.
- For BDI skills, make agent loop semantics and coordination protocol separate: BDI is a single-agent practical-reasoning architecture; it does not itself guarantee team agreement, authorization, safety, or distributed consistency.
- Distinguish stable conceptual references from current product docs. Framework/model/provider choice, legal requirements, service limits and prices need dated official references and a last-checked marker.

### 2. `agent-identity-continuity-reputation` — 1 ref; 1 candidate ASCII block
**Read/evidence:** Full skill and `failure-modes-and-defenses.md`. It usefully separates continuity and reputation, but philosophical persistence criteria, account identity, process identity, and authenticated authority are not interchangeable. Elo/BT/TrueSkill and bandits are domain models, not proof of competence; ratings inherit outcome-oracle, selection, collusion, and drift problems. Its Port Daddy section mentions AgentNode/ADR-0118 but self-asserted skills remain claims, not reputation. **Improve:** explicit identity chain (principal → stable ID → session/process → signed/observed actions), revocation/recovery, aliases and merges; reputation evidence schema with evaluator/provenance, cohort, uncertainty, time decay policy and appeals; never rank declared skills as earned. Worked example: a restarted worker retains a stable ID only after independent binding, while its old session lease expires. **Diagrams:** identity/alias/recovery state; evidence-to-reputation pipeline showing independent outcome verifier. **ASCII audit:** 1 candidate block in `SKILL.md`; inspect support ref before conversion. **Book lead:** reputation as a provenance-bound estimate with an outcome-oracle threat model; no novelty claim.
