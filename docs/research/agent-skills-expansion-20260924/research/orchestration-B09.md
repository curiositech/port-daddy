# B09 — Orchestration and execution research

**Coverage:** 11 new skills. `resolution-trace-damping` is intentionally skipped as already researched in `research/evaluation-evidence.md`; see cross-reference at end. Full-skill bodies reviewed; focused reference review where present. Candidate ASCII counts below cover main skill text only. No source edits.

## Evidence anchors and limits

- [JSON Schema 2020-12 Core](https://json-schema.org/draft/2020-12/json-schema-core) opened: structural contract reference; schema validation is not semantic truth or authorization.
- [W3C PROV-O](https://www.w3.org/TR/prov-o/) opened: provenance graph vocabulary; a provenance assertion can itself be false or incomplete.
- [OpenTelemetry trace semantic conventions](https://opentelemetry.io/docs/specs/semconv/) opened: telemetry naming conventions; trace data does not guarantee every side effect was observed.
- Many scores, caps, retry counts and quality cutoffs below are uncalibrated prescriptions. For permission subset checking, text/glob comparison alone cannot prove sandbox enforcement. For skill matching, lexical ranking may be useful as one retriever but must not be presented as semantic understanding or sole authority; enforce privacy and corpus scope before ranking.

## Per-skill review

### `dag-permission-validator` — 197 lines; 0 refs; 1 ASCII candidate
**Access/evidence:** full skill; no implementation/spec verified. The “child permission ≤ parent” lattice is sensible only after defining resource, principal, scope, deny precedence, inheritance and time; glob patterns and network domains do not form an obvious simple subset. Validation is not enforcement. **Extension:** canonicalize policy into explicit operations/resources/conditions; fail closed on unknown comparison; test generated requests at runtime against the actual enforcement point; include revocation and inherited-deny tests. **Trace:** parent may read `/repo`; child requests one exact file but broader network egress; deny only egress and record policy version. **Diagrams:** policy normalization/subset proof pipeline; request-to-enforcement decision sequence. **ASCII:** 1 candidate. **Book lead:** static permission validation versus runtime enforcement boundary; manuscript absence unknown.

### `dag-quality` — 137 lines; 1 Mermaid pipeline; 1 ASCII candidate
**Access/evidence:** full skill. It combines six separate functions, but its evaluator weights (including 0.50 human, which can make total exceed 1 before normalization), thresholds and plateau-at-two-iterations rules have no evidence. It also treats schema, confidence, hallucination and user satisfaction as commensurate scores. **Extension:** keep separate result dimensions: schema, task acceptance, claim evidence, uncertainty, provenance, safety and user preference; publish pass/fail/unknown with reasons. If an aggregate is required, specify decision loss and calibrate. **Trace:** valid JSON but one cited claim is unresolved; output can pass structure but remain held from factual downstream use. **Diagrams:** independent validation lanes and their evidence; iteration loop with bounded criteria and best-known artifact. **ASCII:** 1 candidate; preserve current Mermaid if accurate. **Book lead:** multidimensional quality status rather than one green score; manuscript absence unknown.

### `dag-replay-debugger` — 159 lines; 0 refs; 1 ASCII candidate
**Access/evidence:** full skill. It promises “full reasoning,” prompt and state inspection without privacy/retention/redaction boundaries; examples expose chain-of-thought-like internal state. Replay can reproduce external mutations unless sandboxed, and model/version changes are not deterministic replay. **Extension:** record minimal permitted inputs, versioned tool/model/config, random seed where applicable, effect receipts and redaction; replay in dry-run/isolated environment with side effects disabled or intercepted. Label replay as re-execution, not deterministic time travel. **Trace:** rerun a task with altered validator in mock network; compare canonical output hashes and event receipts while blocking production writes. **Diagrams:** evidence capture and redaction boundary; replay modes (deterministic reconstruction, re-execution, counterfactual) and side-effect gate. **ASCII:** 1 candidate. **Book lead:** debug reproducibility includes external state and privacy; manuscript absence unknown.

### `dag-result-aggregator` — 174 lines; 0 refs; 1 ASCII candidate
**Access/evidence:** full skill. Aggregation is not just merging; must preserve source, scope, timestamp, conflict and missingness. **Extension:** use schema-versioned collection with stable item IDs; deduplicate only with explicit identity rule; retain conflicting claims; distinguish absent, null, failed and not-applicable. Averages require comparable units/populations and cannot summarize incompatible evidence. **Trace:** two research workers return different dates because one uses publication and one event date; store both with field semantics rather than average/overwrite. **Diagrams:** aggregation pipeline with conflict lane; provenance-preserving result graph. **ASCII:** 1 candidate. **Book lead:** aggregation should conserve contradictions and provenance; manuscript absence unknown.

### `dag-runtime` — 174 lines; 0 refs; 4 ASCII candidates

### `dag-skills-matcher` — 146 lines; 0 refs; 4 ASCII candidates
