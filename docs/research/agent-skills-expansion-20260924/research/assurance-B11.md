## agentic-zero-trust-security
**Sources.** NIST SP 800-207 above gives resource-oriented ZTA, not agent-specific cryptographic guarantees. IETF RFC 9421, *HTTP Message Signatures*, opened full text: https://www.rfc-editor.org/rfc/rfc9421 ; §§1 and 7 explain component coverage/end-to-end message integrity limits. Signatures authenticate covered bytes under key assumptions; they do not prove truth, freshness unless correctly bound, or execution of an action. MCP security best practices, 2025-11-25 versioned page (body opened): https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices ; its token-passthrough section explicitly forbids accepting tokens not issued for the MCP server.
**Correction/extension.** Replace blanket “tamper-proof”/“prove agent did X” readings with a claim ladder: signed statement → verified signer/key → covered fields and freshness → host-observed event → independently checked effect. Worked example: sign method, target, body digest, audience, nonce, and expiry; verifier rejects stale nonce; still verify effect at target system. Delegation must narrow subject, resource, verbs, expiry, and audience; it cannot expand parent authority.
**Diagrams.** Signed-envelope coverage vs unproven semantics; capability attenuation tree and verifier decision path. ASCII inventory: check code blocks in decision trees and examples; convert actual branch logic.
**Book candidate.** Cryptographic attribution is not truth or effect evidence; prior art abundant, novelty pending.
