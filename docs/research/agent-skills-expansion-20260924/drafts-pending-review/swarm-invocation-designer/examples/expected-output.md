# Constructed three-reviewer contract worksheet

This is an illustrative design; no reviewers were launched and no latency was measured.

| Role | Bounded artifact | Review obligation |
|---|---|---|
| Correctness reviewer | Findings on declared files and revision | Reproducible failure evidence |
| Product reviewer | Findings on declared acceptance criteria | User-visible consequence and evidence limits |
| Security reviewer | Findings on declared trust boundaries | Operation/authority scope and counterexample |

Choose a capacity ceiling before admission. If only two slots are available, two attempts
may run while the third waits under a recorded runtime projection. The planning diagram's
three branches do not authorize three concurrent leases.

Seal all three gather members. If two return and security review is unknown, an `ALL`
gather cannot close successfully. If an explicitly accepted partial policy closes the
semantic result, retain the security attempt's reservation until termination or exact
operation reconciliation determines its disposition. A cancellation request alone does
not free the slot.

The output contains a static contract, validation report, unproved runtime obligations,
and references to constructed artifacts. The positive machine-readable example is
[valid-static-contract.json](valid-static-contract.json). Its fixture digest strings and
locators are labels, not real signatures or receipts. A runtime assessment would need
separate evidence of reservation consumption, target fencing, result acceptance,
provider accounting, and durable readback.
