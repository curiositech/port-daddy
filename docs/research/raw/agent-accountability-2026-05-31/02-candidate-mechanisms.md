# Candidate Mechanisms — underexploited + never-syllogized (29)

## 1. The persistent-goal commitment object (two-part: commitment condition + termination condition)

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Rao & Georgeff 1995, commitment-strategies-and-reconsideration.md: "A commitment usually has two parts to it: one is the condition that the agent is committed to maintain, called the commitment condition, and the second is the condition under which the agent gives up the commitment, called the termination condition." Plus the restriction: "an agent can choose what to do with its intentions. Thus, we restrict the commitment condition to intentions." (the agent has no control over beliefs/desires, so only intentions can bear commitment).
- **How it compels responsibility:** An LLM agent that says 'I'll fix the flaky test' has a do-and-forget goal that dies with the turn. Reified as a commitment OBJECT it becomes durable state: the maintain-condition (test must stay green) and the termination-condition (test green for 7 days OR test deleted OR file owner reassigns) outlive any single context window. The obligation is now something a future session — or a different agent — inherits and must discharge, not re-derive. Responsibility is OWNED because the object has a single owning actor and cannot be silently abandoned; abandonment requires firing a termination condition that is logged.
- **Formal core:** commitment := { object: φ (the intended state/action), commitment_condition: maintain(φ), termination_condition: T }. The two halves are kept distinct from beliefs/desires because only intentions are under the agent's control. φ is restricted (per the practical PRS system) to ground/checkable predicates, not arbitrary modal formulas, so maintenance checks are cheap pattern-matches rather than theorem proving.
- **Port Daddy mapping:** NEW PRIMITIVE: a `commitment` (durable SQLite row, idempotent CREATE TABLE IF NOT EXISTS per the module-factory pattern) bound 1:1 to an owning actor-soul. Columns: object (predicate text), owner_actor_id, maintain_predicate, plus the termination columns below. Composes with existing claim-tree (a claim is the now; a commitment is the ongoing obligation over that claim). `pd commit "<object>" --owner <actor> --success <cmd> --impossible <cmd>`.

## 2. Three explicit drop conditions (Cohen-Levesque persistent goal), encoded as the single/open-minded U-axioms

- **Novelty:** `underexploited`
- **Source:** Rao & Georgeff 1991, commitment-strategies-as-persistence-axioms.md. Single-minded: INTEND(inevitable φ) ⊃ inevitable(INTEND(inevitable φ) U (BEL(φ) ∨ ¬BEL(optional(φ)))) — drop on achieved OR believed-impossible. Open-minded: ...U (BEL(φ) ∨ ¬GOAL(optional(φ))) — drop on achieved OR no-longer-a-goal. Blind (AI₉a): ...U BEL(φ) — drop ONLY on believed-achieved. The bdi-agency-model operationalizes this trio as drop on 'goal_achieved', 'goal impossible → propagate failure', 'goal no longer matters → clean up', with success_conditions/goal_achieved_by_other_means checks.
- **How it compels responsibility:** These are the ONLY three legal exits. The agent cannot quietly let the obligation lapse: it persists until (a) success is observed, (b) it is proven impossible, or (c) motivation is formally withdrawn — each a logged, witnessed transition. This is the antidote to context-window evaporation: an LLM agent today drops an obligation implicitly by simply not mentioning it next turn; a commitment with U-axiom semantics can only terminate by firing one of three named predicates, so 'I forgot' becomes structurally impossible. Critically per bdi-agency-model: success can be recognized 'by other means' (the goal got satisfied by someone/something else), so the agent stops wasted work — and conversely cannot declare done without the success predicate passing.
- **Formal core:** termination_condition T is exactly one of: T_success = BEL(φ) [achieved, incl. achieved-by-other-means]; T_impossible = ¬BEL(optional(φ)) [no surviving future where φ holds]; T_motivation = ¬GOAL(optional(φ)) [open-minded only]. Strategy ∈ {blind: {T_success}, single-minded: {T_success, T_impossible}, open-minded: {T_success, T_impossible, T_motivation}}. Each is a runnable predicate, evaluated only on triggering events (not continuously).
- **Port Daddy mapping:** On the commitment row: success_check, impossible_check, motivation_check as executable predicates (shell exit-0, or a Haiku judge for fuzzy φ — never keyword lists). A commitment-monitor daemon job (like fleet agents) evaluates them on relevant events and on TTL ticks; firing any check transitions the row to done/abandoned/superseded with an immutable note recording WHICH condition fired. arbiter/guard refuses `pd done` while a single-minded commitment's success_check still fails — turning the existing 'guard check before commit' into 'guard check the obligation is actually discharged'.

## 3. Reconsideration policy: bold vs cautious + the meta-cost (reconsideration cost vs missed-opportunity cost)

- **Novelty:** `underexploited`
- **Source:** Rao & Georgeff 1995 cite Kinny & Georgeff 1991: intermediate (single-minded) strategies beat both rigidity and continuous re-planning — "This results in savings in computational effort and hence better overall performance." Bratman 1988 (filter-override-mechanisms.md) gives the six-situation taxonomy: cautious-pays (S1), cautious-doesn't-pay (S2b, S3 pure waste), bold-pays (S4), bold-doesn't-pay-but-would-have-helped (S4a), bold-doesn't-pay-but-checking-cost-more (S4b, "no criticism of a well-designed agent"). The override is "evaluated statistically over many decisions, not per-decision"; footnote 10: the agent should self-tune thresholds — raise if too much fruitless deliberation, lower if too many missed opportunities.
- **How it compels responsibility:** This stops the two pathologies that make LLM agents irresponsible: the Hamlet failure (re-deliberating every turn, never finishing — over-eager context re-reading) and the blind failure (grinding on an obsolete obligation). A commitment carries a reconsideration_policy so an agent is held to its plan unless a genuine override fires — it can't thrash, and it can't go stale. The policy makes 'when do I get to change my mind?' an auditable contract rather than a per-turn whim, so the OWNER stays accountable for the original obligation across reconsiderations.
- **Formal core:** reconsideration is event-triggered, not continuous: only 'potentially significant changes ... determined instantaneously at the granularity of primitive actions' post a reconsider event (Rao-Georgeff 1995). Bratman: compatibility_filter blocks incompatible options cheaply; filter_override(option) fires only when sensitivity threshold exceeded → option goes to deliberation WITH the conflicting commitment reweighed. Policy params: {strategy, override_thresholds (cost/risk/priority), self_tune: adjust thresholds from observed S2b/S3 (too cautious) vs S4a (too bold) rates}.
- **Port Daddy mapping:** reconsideration_policy field on the commitment + a feedback loop: the existing feedback/pheromone primitive logs each reconsideration outcome tagged S1/S2b/S3/S4/S4a/S4b; a periodic fleet agent reads the histogram and nudges override thresholds (raise on excess S2b/S3, lower on excess S4a) — Bratman's self-tuning footnote made real. Events flow through the existing ambient-broker/pub-sub; only flagged 'significant' events wake the commitment-monitor, mirroring the event-queue filter.

## 4. Intention as a FILTER on deliberation (commitment narrows the option space, not just records a choice)

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Bratman, Israel & Pollack 1988, plans-as-deliberation-constraints.md: plans serve a "dual role — they are outputs of deliberation but also inputs that constrain future deliberation." Three constraint functions: drive means-end reasoning, filter incompatible options ("need not consider options incompatible with her getting there by 4:00"), ground further reasoning. Consistency requirement: "it should be possible for her plans, taken together, to be executed successfully in a world in which her beliefs are true." Means-end coherence is a forcing function: "Means-end reasoning ... must occur" at the point a plan risks becoming incoherent.
- **How it compels responsibility:** Today an LLM agent re-evaluates the entire 180-skill option space every turn, which both wastes deliberation and lets the original obligation get crowded out by whatever the latest prompt emphasizes. A commitment as a deliberation filter means once an actor commits to φ, incompatible work is auto-rejected and the agent's attention is pinned to discharging φ — the obligation actively shapes what the agent is even allowed to consider next, so it can't drift. Means-end coherence gives a deadline-like forcing function: when φ is in danger of becoming unachievable (deadline, dependency), the system MUST surface it for action, not let it rot.
- **Formal core:** commitment exposes a compatibility predicate: an incoming option o is admissible iff consistent(o, {active commitments} ∪ beliefs). Incompatible o is filtered pre-deliberation (cheap) unless filter_override(o) fires. means_end_coherence: if believed-necessary-subplan(φ) is unfilled and slack→0, raise must-deliberate event. Resource accounting (time/budget/API) is part of the consistency check, per Bratman's cash/credit-card example.
- **Port Daddy mapping:** Extend the claim-tree/arbiter: active commitments register a compatibility guard so the arbiter REJECTS a new claim or sortie that conflicts with a live commitment's resource/temporal envelope (e.g. a 'complete in 5s' commitment blocks an 'analyze all 10k files' claim). roadmap-pop becomes commitment-aware: the next popped item is filtered to those compatible with standing commitments. A coherence-watchdog (fleet) fires must-act notes when a commitment's slack to its deadline collapses.

## 5. Selective commitment (sub-world pruning) so an owner is bound to the obligation but NOT to its side-effects

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Rao & Georgeff 1991, sub-world-compatibility-solves-side-effects.md: intention-worlds ⊑ goal-worlds ⊑ belief-worlds (CI1/CI2). "Commitment is selective pruning, not universal acceptance." The dentist case: INTEND(go_to_dentist) ∧ BEL(inevitable(dentist→pain)) ∧ ¬INTEND(pain) is satisfiable because the intention-world is a sub-tree that need not include the pain node. Proposition 2: GOAL(φ) ∧ BEL(inevitable(φ→ψ)) ∧ ¬GOAL(ψ) is satisfiable — non-closure under cross-modal implication.
- **How it compels responsibility:** Makes the scope of an obligation precise and honest. An agent that commits to 'optimize the query' is held to query-performance (the defining feature) but is NOT auto-charged with 'cause user delays' (a believed side-effect). This prevents two failures: scope-creep (an agent treating every consequence as its job and never finishing) and bad-faith reporting (claiming it 'wanted' a harmful side-effect, or hiding one). The owner is accountable for exactly φ's defining features and must DECLARE believed side-effects without owning them — so cost/benefit reweighing (drop φ if side-effects too costly) is clean and auditable.
- **Formal core:** commitment.object stores only defining features of φ (the pruned sub-world), separate from commitment.believed_side_effects (consequences the owner believes but does not intend). Realism still enforced: φ must be achievable in beliefs (intention-world is a genuine sub-world of belief-world), so you cannot commit to something believed impossible. Closure holds WITHIN a modality (INTEND φ ∧ INTEND(φ→ψ) ⊃ INTEND ψ) but not across (belief does not force intention).
- **Port Daddy mapping:** commitment row carries object (defining features) + declared side_effects (informational, drives cost accounting via the cost-accrual primitive). arbiter realism-check at creation: reject `pd commit` for an object that conflicts with current beliefs/claims (can't commit to the impossible). Side-effects surface in briefing/notes so other actors plan around them (Bratman coordination: stable announced commitments let peers plan) without the owner being scored as if it intended them.

## 6. Owner-bound persistence with joint-intention stability for handoff across context windows and agents

- **Novelty:** `underexploited`
- **Source:** bdi-agency-model _raw_response.md: intention drop cascades ("When a high-level goal is dropped, all supporting goals and plans are recognized as obsolete and terminated"); Tambe joint intentions: "In multi-agent systems, intentions can be communicated to others, who can then plan around them. This only works if intentions have some stability (are not instantly abandoned)" — premature abandonment of X cascades failures to a dependent agent B. Rao-Georgeff 1991 Theorem 3 (the practical result): a single-minded agent that only takes intentional actions and preserves beliefs across them will eventually believe φ achieved — durability + belief-coherence, NOT omniscience, yields discharge.
- **How it compels responsibility:** This is the direct fix for 'responsibility evaporates with the context window.' Because the commitment is durable SQLite state owned by an actor-soul (not a transcript), a fresh session resuming an identity INHERITS the live commitment and must discharge or legally terminate it — the obligation survives compaction, crashes, and agent swaps. Joint-intention stability means when actor A's commitment is depended on by B, A cannot silently drop it; abandonment fires a cascade that notifies B (salvage/inbox) so failures don't propagate invisibly. Theorem 3 gives the discharge guarantee: persist + act only intentionally + keep beliefs coherent ⇒ the obligation actually gets met.
- **Formal core:** commitment.owner = actor-soul id (survives session TTL). On session resume: load_active_commitments(owner) → agent must address each before new work. abandonment(commitment) ⇒ cascade_drop(dependents) + notify(dependents). dependents tracked as edges (B's commitment depends_on A's). Theorem-3 discharge condition: ∀ steps ∃ intended action ∧ belief_preserved_over(action) ⊃ inevitable(BEL(φ)).
- **Port Daddy mapping:** Bind commitment to actor-soul (the durable identity), not the ephemeral session — `pd begin` rehydrates open commitments and the agent is blocked from `pd done` until each is discharged or terminated (guard enforce). depends_on edges live in the claim-tree; abandoning a commitment fires the existing salvage/resurrection + inbox path to dependents. The commitment-monitor fleet agent is the 'always-on' discharge tracker — exactly the standing-policy daemon already required in this repo.

## 7. Obligation-with-deadline as a monitored norm instance (the ⟨M,A,E,C,S,R⟩ tuple)

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Tufiș & Ganascia, abstract-norm definition: n_a = ⟨M, A, E, C, S, R⟩ where M=modality (O/F/P), A=activation condition, E=expiration condition, C=content, S=sanction, R=reward (raw_response lines 577, 849-860)
- **How it compels responsibility:** An obligation is not a one-shot check — it is a STANDING record that persists in the NIB from the moment its activation A fires until its expiration/deadline E fires. The agent cannot do-and-forget: the instance keeps living in working memory, re-evaluated every belief-update cycle, until either the content C is achieved or E passes. That persistence is exactly what 'owning an ongoing obligation' means — the duty outlives the deliberation tick that created it.
- **Formal core:** Instantiation bridge rule: ∃ n_a=⟨M,A,E,C,S,R⟩ ∈ ANB ∧ eval(A,B)=true ∧ eval(E,B)=false → n_i=⟨M, ground(C,B), timestamp⟩ ∈ NIB (lines 876-879). De-instantiation: when eval(E,B)=true the instance is removed from NIB (reactor-cooling timeline T0→T3, lines 963-985). E doubles as the DEADLINE: a deadline obligation uses E = (task_complete ∨ deadline_passed) — see lines 1072-1077, ⟨O, time_remaining(task)<emergency_threshold, task_complete ∨ deadline_passed, escalate_priority(task)⟩.
- **Port Daddy mapping:** New primitive: an obligation/claim-instance table parallel to the existing prohibition-style Arbiter. Reuse the claim-tree + actor-soul: when an actor calls `pd begin`/claims a file, mint an obligation instance ⟨O, activation=claim_acquired, expiration=note_with_result_written ∨ session_TTL, content=durable_evidence_note, sanction=…⟩. The pheromone/feedback loop re-evaluates it each heartbeat. This is genuinely new — PD today regiments 'can't touch claimed file' but has no first-class 'must close out what you claimed' record.

## 8. Regimentation (prohibition / Arbiter) vs Enforcement (obligation / monitor+sanction) — the dividing line

- **Novelty:** `underexploited`
- **Source:** Tufiș & Ganascia: 'Regimentation approaches: Norms are hardcoded constraints → No recognition phase, immediate enforcement' (line 803); plan-norm consistency predicate consistent(p,NIB) ⇔ (effects(n_F)\effects(n_P)) ∩ effects(p)=∅ ∧ effects(n_O) ∩ neg_effects(p)=∅ (lines 224-227); SKILL.md 'not for environments that require literal non-violation regardless of consequences' (SKILL.md lines 88-90)
- **How it compels responsibility:** The consistency predicate shows WHY obligations cannot be regimented the way prohibitions can. A prohibition F is enforced by a static state filter — never reach a forbidden state — which is exactly what PD's Arbiter does (reject the conflicting claim, block the lock). But an obligation O is checked against neg_effects(p): you violate it not by reaching a bad state but by reaching the *end of its window with the required effect absent*. There is no edge you can block at decision time; you can only watch and penalize after. So obligation = ownership precisely because it survives past the moment of permission.
- **Formal core:** Prohibition: violated when effects(p) ⊨ f for forbidden f → blockable pre-execution (regiment). Obligation: violated when eval(E,B)=true ∧ content C not in B → detectable only at/after expiration (enforce). Permission P carves exceptions: effects(n_F)\effects(n_P) — a permission literally subtracts from the forbidden set, mapping cleanly to PD's existing override/guard-bypass.
- **Port Daddy mapping:** arbiter (keep, for F: port collisions, double-claims, lock conflicts) PLUS a new monitor primitive for O. The guard already does pre-commit `pd guard check --staged` (regimentation of 'can't commit over someone's claim'). Add a post-condition monitor: a background fleet agent that scans live NIB-style obligation instances and fires when E passes with C unmet. Permission P maps to `pd guard install --mode advisory` / explicit override = exception carved out of the forbidden set.

## 9. Violation detection = expiration fires with content unsatisfied; sanction re-enters deliberation as a weighted negative desire

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Tufiș & Ganascia: S = 'Sanction (consequence of violating)', R = 'Reward (consequence of respecting)' (lines 859-860); 'Obligations (O): High-priority desires … Failure to satisfy incurs sanctions (from norm definition)' (lines 1853-1855); internalize_norm() weights content by modality, prohibition → desire(¬content) at HIGH_PRIORITY (lines 1871-1888); SKILL.md Hidden-Violation failure mode + 'Chosen violations are logged with explicit consequence comparisons' (SKILL.md 159-162, 198)
- **How it compels responsibility:** The sanction is not punishment-for-its-own-sake — it is the mechanism that makes the obligation *matter to deliberation on the next tick*. When O is violated, S is asserted into the belief-set as a consequence, and because norm content was internalized into the DESIRE-set (not beliefs, not intentions — lines 1786-1788), the unmet obligation and its sanction now compete in the worst-consequence ranking of every subsequent decision. The agent literally cannot deliberate cleanly while carrying an un-discharged, sanctioned duty — the debt is priced into all future plans. That is enforcement of responsibility, not a fire-and-forget flag.
- **Formal core:** Detection: at each cycle, ∀ n_i ∈ NIB with modality O: if eval(E_i,B)=true ∧ content(n_i) ∉ B → emit violation, assert S_i into B. Sanction enters deliberation via desire-level internalization: norm content added to D (not B/I) so it is ranked by the ≻c (worse-than) consequence relation: φ ≻c φ′ iff a consequence of φ is worse than every consequence of φ′ (lines 47-51). Reward R symmetric on respecting.
- **Port Daddy mapping:** feedback + actor-soul + pheromone. A violation deposits a negative pheromone / reputation decrement on the actor-soul (sanction S), and a positive one on clean discharge (reward R). The existing immutable-notes ledger is the audit trail the SKILL.md demands ('violations logged with explicit consequence comparisons'). New: a `pd obligations` view showing live, met, and violated duties per actor — surfacing the Hidden-Violation failure mode the paper warns against (post-hoc explanations that omit the dropped norm).

## 10. Recognition vs Internalization split (ANB vs NIB) — advisory awareness vs owned commitment

- **Novelty:** `underexploited`
- **Source:** Tufiș & Ganascia: ANB = recognized norms 'in force in environment', NIB = adopted/active; 'At this point the agent is simply storing an abstract norm which it detected to be in-force in its environment; it has not yet adhered to it!' (lines 521-533); ANB serves as the record of norms 'the agent knew about but chose not to follow' for post-hoc explanation (lines 550-553)
- **How it compels responsibility:** Two-tier representation makes the difference between 'I was told' and 'I accepted' explicit and auditable. PD claims today are described as 'advisory — they announce intent, not enforce locks' (server instructions) — that is exactly the ANB level. To compel responsibility you need the NIB level: a separate, timestamped record that the agent INTERNALIZED the duty. The split is what lets you later prove an agent recognized an obligation (it was broadcast to its ANB) but never adopted it — turning silent non-compliance into a detectable, attributable event rather than plausible deniability.
- **Formal core:** Two stores: ANB holds ⟨M,A,E,C,S,R⟩ abstract; NIB holds ground(C,B) instances post consistency-check. Transition gated by consistency predicate + (on conflict) worst-consequence resolution. Internalization writes content into Desire-set D, NOT beliefs/intentions, so it enters normal BDI deliberation rather than forcing immediate action (lines 1786-1838).
- **Port Daddy mapping:** claim-tree + ambient-broker. The broker already broadcasts norms/notes into an actor's awareness (= writing to its ANB). Add an explicit acceptance step: an actor must `pd obligation accept <id>` (NIB internalization) before the obligation counts as owned — and refusing-to-accept is itself logged. Cleanly extends today's advisory claims into accountable commitments without breaking the advisory default.

## 11. Activation/expiration grounding against live beliefs — duties that arm and disarm with world state

- **Novelty:** `underexploited`
- **Source:** Tufiș & Ganascia, norm-instantiation-through-belief-grounding: conjunctive/disjunctive/quantified/threshold activation conditions (lines 989-1027); GDPR example ⟨O, contains_PII(dataset)∧jurisdiction=EU, processing_complete, apply_GDPR_protections⟩ (lines 1035-1051); resource-constraint norm ⟨F, memory_usage>0.9·total, memory_usage≤0.8·total, allocate_large_buffer⟩ (lines 1081-1087)
- **How it compels responsibility:** Obligations are not always-on nags — they self-arm when their activation condition becomes true in the agent's beliefs and self-expire when satisfied, so the agent owns a duty exactly and only while it is relevant. This prevents both over-adoption deadlock (SKILL.md failure mode 1) and obligation-fatigue. The duty tracks reality: claim a file and the obligation to release/document arms; the moment the work is durably noted, it disarms. Ownership is scoped to the live condition, which is what makes continuous responsibility tractable rather than paralyzing.
- **Formal core:** Per cycle: _should_instantiate(n) ⇔ eval(A,B)=true ∧ eval(E,B)=false; _should_expire(n_i) ⇔ eval(ground(E, bindings(n_i)), B)=true. Multiple groundings of one abstract norm produce multiple instances (latex/radiation allergy example, lines 945-952). Closed-world (undefined=false) vs open-world handling of missing predicates is the documented failure point (lines 1141-1144).
- **Port Daddy mapping:** feedback + roadmap-pop. PD's roadmap phases and session-TTL are belief predicates: activation = phase entered / file claimed / session live; expiration = phase done / note written / TTL elapsed. Wire obligation instances to these existing signals so 'must write result note' arms on claim and disarms on note — reusing the heartbeat/TTL machinery rather than adding a polling layer.

## 12. Intention-as-commitment that bounds deliberation — why a held obligation stops reconsideration

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Jenkins & Jarvis, intention-as-commitment-bounds-deliberation: 'intentions are commitments to act towards the fulfilment of selected desires' and 'the commitment implicit in an agent's intention to act limits the amount of practical reasoning that agent has to perform'; failure modes Over-commitment (paralysis), Under-commitment ('Butterfly Syndrome'), Inconsistent Commitments (lines 42, 89-101); intention handoffs require commitment transfer (lines 116-117)
- **How it compels responsibility:** This is the missing 'why responsibility sticks' piece: once an obligation's content is committed as an intention, the agent deliberately STOPS reconsidering whether to do it — the commitment creates a computational boundary that protects the duty from being re-litigated away on every new signal (Under-commitment / Butterfly Syndrome is the failure where an agent keeps abandoning duties for shinier ones). Responsibility = a commitment that survives distraction. Crucially, delegation is 'commitment transfer': handing a task to a sub-agent must move the obligation+sanction, not just the work, so accountability is never dropped in the gap.
- **Formal core:** Intention = committed desire that (a) bounds future practical reasoning over its scope, (b) must pass intention-consistency (no conflict with existing commitments), (c) propagates as a temporal/resource constraint to sub-intentions. Handoff = explicit commitment transfer: receiving agent must adopt the intention with its constraints. Maps onto the consequence-ranking: only the subset selected by worst-consequence comparison becomes an intention; the rest stay desires.
- **Port Daddy mapping:** actor-soul + fleet + claim-tree. Delegation via `pd spawn`/`pd sortie` must carry the obligation instance to the child actor-soul (commitment transfer) — today work is handed off but the duty-to-close-out is not formally transferred. The bounded-deliberation property argues for letting an actor mark a duty 'committed' so the orchestrator won't reassign or interrupt it mid-discharge except via explicit revision — exactly the Over- vs Under-commitment balance the paper formalizes.

## 13. Bonded Award Contract (announce -> bid -> award becomes a posted collateral)

- **Novelty:** `underexploited`
- **Source:** Smith 1980 Contract Net (task-announcement / bid / award / report message types; mutual contractor-manager obligation) + mechanism-design-for-agent-labor escrow lifecycle (BOND POSTING -> EXECUTION -> SETTLEMENT, four terminal states)
- **How it compels responsibility:** Today `roadmap pop atomic-claim` is a do-and-forget award: the agent takes the item and nothing of theirs is at risk if it dies, ghosts, or sabotages. Wrapping the pop in a posted bond makes the award a genuine Contract Net contract — the agent has skin locked in escrow that only returns on verified completion. The agent now OWNS the item because abandoning it costs them collateral; the obligation persists from award through settlement, not just at the instant of claim.
- **Formal core:** On `pop`, agent posts bond B = base_rate * complexity_score(scope: read=1x|write=3x|critical-auth/config/migration=10x|full=25x) * duration_multiplier * reputation_discount(agent). Escrow records {agent_id, item_id, B, deadline, acceptance_criteria(immutable manifest)}. Settlement: SUCCESS -> 100% return + reputation++; PARTIAL (completion_fraction = met_criteria/total) >0.5 -> fraction*B returned, remainder funds salvage successor; SABOTAGE/zero-progress -> B liquidated to reconstruction fund; DISPUTE -> arbitration hold. IC condition: B > max_gain_from_sabotage AND B > P(fail|incapable)*opportunity_cost.
- **Port Daddy mapping:** Extend claim-tree + roadmap-pop: `pd roadmap pop --bond` posts a Float Plan escrow keyed to the atomic-claim; arbiter holds it; feedback/salvage already exists as the PARTIAL settlement path (work preserved, successor funded). New primitive: an escrow ledger table {agent, claim, bond, deadline, manifest_hash, state}.

## 14. Negotiability-Indexed Commitments (a claim is breakable only with notification, ranked by how much it hurts dependents)

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** Decker-Lesser GPGP: C(Do(T,q)) vs C(DL(T,q,tdl)); negotiability index high/medium/low; conflict resolution by choosing schedule with largest positive utility change; 'if commitment made to other agents, the other agents are also informed of the change'
- **How it compels responsibility:** An atomic-claim is currently binary (held/released) with no semantics about how much other agents depend on it. GPGP makes the claim a TYPED commitment carrying a negotiability index and an estimated utility that RISES as other agents come to depend on it. The agent cannot silently drop it: breaking requires (a) computing the utility change, (b) being allowed only if positive after counting dependents' loss, and (c) notifying every downstream agent. Responsibility becomes ongoing because the cost of walking away is dynamically repriced upward by everyone who built on your commitment.
- **Formal core:** Each claim carries type {Do | Deadline(tdl)} + negotiability {high,medium,low} + Uest. Local scheduler exposes Violated(S), Alt(C,S) (returns later-deadline alternative or NIL), Uest(E,S,NLC). Substrate computes Su (max utility) and Sc (max utility violating no commitment); if they differ, break commitments only by 'largest positive change in utility', breaking high-negotiability before low. Hard relationship (enables M1,M2) -> low negotiability deadline commitment; soft (facilitates) -> high negotiability. Termination requires: idle AND no expected communications AND no outstanding commitments — so an agent literally cannot declare itself done while owing a claim.
- **Port Daddy mapping:** Upgrade advisory file/symbol claims (claim-tree) to carry negotiability + Uest fields; arbiter becomes the GPGP substrate selecting Su vs Sc; pheromone/feedback propagates Uest upward as dependents attach. The 3-condition termination gate becomes a `pd done` precondition: refuse `done` if outstanding non-local commitments exist.

## 15. Cheap-Fast Arbiter as Conflict Resolution + Daemon-as-Correlating-Device

- **Novelty:** `underexploited`
- **Source:** Ostrom Principle 6 (disputes resolved quickly/cheaply/locally; daemon as algorithmic arbiter; synchronous resolution; never require human for every conflict) + game-theoretic correlated equilibrium (daemon sends private recommendations; weighted coin on contested resource sends 'claim' to winner / 'wait' to loser; obedience constraint; strictly better than Nash, drives price-of-anarchy toward 1)
- **How it compels responsibility:** When two agents want the same item, leaving it to a race (first-come-wins or both-claim) produces the worst Nash outcomes — popular files thrashed, unglamorous files orphaned (the bystander/race-to-bottom equilibrium). A daemon that issues a binding recommendation makes each agent's responsibility unambiguous and self-enforcing: the loser OWNS the obligation to wait because deviating yields a conflict penalty worse than waiting, and the winner OWNS the item under bond. The correlation signal converts a contested free-for-all into individually-rational ownership without full enforcement (which would deadlock on crash).
- **Formal core:** Daemon observes full conflict graph {active claims, identities}; on contention over item I, draws from a priority/history-weighted distribution and sends private recommendation r_a in {claim, wait} per agent via pub/sub. Obedience constraint: for each agent and each r it may receive, E[payoff | follow r] >= E[payoff | any deviation]. Welfare guarantee: a correlated equilibrium exists that weakly Pareto-dominates some Nash equilibrium (so daemon recommendation never makes it worse). PoA bound in congestion/claim games <= 5/2 for linear latency; correlation + reputation penalties drive it toward 1. Resolution must be synchronous (within-request) or async-minutes, never human-hours.
- **Port Daddy mapping:** PD's existing arbiter + deterministic-port hashing + advisory claim conflict reporting IS the cheap-fast arbiter for Principle 6. The upgrade: when claims contend, arbiter emits a private recommendation over the ambient-broker/pheromone channel rather than first-come-wins, implementing the correlated equilibrium. roadmap-pop priority becomes the weighting on the coin.

## 16. Nested Governance Scopes (project commons within system commons; local rules refine, never contradict, global rules)

- **Novelty:** `underexploited`
- **Source:** Ostrom Principle 8 (nested enterprises; small commons nest in larger; inner scopes override outer defaults but only by refinement; avoid both the 'flat world' and the 'infinite hierarchy') + Decker-Lesser multi-level abstraction (task groups > tasks > methods; commit at high abstraction without fixing low-level method)
- **How it compels responsibility:** A flat governance scope means one agent's misbehavior in project X applies the same generic rules as a critical-infra project Y, so accountability is mispriced everywhere. Nesting lets each project OWN its own contract terms — its own bond prices for critical files, its own sanction thresholds, its own deadline norms — while inheriting the system's floor. An agent's obligation is then sized to the actual local commons it joined, which is what makes the responsibility feel real and proportional rather than boilerplate.
- **Formal core:** Scope hierarchy mirrors semantic identity project:stack:context. Rule resolution: check project config, fall back to stack config, fall back to system config; local rules may only REFINE (tighten or specialize) global rules, never contradict (composition predicate: local ⊑ global). Governable parameters per scope: bond pricing function, sanction tier thresholds, lock/claim TTL, deadline norms. Constraint: 2-3 levels suffice; over-nesting adds rule-resolution cost without governance benefit. Commitments expressed at the level of abstraction the agent controls (commit to task-group quality, not specific method).
- **Port Daddy mapping:** Identified GAP in PD's own Ostrom audit (6/8 satisfied; Principle 8 is a gap): semantic identity project:stack:context exists for NAMING but governance is flat. New primitive: a `/projects/:id/config` scope-config store + scope-aware resolver in the arbiter that layers project overrides on system defaults. Composes with the bonded-award and sanctions mechanisms by parameterizing them per scope.

## 20. MAPE-K managing loop with strict managed/managing separation

- **Novelty:** `nobody-has-syllogized-this`
- **Source:** self-adaptive-systems _raw_response.md — 'A self-adaptive system comprises two distinct parts: the first ... domain concerns; the second consists of a feedback loop ... responsible for the adaptation concerns – i.e. concerns about the domain concerns.' MAPE-K: Monitor (probes), Analyze (compare to goals), Plan (verify before enacting), Execute (via effectors at quiescence), Knowledge (shared runtime models). - **How it compels responsibility:** The decisive move: the agent's job is reframed as 'managing the domain concerns,' which is itself a perpetual concern. - **Formal core:** Managed tier exposes Probes (read state w/o side effects), Effectors (accept adaptation commands), Quiescence (apply changes only in no-activity states), Checkpoint/Restore. Managing tier = MAPE over Knowledge containing System model, Environment model, Quality model, Adaptation model as FIRST-CLASS executable artifacts (not logs). Plan verifies candidate adaptations against formal goals BEFORE Execute (DeltaIoT: configs pre-verified via Markov chains). Execute respects adaptation-performance meta-goal: t_quiesce + t_execute + t_validate <= 1 cycle.
- **Port Daddy mapping:** actor-soul as the managing loop (Monitor=ambient-broker+activity stream, Analyze=goal check, Plan=propose fix, Execute=spawn sortie/fleet agent at a safe quiescence point such as a clean working tree); Knowledge = PD notes/tuples/claim-tree as the shared runtime model. ## 21. Machine-readable adaptation goals with a four-class hierarchy (invariant / relaxable / optimization / meta)

- **Novelty:** `underexploited`
- **Source:** self-adaptive-systems _raw_response.md — 'Adaptation goals ... need to be specified in a format that can be used by the managing system at runtime.' Four classes: Invariant (hard, never relax, e.g. P[failure]<=0.14 — any violating composition rejected); Relaxable (soft over windows, e.g. packet loss <=10% in 12h); Optimization (min cost s.t. constraints); Meta-goals (awareness: 'detect packet loss within 2s'; adaptation: 'complete within 1 cycle').

- **Formal core:** Invariant: boolean predicate evaluated continuously, violation -> emergency/escalate. Relaxable: temporal/ordinal relaxation, escalate if still violated after window. Optimization: argmax utility U_c = Sigma w_i * p_i(x_i) over configs satisfying invariants (worked example selects MS2+AS2+DS3, U=73.8, despite highest cost because w_reliability=0.7). Meta/Awareness: monitor polling f>=0.5Hz, detection latency t_detect<=2s — if unmet, 'the managing system itself is failing.'
- **Port Daddy mapping:** A goals.yml / declarative fleet schema (extends pd-fleet.yml ADR-0019) read by the arbiter: invariant='CI green on main', relaxable='roadmap internally consistent within 1h', optimization='minimize open salvage-yards', meta='arbiter detects red within 60s'. Maps to feedback primitive + claim-tree (the formal goal is a typed obligation, not prose).

- **Novelty:** `underexploited`

Rules: each layer >=10x slower than the one below; observe a full MAPE cycle of the layer below before intervening; faster layers have action priority.
