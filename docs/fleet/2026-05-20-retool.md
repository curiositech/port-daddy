# Fleet Retool — 2026-05-20

> The old fleet shouted into pub/sub channels nobody read. The new
> fleet writes where Erich already lives: GitHub PR comments,
> issues, and draft PRs. Channels stay — they're how ships chain to
> other ships — but they're internal plumbing now, not the operator
> surface.

## The problem this fixes

Pre-2026-05-20, every ship in `pd-fleet.yml` published findings to
pub/sub channels: `port-daddy:fleet:qa`, `notify-findings`,
`tests:gap-found`, on and on. They were durable in SQLite. They had
SSE streams. They had a dashboard panel. And the operator never
read them.

That's not a tooling problem. That's a delivery-channel problem.
Findings live where the operator already lives, or they don't live.
Erich lives in GitHub PRs. The fleet now writes to GitHub PRs.

## What changed, in one paragraph

- Five new ships (`code-reviewer`, `red-team`, `test-author`,
  `tautology-sniffer`, `unspider`) trigger on `pull_request:*` events
  and write PR comments, issues, or draft PRs.
- Eight existing ships (`gardener`, `qa`, `test-hunter`,
  `documentarian`, `simplifier`, `cartographer`, `spark`, `spider`)
  had their backends pinned per the brief and their outputs rewired
  to GitHub primitives or operator-readable repo files where
  appropriate. `spark` and `spider` keep their internal-only output
  paths because they're research input for other ships, not for
  Erich.
- A single shared primitive (`lib/fleet/github-output.ts`) implements
  `postPRComment`, `openIssue`, `openDraftPR`, `closeIssue`. Ships
  call this; they do not reinvent the API client.
- Two zombie shell scripts (`fleet/qa-adversary.sh`,
  `fleet/test-gap-hunter.sh`) hardcoded `ollama` and didn't run.
  Deleted. Their behavior is captured in the new yml-based config.

## The shared primitive

```ts
// lib/fleet/github-output.ts
export interface GitHubOutput {
  postPRComment(prNumber, body, opts?): Promise<{ url, commentId?, edited }>;
  openIssue(title, body, labels, opts?): Promise<{ number, url, created }>;
  openDraftPR(branchName, title, body, baseBranch?): Promise<{ number, url }>;
  closeIssue(number, reason): Promise<void>;
}
```

Backed by `gh` CLI, inherits the operator's auth. When the Port
Daddy GitHub App lands, the helper flips to App credentials via the
`GH_TOKEN` env injected by the daemon. The interface does not
change.

Two sub-features matter:

1. **One-comment-per-ship-per-PR.** Every comment carries a marker
   line `<!-- pd-fleet:ship=<name> -->`. `postPRComment` with
   `editIfExists: true` (the default) finds the marker and edits in
   place. PRs stay scannable; ships don't carpet-bomb.

2. **Issue dedup by title.** `openIssue` with `dedupeByTitle: true`
   (default) searches open issues for an exact title match before
   filing. `unspider` running every Monday won't refile the same
   drift complaint.

## GitHub-event channel bridge

The fleet engine doesn't natively know about GitHub events. The
`pull_request:*` channels in `pd-fleet.yml` are marked
`external_producer: github-webhook-bridge`. Today they can be fired
manually:

```bash
pd pub pull_request:opened '{
  "prNumber": 117,
  "headRef": "fix/wire-shape-bug",
  "baseRef": "main",
  "title": "fix: SDK claim wire shape",
  "author": "erichowens",
  "changedFiles": ["lib/sdk.ts", "tests/unit/sdk.test.ts"]
}'
```

That's the test harness path (see the end-to-end test below). The
persistent path is a webhook receiver or a `gh` polling watcher,
which is sibling work in flight. Until that lands, ships fire when
the channels are manually published, or when a future
`scripts/gh-event-pump.sh` cron job pumps them.

## End-to-end test (PR-opened → ship fires → comment lands)

Prerequisite: daemon running, fleet up, `gh` authenticated, a test
PR open.

```bash
# 1. Pick an open PR
PR=117

# 2. Bring fleet up
pd fleet up

# 3. Manually fire the channel
pd pub pull_request:opened "{
  \"prNumber\": $PR,
  \"headRef\": \"test/fleet-retool-smoke\",
  \"baseRef\": \"main\",
  \"title\": \"smoke: fleet retool e2e\",
  \"changedFiles\": [\"lib/sdk.ts\"]
}"

# 4. Watch fleet events
curl -N http://localhost:9876/fleet/events

# 5. Verify the comment landed
gh pr view $PR --comments | grep "pd-fleet:ship=code-reviewer"
```

Expected timeline: `code-reviewer` spawns within ~5s of the
channel pub; comment lands within 30-90s depending on PR diff size.
`tautology-sniffer` and `red-team` may or may not fire depending
on whether the diff touches tests / adversarial surface.

Re-running step 3 (or running a real `git push` against the PR
branch and publishing `pull_request:synchronize`) edits the same
comment in place. Verify the comment count on the PR did NOT
increase.

## What needs operator review before promotion to main

1. **The `pull_request:*` channel bridge.** The yml declares the
   channels with `external_producer: github-webhook-bridge`, but
   that bridge isn't built. Three options for the operator:
   - Ship the webhook receiver as a separate concern
   - Wire a `gh` polling watcher in the daemon (every 30s)
   - Keep the manual-pub test path until the GitHub App lands

2. **`cartographer-state` branch.** The retool adds a write to a new
   orphan branch. The operator should confirm this is the desired
   pattern vs. (a) writing to a `cartographer/` dir on `main` with a
   bot commit, or (b) writing to a separate repo. Default is the
   orphan-branch pattern.

3. **Budget ceiling.** `budget_usd_per_day: 8.50` is up from `9.76`
   (counterintuitive — it's lower because two ships are paused and
   we tightened the active set). Operator may want to raise during
   the first week as we gather actual spend data, then ratchet down.

4. **`unspider` cadence.** Monday-only is the brief's default. If
   Erich finds it valuable, bump to twice-weekly (also on Thursdays).
   If it's noisy, drop to first-Monday-of-month.

## Rollback

If the new fleet misbehaves:

```bash
# Stop the new fleet
pd fleet down

# Revert the yml to the pre-retool version
git checkout HEAD~1 -- pd-fleet.yml

# Restore the deleted shell scripts (optional — they didn't work)
git checkout HEAD~1 -- fleet/qa-adversary.sh fleet/test-gap-hunter.sh

# Re-bring up
pd fleet up
```

The `lib/fleet/github-output.ts` module and the `fleet/ships/*.md`
contracts are additive — they hurt nothing if unused. Leave them in
place during rollback so the retool can be retried later without
re-writing.

## Acknowledged debt

- The GitHub-event bridge is not built. Today the `pull_request:*`
  channels are operator-manually-fired or wait on the sibling
  webhook task.
- `lib/fleet/github-output.ts` has no unit tests yet. The module
  shells out to `gh`; testing requires either a `gh` mock or
  integration tests against a sandbox repo. Either is fine; neither
  is done.
- `test-hunter` → `test-author` chain assumes the `coverage-gap`
  issue references the PR by number in the body. The bridge that
  cross-links them is implicit (search by title + PR number). A
  durable link via issue body would be tighter.
- The `cartographer-state` branch auto-commit pattern is
  unimplemented; cartographer needs a small shell helper for the
  orphan-branch write. Flagged in the operator-review section.
