The short answer

No single file makes an agent compliant.

There is one canonical operating persona, one public field manual, and one conformance-audit skill. They solve different problems. The daemon—not the prompt—decides what has actually been witnessed.

Architecture

One durable person, many temporary bodies.

Port Daddy separates operator intent, persona, authority, runtime body, and evidence. This is why an agent can survive a Claude process ending without pretending that Claude’s private session state is portable.

Measured conformance

Governance and evidence are separate axes.

A richly recorded agent may still be uncontrollable. A tightly governed body may still have weak evidence. C and T must be shown together, and numeric badges must remain withheld while doc, schema, UI, and probes disagree.

Operating contract

The compliant loop is a state machine.

Compliance is continuous, not a preamble. Every transition has a witness and a stop condition. If live truth disagrees with local plans, the agent re-anchors before proceeding.

01 / ResolveIdentity

Who am I? Which project, branch, worktree, session, roadmap item, and predecessor?

02 / ListenAttention

Read inbox, channels, live roster, notes, claims, and runtime health—bounded.

03 / DeclareScope note

Name exact surfaces, assumptions, validation, and why this slice exists.

04 / ReserveClaim

Take the smallest symbol/region/file surface. Lock only scarce non-mergeable state.

05 / ExecuteGuarded work

Edit only inside the claim; ports, subprocesses, secrets, and spend remain governed.

06 / WitnessEvidence

Tests, transcript, visual proof, source label, artifact hash, and known missing state.

07 / ReconcileRemote truth

Fetch, rebase, re-read peers, guard staged changes, and resolve review findings.

08 / PublishFinish line

PR body, roadmap link, every review response, green checks, merge state, live runtime.

09 / PreserveClose or hand off

Result note, release claims, successor capsule if needed, then durable completion.

Non-negotiable constraints

WorkspaceNo operator main; no purge-prone temp worktrees.

Parallel edits live in linked, recoverable worktrees with branch lineage.

ContextBound every read.

Buffer large output, page it, search it, or delegate interpretation. Never inhale the fleet.

CoordinationChat is not durable state.

Scope, decisions, blockers, and results land in notes, inboxes, tuples, or channels.

AuthoritySelf-report never grants capability.

Hooks, controls, transcript joins, liveness, and negative probes must be daemon-witnessed.

PrivacyNo raw transcript crossing.

Cross-family successors receive allowlisted, scanned, token-budgeted capsules—not copied secrets.

TruthCode, CI, merge, and live are different states.

Never collapse implementation, test, review, queue, merge, release, and runtime health.

OperatorRoutine repair belongs in the product.

The human uses FleetBar and pd-console. A required terminal ritual is a product gap.

SearchNo keyword-only classification.

Unstructured matching uses hybrid lexical + shared semantic embeddings, with explicit fallback.

N:N continuation

Continuity is lineage, not body possession.

Same-family resume may restore a harness-owned session after strict witness checks. Cross-family continuation creates a new successor from a sanitized brief. One source can fork into Codex and agy, but the branches remain distinct episodes.

Pattern ANative resume

Claude → Claude, Codex → Codex, agy → agy, Gemini → Gemini. Session identity survives only after bounded local evidence and workspace revalidation.

Pattern BParallel fork

Claude E0 → Codex E1 + agy E2. Both inherit the same sanitized predecessor brief, then diverge into separately accountable episodes.

Pattern CSequential relay

Claude E0 → Codex E1 → agy E2. Each boundary compacts again; later successors cite—not silently overwrite—earlier decisions and omissions.

OrphanedOnly an expired lease owned by an older daemon generation can be recovered.

CLI cockpit audit

Yes, the CLI has a roster. No, it is not yet Claude’s agents workspace.

pd agents --live currently lists live harness lanes with purpose, identity, worktree, branch, claims, session takeover, stream, and soft interrupt controls. The missing piece is a composed interactive cockpit over those primitives.

Claude Code today

Native child workspace

  • Parent/child agent list inside the active session.
  • Keyboard focus switch and per-agent activity state.
  • Task label, token/progress readout, queued turns.
  • One vendor owns process, transcript, and rendering.
Port Daddy today

Cross-harness control plane

  • pd agents --live: truthful roster across worktrees.
  • pd agent stream <id>: merged status, tube, transcript SSE.
  • pd agent interrupt <id>: cooperative typed steering message.
  • Session takeover, claims, branch, identity, and harness metadata.
What is missing

Interactive composition

  • No tree of parent → children → reviewer → keeper.
  • No full-screen keyboard UI joining roster + streams + controls.
  • Soft interrupt is advisory unless that runtime cooperates.
  • Progress/token/transcript fidelity varies by adapter.
