% Brief (tikz-diagram-craft). Register row ch1-07 [should].
% Reader question: same commit, same 5ms-later fault instant -- why does one
%   fault class survive and the other not?
% Claim: a daemon kill and a power loss are the same distance from the same
%   commit, but only the page cache survives the first; I1a (process-crash
%   durability) holds, I1b (power-loss durability) is not guaranteed.
% Evidence: whitepaper/single-writer-kernel.tex prop:durability (I1a Built,
%   I1b NotGuar), the "Alice crashes mid-write" dramatization: claim + note
%   committed at t0, daemon killed vs. power lost at t0+5ms.
% Must distinguish: the one shared commit point; that both faults are
%   equidistant in time; that the page cache, not the write itself, is what
%   differs between the two outcomes.
% Grammar: one trunk forking into two branches at the fault instant, the
%   two outcomes in the concept hues for ready/breach. Rejected: two
%   separate timelines side by side, which would hide that the fork point
%   -- not the write -- is the only thing that varies.
% Five-second test: "one line forks at t0+5ms into a solid branch that
%   survives and a dashed one that may vanish".

\caption{The same commit, the same 5\,ms-later fault instant, two outcomes.
A daemon kill and a power loss are equidistant from the commit at $t_0$; the
only thing that differs is whether the committed pages had left the
operating system's page cache. I1a (process-crash durability) is \Built{}
because the cache outlives the process; I1b (power-loss durability) is
\NotGuar{} because the normal synchronization level fsyncs only at the next
checkpoint. [internal]}
