# Exposition + Figure Review: The Legible Swarm

*Chapter I of VII, Port Daddy Coordination Papers.* `whitepaper/source/legible-swarm.tex`, 2253 lines, 11 TikZ figures, 6 tables, 55 bibliography entries. This is the outward-facing lead volume of the seven-chapter whitepaper series — the thing a skeptical reader meets before any formal paper — arguing that a coding-agent swarm is a Hobbesian state of nature, that the operator rationally consents to a *local* coordinating authority, and that the binding design constraint is *legibility* (a summary that is always a lens, never a replacement) under *read-poverty* (state accumulating faster than anyone can read it). It is unusually disciplined already: the harbor-exposition apparatus (Reader's Map, `\keyidea`/`\pitfall` boxes, scene vignettes, exercises with starred open problems, an honest built/designed/proposed appendix) is applied throughout, and the house LaTeX craft rules (one accent color, one typeface, booktabs tables, quiet callouts) are followed almost everywhere. The issues below are the real remainder in an already strong document, not manufactured nits — several sections and figures are called out as already excellent rather than padded with invented complaints.

## Part B — Existing figures/tables: clarity audit

1. **`fig:stack-map`** (`figures/legible-swarm-stack-map.tex`), opens the paper after the abstract.
   **Shows:** The L0–L3 layer stack (daemon kernel → coordination protocol → legibility & authority → economy/federation), which chapter owns which layer, and bidirectional "assumes"/"provides" arrows between layers.
   **Takeaway:** This chapter (I) owns L2 plus the L1 directory substrate; each layer depends on the one below and hands capability up.
   **Will they get it?** Yes. Cleveland–McGill: position/length carries the ordering (top-to-bottom = abstraction), the strongest channel, used correctly. The "assumes" (down) and "provides" (up) arrow pairs are offset by `xshift` so they never overlap the same line — a genuinely careful choice that avoids the "labels riding lines" tell. One color (cobalt for downward, teal for upward) each doing one job, not decorative. Caption states the finding, not just the parts.
   **Verdict:** Excellent — no fix needed. Worth using as the house reference example for future figures in the series.

2. **`fig:state-of-nature`** (`legible-swarm-state-of-nature.tex`), §1.
   **Shows:** Two side-by-side panels — five colliding agents with no referee (left) vs. the same five agents legibly spoked to a central daemon (right) — joined by a "covenant" arrow.
   **Takeaway:** Consent transforms collision into legible structure; the right-hand spokes are legibility, not chains.
   **Will they get it?** Mostly yes — the zigzag "collide" decoration vs. clean radial "legible" arrows is an intuitive before/after. One craft issue: `collide` uses `hhcobalt` for the danger/collision lines, while two other figures in this same document (`cascade`, `zoom-vs-potemkin`) use a *different*, off-palette color (`maydayred`, `HTML 8B0000`) for the equivalent "bad/danger" concept — see item 4 below, this is a cross-figure consistency defect, not a defect of this figure alone.
   **Verdict:** Good, minor cross-document consistency fix needed (see item 4).
   **Concrete fix:** None locally; fix at the palette level (item 4).

3. **`fig:zoom-vs-potemkin`** (`legible-swarm-zoom-vs-potemkin.tex`), §3.
   **Shows:** A legible digest tile with three zoom arrows to real artifacts (left) vs. a Potemkin tile ("all green") with a single dashed dead-end arrow to a red box (right).
   **Takeaway:** A digest is only honest if every claim in it reaches a verifiable artifact; the Potemkin tile's confidence is unearned.
   **Will they get it?** Yes, this is a strong, well-chosen contrast pair (Cleveland–McGill: the *presence vs. absence* of an arrow path is doing the real work, easy to read even greyscale since it's also encoded by solid-vs-dashed line style, not color alone — good defense-in-depth). **Cheap-tell check:** uses `maydayred` (`HTML 8B0000`), a color that is not defined anywhere in the main document's preamble palette block (`codebg, codeframe, hhsand, hhsanddeep, hhebony, hhink, hhcobalt, hhamber, hhteal, hhpaper, hhgray`) — it is locally `\providecolor`-defined inside two figure files only. This is exactly cheap tell #1 (off-palette color) and, combined with `hhteal` for the "good" path, also risks cheap tell #3 (status carried by hue: green/teal = good, red = bad) where the house rule is explicitly "status differs by weight/small-caps, never by hue" (stated in this very document's own preamble comment, lines 41–42).
   **Verdict:** Content is strong; palette discipline is broken.
   **Concrete fix:** Delete the `maydayred` `\providecolor` line; recolor the `dead` style to `hhink` (solid ink) with the dashed line style alone carrying "this path is broken" — the dashing plus the "(paraphrased away...)" label text is already sufficient signal without a second hue. Reserve `hhcobalt` as the one color that means "pay attention here" program-wide.

## Part D — Cross-reference notes

The pairing guess in the task brief is correct and substantive, not a false lead: **`whitepaper/research/tex/paper1.tex`, "The Price of a Summary: Information-Theoretic Limits of Agent Oversight,"** is the direct formal counterpart to this whitepaper's read-poverty/legibility chapters (§6–7), and the relationship is closer and more essential than the whitepaper currently signals.

- **Exact-formula match, uncredited.** `legible-swarm.tex`'s Theorem 6.1 (`thm:lowerbound`, "Legibility lower bound with a review budget," $\log_2\binom{N}{k}-\log_2\binom{m}{k}$) is *verbatim* paper1's Theorem 1 (abstract result (i), same $N,k,m$ notation). Paper1's version carries a pre-registered falsification test (0/16 violations across 16 configurations, including an adversarial oracle encoder) and a worked numeric consistency check at $N{=}1000$. The whitepaper states the bound as an unvalidated proof sketch and never cites paper1 for it — `grep`-confirmed: no `\cite` or textual pointer to "Price of a Summary" or paper1 exists anywhere in `legible-swarm.tex`. This is the single most actionable cross-reference fix: add a citation (and, ideally, the numeric example — Part A item 4) pointing the "skeptic checking honesty" reader at the paper where this exact claim has already been empirically stress-tested.

- **The "one summary can't serve two readers" idea is stated three times, unbudgeted.** Paper1 has one unifying result here — §sec:split, "One summary cannot serve two readers," formalized via **comonotonicity** of the two readers' preference orders, with a quantified super-additive joint floor ($\approx 2.13\times$, not $2\times$). The whitepaper restates this idea in three separate, un-unified places: Thm. `thm:split-ranker` (discovery-fit vs. attention-regret, §7.2), Thm. `thm:split-digest` (successor-agent vs. operator, §7.4), and implicitly Q3 of the four-questions decision procedure (§3.3). None of the three whitepaper instances uses the word "comonotone" or cites paper1's Theorem 2, and none carries paper1's quantified constant. Recommend: at minimum, a footnote or related-work sentence noting these are two instances of one deeper formal result, with a pointer to paper1's comonotonicity theorem and its $2.13\times$ figure — this would also strengthen the "Related work and prior art" section (§8), which currently discusses five external literatures but never mentions the paper's own formal sibling.

- **The regret-head derivation is a near-paraphrase of paper1's §sec:regret ("The regret head is derived, not designed"), also uncredited.** The dense, under-scaffolded paragraph flagged in Part A item 5 covers essentially the same Bayes-cost argument paper1 makes formally and by name. Citing paper1 here would both solve the "dropped with no context" problem (a reader can be pointed to the fully worked formal treatment) and correctly attribute the whitepaper's derivation as a popularization of an existing result rather than a fresh one.

- **The zoom-advantage / adaptive-search material is not yet in the whitepaper at all.** Paper1's §sec:frontier proves a "zoom theorem" (adaptive group-testing halves the flagged set in $2k\lceil\log_2(F/k)\rceil+4k$ opens) that is a natural, concrete companion to this whitepaper's "digest-with-zoom" chapter (§3) — it is literally the algorithm that makes "zoom" cheap at scale, and paper1 even uses the *same* twenty-questions analogy the harbor-exposition style guide recommends. This is optional (paper1's frontier result is more technical than this chapter needs), but a single forward-pointing sentence in §3 or §6 ("the zoom step itself has a provably efficient algorithm — see the companion paper's zoom theorem") would tie the two documents together and reward a reader who continues to the formal paper, which is exactly this whitepaper's stated job (Chapter I "read before the formal papers").

- **Terminology is otherwise consistent** — no drift found. Both documents use $N$/$k$/$m$ identically for the covering-set bound, "digest," "zoom," and "Potemkin"-adjacent framing (paper1 doesn't use "Potemkin" by name but the concept — a summary that terminates without reaching ground truth — matches exactly), and both use "stakes × irreversibility × anomaly" as the regret/surfacing key with identical variable names. This is good news: the two documents were clearly written in the same voice with a shared vocabulary; the gap is citation/attribution, not notation drift.
