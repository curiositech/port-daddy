- **`media.portdaddy.dev` now serves the repository's review evidence, and 108 files have left git for it.** The custom domain is attached to the `port-daddy-media` bucket and verified by fetching a real object over it — `HTTP 200`, `content-type: image/png`, `cache-control: public, max-age=31536000, immutable`, 555,965 bytes hashing to the sha256 in its own key — because a config that says it is attached is not evidence that it serves (for about three minutes after the attach it did not: `HTTP 403`, Cloudflare error 1014, while ownership was still pending). 655 objects / 325.8 MiB are mirrored, and `docs/pr-assets/` and `docs/pr-media/` are removed from git entirely: 108 files, 67.0 MiB, with the 5 prose files that cited them rewritten to `media.portdaddy.dev` URLs, and 5 further files refused by the mover because a `.tape` script and a Swift snapshot test read them. (Three more files matching the same rule reached `docs/pr-assets/pr-10178/` on `main` after this move ran; they stay in git as Phase 1 mirrored assets — see `media/r2-manifest.json`'s 583 — rather than being force-moved without the bytes first landing in the real bucket, which this environment has no credentials to do.) Removing a file from the tip does **not** shrink the repository — history keeps every blob — so what this reclaims is working-tree and shallow-checkout size, which `docs/adr/0142-r2-media-offload.md` §9.1 now says instead of the earlier "46% of the repository".
- **A new CI job proves those URLs work, and holds no credentials to do it.** `media/r2-manifest.json` is a projection of the git tree, so it goes silent about a file the moment that file leaves git — which is exactly when its URL starts mattering. `media/r2-offloaded.json` is the authority for files git no longer has, and `scripts/verify-r2-public-reads.mjs` fetches every URL in it anonymously over `media.portdaddy.dev`, comparing **bytes, not status**: each key is the sha256 of its object, so a 200 from the wrong object fails. It has no `env:` block at all, so it runs on fork PRs where the upload job deliberately cannot.
- **`scripts/sync-r2-media.mjs` gained a REST transport, because the S3 one is unreachable with the credential that exists.** An account-owned Cloudflare API token cannot be turned into an S3 access key id — it cannot call `/user/tokens/verify` and cannot list account tokens — so the signed-S3 path could not be addressed at all. The REST path is selected only when `CLOUDFLARE_API_TOKEN` is set *and* both S3 variables are unset, so a half-configured environment fails closed instead of silently downgrading. Measured costs, now recorded in ADR-0142 §11.1: `HEAD` is 405 and `Range` is ignored there (so the tool lists the bucket once rather than probing per key), and **`If-None-Match: *` is ignored**, so the append-only guarantee rests on the tool's own skip plus its pre-upload re-hash rather than on the store refusing the write.
