type: changed

- **Changelog entries are now one file per PR, so a merge can no longer silently delete one.** Every PR used to insert its bullet at the same line of `CHANGELOG.md` — `## [Unreleased]` is line 8, `### Added` is line 10, so every entry landed at line 11, and 29 of the last 200 commits wrote those same three lines. Two branches cut from the same base therefore conflicted on nearly every pair, and a resolver taking "ours" dropped the other PR's entry with **nothing failing**: no test reads the file, and the release gate only greps for a heading, not for content. Entries now go in `changelog.d/<pr>-<slug>.md` (format spec: `changelog.d/README.md`), so two branches never touch the same file and there is no conflict to mis-resolve. `scripts/assemble-changelog.mjs` splices the fragments into a dated section at release time and deletes them in the same bump commit; the release train calls it in place of the `perl -0pi` one-liner that stamped the heading textually, and with zero fragments its output is byte-identical to that line — the equivalence is asserted against the real `CHANGELOG.md` in `tests/unit/changelog-fragments.test.js`, alongside the literal `grep -Fq "## [$version] -"` that `release-train.yml` runs before it will tag. Two gates back it: `changelog-guard` in `ci.yml` (wired into `ci-gate`'s `needs:`) validates every fragment's shape on every PR and merge-queue head, and a fourth rule in `scripts/check-pr-requirements.mjs` fails a PR that changes a user-visible surface and adds no fragment, with `<!-- changelog-exempt: <reason> -->` as the audited escape hatch. The user-visible classifier is the release train's own `DAEMON_PATHSPEC` plus the visual surfaces, extracted to `scripts/lib/user-visible-surfaces.mjs` and held against the workflow by a drift test — deliberately not `ci.yml`'s `detect-changes`, which is a build-cost classifier that would have demanded a changelog entry for a lockfile bump. Not a fix, and named so nobody tries it: `merge=union` in `.gitattributes` interleaves and duplicates entries without ever conflicting, which is a quieter version of the same bug.
- **A PR-body exemption marker with an empty reason no longer exempts anything.** `hasMarker()` in `scripts/check-pr-requirements.mjs` tested `\S` against the raw HTML comment, and `\S` matched the `-` of the closing `-->` — so `<!-- visual-exempt: -->`, carrying no reason at all, silently disabled the visual-artifact gate, defeating exactly the "auditable, not blank" property the function's own comment claims. The reason is now matched against the comment's inner text with the delimiters stripped. The colon-less `<!-- visual-exempt -->` form was already correctly ignored and already had a test, which is how the colon-with-no-reason form survived; both are now pinned.
