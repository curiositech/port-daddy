type: fixed

- **A malformed parley URL no longer answers differently from a missing one.** The `/account/parleys/` router decoded path segments without guarding `decodeURIComponent`, so a bad percent-escape (`/account/parleys/%ZZ/dock`) threw `URIError` past the routing into the worker's global boundary and came back `500 INTERNAL_ERROR`, while an unroutable shape came back as a bare nine-byte `Not Found` with none of the surface's headers, and a genuinely missing parley came back as the full 404 page. Three different replies on a surface whose 404 exists to give exactly one, so that "no such parley" and "not yours" are indistinguishable and a session cannot be used to enumerate which harbors and parley ids exist. The decode is now guarded the way the sibling `/account/harbors/` branch already guarded its own, and every unservable parley path — undecodable, unroutable, unknown, or foreign — is served by the one exported `parleyNotFoundPage()` in `apps/relay/src/parleys-page.ts`: the same bytes, the same `no-store`, `noindex, nofollow` and script-free `default-src 'none'` CSP. `apps/relay/tests/parleys-page.test.ts` asserts the malformed path is a 404 whose body is byte-identical to the ghost parley's, and that both carry those headers.
