- **The relay decode guard now scans all of Relay's source tree and is reusable by other apps.** `scripts/check-relay-decode-guard.mjs` previously checked only `apps/relay/src/index.ts`; its file set is now a declared config (`AREAS`, a list-or-`**`-glob per area) that expands to every `.ts` file under `apps/relay/src/`, so a new file cannot silently sit outside the scan. Widening the scan surfaced one real violation — `apps/relay/src/coordination.ts` hand-rolled its own decode try/catch instead of calling the shared helper — now fixed to import `safeDecodeSegment` (moved to `handlers.ts` so every file can share it) rather than reimplement it; `apps/relay/src/index.ts`'s `/account/parleys/` branch is unified onto the same helper for the same reason. The forbidden-identifier/sanctioned-helper rule is per-area config rather than a hard-coded constant, so covering another app that decodes URL segments raw is a config entry, not new code; a survey of every app under `apps/` found no other app with this pattern today. `tests/unit/relay-decode-guard.test.js` adds a fail-closed regression test: renaming the sanctioned helper everywhere, consistently, with zero raw references left, still makes the guard exit non-zero rather than silently reporting clean.
