- **A real client for the Fleetbot GitHub App publisher.** `lib/fleetbot-publish-client.ts` opens pull requests, updates PR bodies, posts comments and replies to reviews as `port-daddy[bot]` through `POST /v1/fleetbot/publish`. It imports the same `lib/github-publisher-contract.ts` Relay imports rather than restating canonicalization, so the identity gate and the component holding the App key cannot disagree about the request bytes. It cannot mint its own authority — the daemon signs the Ed25519 capability — and it has no credential fallback: every refusal raises `FleetbotPublishError` carrying the preserved branch, base/head and operation so publication can stay pending instead of being re-attributed to a human. Claude Code attribution is applied by the request builder, not by callers. `scripts/fleetbot-publish.ts preflight` separates "the route is not deployed" from "admission refused", which otherwise look identical from the caller's side.
