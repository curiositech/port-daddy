type: fixed

- **Re-claiming an expired service now gets a fresh claim instead of the dead one.** `services.claim()` reused an existing row before checking `expires_at`, so a re-claim in the window between a service's deadline and the next cleanup tick returned "reusing existing service" with the past deadline intact, and that tick then deleted the service that had just been claimed again. An expired row is now dropped with its endpoints and the call proceeds as a new claim; a live row is still reused. The re-claim path also wrote the raw `expires` option into `expires_at`: `--expires 1m` stored the string `'1m'`, which SQLite sorts above every integer, so the service never expired, and a numeric duration stored a 1970 timestamp. Both paths now store `now` plus the parsed duration. `cleanup()` and `release --expired` also delete the expired services' endpoints, so a later claim of the same identity no longer inherits a lapsed claim's tunnel URL.
