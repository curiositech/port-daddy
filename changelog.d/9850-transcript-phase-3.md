- **`pd fleet transcript` brings every captured ship session to the terminal, backed by a hardened transcript API — pd-transcript.v1 Phase 3** (`docs/FLEET-SESSION-TRANSCRIPTS.md`). The relay gains `GET /fleet/runs/:id/transcripts.json` — the run's transcript LEDGER: every captured (ship, attempt) with turns, bytes, models, token totals, cost, and the incomplete flag, under exactly the run page's capability scheme and its indistinguishable-404 posture — and the `.jsonl` route gains `?after=<seq>` slicing so a machine consumer re-fetches only the tail it has not seen; both transcript routes now scope their D1 lookups with the promised `WHERE ship = ?` index variant instead of filtering rows in the Worker. On top of that API, `pd fleet transcript <run-id>` lists a run's captured sessions as a table and `pd fleet transcript <run-id> <ship>` prints one session as turn cards (`--attempt N`, `--raw` for verbatim JSONL, `--full` to open the folded system/user prompts, `--follow` to wait for a ship's completed flush — honestly framed, since capture flushes once at ship completion by design); the relay resolves via `--relay`/`PD_RELAY_URL`/the daemon's configured `relay_url`, and the credential is either an operator bearer (`--token`/`PD_RELAY_OPERATOR_TOKEN`) or a pasted `v1.<hmac>` run-page capability token, which rides `?t=` exactly as the web viewer sends it.
