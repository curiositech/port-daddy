- **The Swiss visual system moves from `/whitepaper` into the design system, so any page can use it.** Three primitives — `Slab` (a flat block of a part's ink carrying paper-coloured content), `PartNumeral` (the oversized chapter-numeral device), and `Eyebrow` (the small-caps label) — now live in `website-v2/src/components/swiss/`, and the role-layer tokens they read (`--part-machine`, `--part-operator`, `--part-person`, `--part-market`, each with a paper-coloured `-on` pair) join `tokens.roles.css`, named by what the part means rather than by the Book's LaTeX colour name. The page's own `PART_INK` lookup table — mapping `pdcobalt`/`pdteal`/`pdviolet`/`pdgold` to a token pair — is deleted rather than moved: `whitepaper/textbook.json` gains a `slug` field on every part (validated by `generate-mega-whitepaper.mjs` as a unique lowercase word), so a surface derives a part's ink mechanically as `var(--part-${slug})` with nothing left to drift. `/whitepaper` renders unchanged in both themes.
- **The part role layer is now checked end to end, so a typo cannot quietly unstyle a page.** `generate-mega-whitepaper.mjs` validates that each part's `webRoleAlias` is *shaped* like a CSS custom property, but nothing confirmed the token it names exists — so `--story-golld` would pass, generate `var(--story-golld)`, paint the Market part's slab with nothing at all, and leave every build green. `npm run test:part-roles` walks the whole indirection instead: every part slug has both halves of its `--part-*` pair, every pair names a part that still exists, every alias resolves to a token that is really defined and defined in *both* themes, and every literal `<Slab slug="…">` in the site names a real part. It runs in the `whitepaper-metadata` workflow on any change to the textbook data, the token files, or the Swiss primitives.
- **`/whitepaper` drops its five sub-menus and shows the findings instead.** Four of the five — Contents, The Spine, The Proofs, Read it — were the same eight chapters listed again under a different heading, and the fifth repeated the masthead's download button, so a reader who wanted the table of contents had to guess which tab it was. The rail is gone and the outline gets the whole panel: four parts, eight chapters, and under each chapter the concrete thing it settles (the 5.98-bit floor, δ\* ≈ 0.3425, the consistency radius of 1.2247, the ProVerif run that broke card v6). The "proves ch. N" tags go with it — a chapter is a chapter. Every part carries its own plate and every chapter its own opener plate, the same files the Book prints.
- **The site shows the Book's actual cover.** The home strip was still advertising the watercolour jacket a week after the Swiss edition became the central one, because nothing derived the site's copy from the Book. `website-v2/scripts/render-book-cover.mjs` renders page 1 of the committed PDF, `--check` fails when the two have drifted, and the strip itself is now a 52px thumbnail on one line instead of a 170px block of a home page that cannot spare it.
- **`/research`'s four panel heads were the same sentence four times.** Run through the humanize pipeline: the structural layer found nothing (the copy passes every measurable threshold — em-dash density, sentence-length variance, contractions), but the judge pass against the catalog found all four standfirsts built on one figure, `[clause] — [clause that reframes it and delivers a verdict]`, under headlines that were epigrams rather than statements ("Four moves, and the third one is the expensive one"; "Wired, or retired. The report is `$SP/humanize/site-report.html`; eight findings, all high or medium, every one with the rewrite that shipped.
- **A missing plate now fails the build instead of printing an empty box.** `/whitepaper` builds every plate `src` by template literal from `whitepaper/textbook.json` — `/whitepaper/plates/swiss/chapter-${record.prefix}.jpg` in `website-v2/src/pages/whitepaper/index.tsx`, and the matching `part-${part.numeral}.jpg` — and nothing confirmed those twelve files exist. A renamed or deleted plate raises nothing: the browser asks for it, gets a 404, paints an empty box, and every build stays green. The repository already had exactly this gate for the Book's side of the same indirection, so the site's half joins it rather than starting a second convention: `scripts/harbor-research/check_plate_provenance.py` gains a section (C) that reads the path *templates* out of the site source, substitutes every chapter prefix and part numeral from `whitepaper/textbook.json`, and fails naming the exact file when one is absent. A template that interpolates a field the script cannot map fails closed rather than being skipped, since silence is the defect being fixed. It runs where the Book's half already runs, in `.github/workflows/library-checks.yml`; six new cases in `tests/harbor-research/test_check_plate_provenance.py` cover each failure mode, and one pins that the committed site source really resolves all twelve plates so the check cannot pass vacuously.
- **The two checks this branch added are now mutation-tested, and one of them was passing a break it claimed to catch.** `website-v2/scripts/check-part-role-tokens.mjs` and `website-v2/scripts/render-book-cover.mjs` shipped with their correctness recorded only in a transcript, which is the same defect they exist to prevent: a mechanism whose reported success cannot be re-run. `website-v2/src/part-role-token-guard.test.ts` builds a copy of the real token tree in a temp directory, breaks exactly one thing, runs the real script against it, and asserts the message names the real problem — twelve breaks in all: a slug renamed without regenerating the CSS, an alias naming a token no file defines, an alias pointing at a source-layer token, an alias target missing from the dark block and from the light block, a missing `--part-<slug>-on`, a `Slab` literal slug that is not a part, a duplicate part slug, a hand-edited `tokens.roles.css` that disagrees with `whitepaper/textbook.json`, a deleted `webRoleAlias`, an alias given a hex colour, and a role token carrying a literal.
