- **The Fleetbot publisher's admission contract is now decided: an OIDC-registered workload identity plus a standing operator grant, replacing the `pdu_` account bearer.** ADR-0141 records that `FleetbotPublisherCapability.accountTokenHash` forces an operator account bearer into every `POST /v1/fleetbot/publish` request, that Relay spends the operator's own sealed GitHub OAuth grant in `authorizeExactRepository`, and that the bearer is custodied by `lib/account-store.ts` in the same OS account the agent runs as — while no daemon client of the route exists in the tree at all. It replaces `accountTokenHash` with a non-bearer `grantId`/`grantEpoch` reference into a durable `publisher_grants` record that is re-read per request, so revocation is one upstream edit instead of a credential rotation, and it binds the capability to the workload key, repository, operation, branch and session so a stolen capability cannot be replayed elsewhere. The named issuer is the GitHub Actions OIDC trust already registered in `apps/relay/migrations/2026-08-08-relay-baseline.sql` and verified by `apps/relay/src/oidc.ts`; the laptop-daemon workload class is recorded as an open question rather than invented. The same grant record carries the operator consent ladder, whose acceptance criterion is that `asks_per_episode` must fall — read-only repo access is asked once ever, and only spend above ceiling and irreversible acts remain per-episode asks. No runtime behaviour changes in this phase.
