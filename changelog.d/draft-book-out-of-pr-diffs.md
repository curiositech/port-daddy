- **The Book is no longer committed to every whitepaper PR, so whitepaper PRs stop conflicting with each other.** `coordination-papers-mega-volume.pdf` is collated from every chapter, so any chapter edit moved it — and with `main` on REBASE merges and linear history, replaying a ~9 MiB binary commit onto a base whose copy had also moved could not merge. Measured across the open cluster on 2026-09-14: 23 of 23 whitepaper PRs carried a diff on that PDF, 23 on `publication-digests.json` and 20 on `whitePapers.ts` (the latter two record only its size and page count), so landing any one of them conflicted the other 22. `whitepaper-build` still renders the Book on every run and still hands it to the cover-band check — an uncompilable Book fails exactly where it did before — but outside a deliberate refresh the artifact is restored before anything can stage it, which freezes its derived metadata with it. A new Book is published by dispatching `whitepaper-build` on a branch with `refresh_book=true`, which commits it there and opens one reviewable pull request instead of twenty-three racing ones. Chapter PDFs are untouched: they are chapter-scoped, and two PRs collide on one only by editing the same chapter.
