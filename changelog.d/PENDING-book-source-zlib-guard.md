- **`scripts/build-book-source.py build` now refuses to write a Book source archive or receipt from a Python whose zlib would not reproduce stock deflate bytes.** The receipt pins the archive's exact gzip bytes, and a zlib-ng Python (the system interpreters on one build machine report `zlib.ZLIB_RUNTIME_VERSION` `1.3.1.zlib-ng`) writes valid but different streams, so its receipt was silently wrong and failed later in CI and the Pages prebuild as merely "stale". Before writing anything, `build` compresses a fixed 48 KB tar-like canary through the archive's own `gzip_writer` and compares its SHA-256 with the stock-zlib result embedded in the script (identical under stock zlib 1.3, 1.3.1 and 1.3.2; different under zlib-ng 1.3.1). On a mismatch it exits 1 naming the interpreter, the zlib build and the fix: a Python linked against stock zlib, such as uv's managed CPython, or on macOS a python.org or uv build. `check` stays ungated, so a website build never fails for its interpreter alone, but a stale-receipt error now adds the same diagnosis when the running zlib is non-stock, and says so when every source hash matches and only the archive bytes differ. The receipt and download redirect are rebuilt with stock zlib for the changed script.
