- **Tool provenance is now answered separately from quality, because conflating them is the mistake the skill exists to avoid.** `python3 skills/make_copy_and_media_human/scripts/humanize_review.py page.html --provenance` reports which tool published a page and stops: no report, no severity. A fingerprint says what made the page, never who wrote it and never whether it is good — and Wix and Squarespace prove the point, since their AI flows seed the ordinary editor and produce markup identical to hand-built output. `skills/make_copy_and_media_human/references/tool-fingerprints.md` adds 21 items carrying that argument plus a greppable table generated from the script's own pattern list, so the two cannot drift. - **Dogfooding the new reference file found a real detector gap.** `definition-after-use` fired on writing that HAD defined its terms, because a term is often defined under a near form — "ARIA is a set of attributes, all beginning `aria-`" defines `aria-` — and the check only looked for the exact token. - **In-product UX writing is now covered, and it is the one lane where hard string matching is defensible.** `skills/make_copy_and_media_human/references/product-ux-writing.md` adds 35 items for the strings a logged-in user reads mid-task — errors, empty states, button labels, confirmations, notifications, field hints. Everywhere else in this skill a closed phrase list is a bad detector, but a product's string table is small, enumerable and extractable, and within it the phrase space is genuinely narrow: “Something went wrong” has no good use at all in a product that knows what went wrong. So `skills/make_copy_and_media_human/scripts/humanize_review.py` gains a UI-string pass that extracts candidate strings first — from i18n catalogs, JSX text and the render/error path — and runs 18 closed sets only over those, so it will not fire on an article quoting the same phrase. The mechanism the lane names: under uncertainty about what failed, the only clause that carries zero risk is the one about how sorry everyone is, so the copy is optimised for the writer's uncertainty rather than the reader's blockage — and the less the system knows about the failure, the warmer it gets. The headline entry is `collapsed-empty-states`, which is not a wording problem at all: three unrelated situations (never had data, filter matched nothing, fetch failed) produce the same zero count and collapse into one string, and the third is what makes users believe their data was deleted.
- **Typographic craft and design-system structure, under one governing idea.** `skills/make_copy_and_media_human/references/typographic-craft-and-tokens.md` adds 38 items covering leading, tracking, line breaking, numerals, type scale, weight, optical size, text colour and token architecture. They all express one finding: a generator emits CSS that is internally consistent and has no craft in it, because craft in typography is per-context judgement and a default is by construction context-free. So the tell is never a wrong value — it is one value where there should have been a function of context, and every check is the same computation: does this property vary with the thing it is supposed to vary with? 18 detectors back the decidable subset. Two cautions are built into them so the lane does not generate noise: read computed values rather than declaration counts (utility frameworks bundle a tightening line-height into their size scale, so a page with no explicit declaration is usually correct), and treat restraint as distinct from absence (a page declaring no font-weight at all is on defaults and is not the two-weights finding).
- **Building the lane surfaced four real bugs, three of them in code that already shipped.** The CSS `margin` shorthand was parsed wrongly: `margin: 2rem 0` is vertical-then-horizontal, so it sets top and bottom to the SAME value, and the first version read it as asymmetric while reading the correct `margin-block: 3rem 1rem` as symmetric — exactly backwards. A layout table carrying `role="presentation"` was being asked for header cells, which is the opposite of the advice for an email template. `definition-after-use` reported “never defined” on writing that defined the term in the very next clause, because a term of art is almost always code-formatted and the closing backtick sat between it and its definition; the em-dash appositive was missing from the pattern outright. And the single line-height check only matched unitless values, so the commonest generated form — a length — escaped it entirely.
