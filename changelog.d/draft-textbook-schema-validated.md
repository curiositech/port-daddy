- **`whitepaper/textbook.schema.json` is now actually run against the data, and it was wrong in two places.** The schema is what `"$schema"` at the top of `whitepaper/textbook.json` points at and what a reviewer is told the file conforms to, but nothing in the repo had ever fed one to the other — the tightening a reviewer asks for lands in a file no build reads, so `additionalProperties: false` sat there while an undeclared `result` string rode on all eight chapters, and `formerNumeral`'s `^[IVX]+$` forbade the empty string that `validateTextbook` in `scripts/generate-mega-whitepaper.mjs` deliberately accepts and that chapter 3 has carried since the Textbook Edition. Both were found by the first run of `scripts/check-textbook-schema.mjs` and both are fixed in the schema, not papered over in the data. The checker is dependency-free because the Library Checks job installs no npm packages, implements the draft-07 subset the schema uses, and refuses to run at all on a keyword it does not implement rather than skipping the constraint and reporting success. It also asserts what no draft-07 vocabulary can say — that `parts[].slug`, `parts[].id`, `chapters[].id`, `chapters[].number` and `chapters[].prefix` are each distinct — since `uniqueItems` compares whole items and is satisfied by two parts that share a slug while differing in their title, which is the failure that collapses `--part-<slug>` to one pair and silently repaints a part of the Book. `npm run check:textbook-schema` and `node --test scripts/check-textbook-schema.test.mjs` run in `.github/workflows/library-checks.yml`.
- **A part's role token can no longer alias a token that is not a colour.** `website-v2/scripts/check-part-role-tokens.mjs` asked whether an alias target was defined in *any* token file and in *both* themes, which `website-v2/src/styles/tokens.source.css` satisfies for free: it defines every name once, in a plain `:root`, so a source-layer token is trivially theme-complete. Point a part's `webRoleAlias` at `--radnika-opsz-body` and the slab's background becomes `var(--radnika-opsz-body)`, which is the unitless number `17` — an invalid background, dropped by CSS, slab paints nothing, every check green. Verified by mutation before the fix and after. `definitionsByTheme` now records which file defines each name in each theme, so the check names the layer as well as the theme, and a new sixth check reads `whitepaper/textbook.json`'s `webRoleAlias` directly instead of only the CSS generated from it — the source of record is validated on its own terms, and a hand-edit to `website-v2/src/styles/tokens.roles.css` that disagrees with the data is reported by the part-role check rather than only by `--check-shared` in a different workflow.
