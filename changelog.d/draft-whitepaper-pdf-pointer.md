type: changed

- **A whitepaper pull request no longer carries a regenerated 9.7 MB PDF, so the whitepaper PRs can rebase again.** `whitepaper-build.yml` committed a freshly rendered `coordination-papers-mega-volume.pdf` onto every same-repository PR head. The repository merges by rebase, git cannot three-way-merge a PDF, and every whitepaper PR regenerates the Book because every one of them touches a `.tex` the Book `\input{}`s — so the first such PR merged and every other one rebased into a binary conflict whose only resolution was another 9.7 MB blob for the next PR to collide with. PDF bytes are now written on one serialized release lane (`release/whitepapers`, or a manual run on it) and nowhere else; a pull request builds, runs the determinism, cover-band and figure gates exactly as before, and commits nothing. Measured on two synthetic whitepaper PRs off one base: before, each head carried a 9,740,646-byte blob that `git diff --numstat` reports as `-` `-` and `git merge-tree` reports as an unresolvable `CONFLICT (content)` in the PDF; after, each head changes two lines of JSON and the same merge conflicts inside `publication-digests.json` with ordinary conflict markers around the two `sha256` lines. `main`'s freshness gate still fails on a stale PDF and now names the lane that heals it.
- **Every published PDF's page count, byte size, digest and public URL now live on one record.** `website-v2/public/whitepaper/publication-digests.json` gains `r2Key` and `r2Url` on each entry, derived from that entry's own `sha256` by the new `scripts/lib/content-address.mjs` and compared field-by-field by the existing drift check. A page count in one file and a pointer in another are two mergeable records describing one binary: two parents, each internally consistent, merge into a child that takes the count from one and the pointer from the other, both hunks apply cleanly, and nothing notices — which is what the repository's "carry the derived metadata" repair commits have been repairing. Collocating them makes those parents conflict where they disagree. All nine URLs were fetched anonymously over `media.portdaddy.dev` and each body hashes to its own key.
- **A git-LFS pointer can no longer be published as though it were the media it names.** In a checkout where the smudge filter did not run — no `git lfs`, `GIT_LFS_SKIP_SMUDGE=1`, or a blob read with `git show <ref>:<path>`, which returns the pointer for an LFS-tracked path — a tracked PNG or PDF is present as roughly 131 bytes of text that is still listed by `git ls-files` and still has the right extension. Hashing it yields a record with a real digest and a plausible size addressing a text stub, and a regenerate-and-diff check passes because regeneration reproduces the same wrong hash. `assertNotLfsPointer` refuses before the hash and names the fix.
