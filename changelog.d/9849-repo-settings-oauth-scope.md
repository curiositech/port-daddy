type: fixed

- **`/account/repos` no longer locks a signed-in user out of every private repository, including their own.** The web login flow requested OAuth scope `read:user user:email` only — no `repo` — so `GET /repos/:owner/:repo` came back **404** (not 403) for any private repository the token's scope couldn't see, identical to the repo not existing. `userCanReadRepo` and `userIsRepoAdmin` (`apps/relay/src/auth-github.ts`) both read that same 404 as "not readable," so a user could not add or configure a private repo they personally owned, and `permissions.admin` — read by `userIsRepoAdmin` to gate the AI-call-deadline write added in #9800 — was likewise never populated. Scope now includes `repo`; a signed-in user with a pre-existing session picks up the fix by signing out and back in.
