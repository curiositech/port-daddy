- **`enabled: false` now actually takes a cloud fleet ship out of service.** The daemon's FleetConfig parser honoured it, but the cloud executor's ship projection (`apps/shared/fleet-config.ts`, `fleetShipsFromDocument`) never read the key — it was not even declared on the parsed-agent type. Two parsers over one `pd-fleet.yml` disagreed about what pausing a ship means, and the one an operator would verify by reading was not the one that ran, so pausing a PR ship changed nothing about the comments it posted. The projection now skips a paused ship, matching the daemon's fail-closed semantics exactly: absent means enabled, `true`/`'true'` means enabled, and any other present value leaves the ship out of service so that `enabled: flase` cannot quietly put it back in. Also documented, and pinned in tests: pausing *every* ship matching a trigger returns null rather than an empty roster, which the executor reads as "no config" and answers with the built-in default ships — so pausing everything runs the defaults rather than nothing.
- **The four ideation ships (`spark`, `spider`, `lookout`, `snipe`) are paused.** Across one pull request they produced 23 advisory proposals of which 2 were actionable — one shipped as a code change in that same PR, one names a real gap still unbuilt — while the rest restated features already in the diff under review, targeted the wrong layer, or, in a later round, cited phrases from the review comments as evidence that the capability they described was missing. They are paused because they are advisory, not because they are worthless: the re-enable precondition recorded beside each one is a mechanical evidence gate that, replayed over all 23, suppresses the restatements and keeps both real findings. All four are `class: ideation` and never gated a merge, so this removes proposals rather than review; the blocking path (`qa`, `code-reviewer`, `red-team`, `test-author`, `tautology-sniffer`) is untouched and still runs on every PR.
