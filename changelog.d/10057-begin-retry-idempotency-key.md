- **A `pd begin` retried after a lost response no longer creates a second session or strands the first.** The daemon committed the session, the response died on the wire (socket reset, 10s client timeout), and every pd transport re-sent the identical body (`cli/utils/fetch.ts` socket-to-TCP fallback, `lib/client.ts` `_request`): with no identity, `--agent`, or `--force` the re-send minted a second agent + session and orphaned the first with its claims and rent; with an identity the resume path found the first session but the retry could not present the once-returned credential, so the daemon answered 403 and the agent could neither drive nor close the session it had just created. The pd CLI, SDK `begin()`, and MCP `begin_session` now send one `idempotencyKey` per logical begin (also accepted as the `Idempotency-Key` header); the new `lib/begin-idempotency.ts` store records `(key -> session)` beside the session and `POST /sugar/begin` answers a known key with the ORIGINAL session flagged `replayed: true`, the credential sealed under the key (HKDF/AES-256-GCM, only the key's hash is stored) re-opened for the requester. Keys are scoped to the (identity, agentId, worktree) they were recorded under (`IDEMPOTENCY_KEY_SCOPE_MISMATCH` discloses nothing), a key reused for a different begin is refused naming the recorded session (`IDEMPOTENCY_KEY_REUSED`), a replay presenting another actor's credential is 403, and a key whose session has closed starts a fresh begin. `pd begin` persists the attempt to `.portdaddy/begin-attempts/` BEFORE the request goes out, and the new `pd session find [--key K | --identity ID]` (`GET /sugar/find`) recovers the session afterwards: by key it restores the context file with the credential; by identity it lists the newest live sessions with `pd session takeover <id>` hints, never a credential. `tests/unit/sugar-begin-retry-idempotency-key.test.js` reproduces the byte-identical re-send on the real route and souls store; `tests/unit/begin-idempotency.test.js` and `tests/unit/pd-begin-idempotency-cli.test.js` cover the store and the client half.
