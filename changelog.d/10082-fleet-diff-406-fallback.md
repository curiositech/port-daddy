type: fixed

- **The Fleet executor no longer dead-letters a large pull request's required check just because GitHub refuses to render its raw diff.** GitHub returns 406 on `Accept: application/vnd.github.v3.diff` once a PR exceeds its own diff-rendering limits (over 300 files or 20,000 changed lines) — not transient, so the queue's four retries never helped and every push dead-lettered the "Port Daddy Fleet" check as infrastructure failure (observed on a 357-file PR, #10077). `fetchPRContext` in `apps/fleet-executor/src/github.ts` now treats a 406 as a signal to reconstruct a reviewable diff from the `/pulls/{n}/files` inventory instead: it walks every page of that endpoint (not just the first), rebuilds `diff --git` headers per file from `status`/`previous_filename`, and marks a missing `patch` as either a binary-file or too-large-to-include line so the reviewer still sees the file exists. Every other non-OK status still throws `PullRequestDiffFetchError` and fails closed, exactly as before. The reconstruction respects the same `MAX_DIFF_BYTES` ceiling as the raw path, and `PRContext` now carries a `diffSource: 'raw' | 'reconstructed-from-files'` field that shows up in the check-run summary and executor logs whenever a review ran on rebuilt evidence.
