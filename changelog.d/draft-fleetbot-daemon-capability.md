- **The daemon-side Ed25519 capability signer.** `lib/fleetbot-daemon-capability.ts` exports `createDaemonCapabilityProvider()`, the `CapabilityProvider` the publish client declares and deliberately cannot implement. Nothing in the tree minted a publisher capability before this, so deploying `POST /v1/fleetbot/publish` would still not have let an agent publish. It mints no key: it borrows the daemon's existing Phase 2 Ed25519 identity through a two-method seam (`signHex`, `phase2PublicKeyHex`) that `createHarborTokens()` already satisfies, keeping custody inside `lib/harbor-tokens.ts`. Each capability binds the repository, operation, session, base branch, base and head commit, the contract's canonical request hash and the account bearer hash, lives at most five minutes, and carries a fresh 32-byte nonce, so one minted for one action cannot be replayed for another. An absent, uninitialized, malformed or disagreeing key is a named refusal carrying no key material — there is no unsigned path and no fallback to any other credential. 42 round-trip tests verify minted capabilities against Relay's own `verifyAndConsumeCapability` rather than a second implementation of it.
