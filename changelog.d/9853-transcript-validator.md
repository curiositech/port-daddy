- **`pd fleet transcript` gains the pd-transcript.v1 format validator** (`docs/FLEET-SESSION-TRANSCRIPTS.md`'s "format validator tool"). `--validate` judges a fetched session — and `--file <capture.jsonl>` judges a LOCAL capture with no relay, credentials, or daemon — against the format's actual rules: major version 1, the closed kind/phase unions, non-negative integer `seq` that strictly increases across the capture, parts-array `content` of `{type:"text", text}`, well-shaped optional `chunk`/`usage`, boolean `truncated`. Where the tolerant renderers (web viewer, CLI turn cards, pd-console pane) deliberately skip bad lines, the validator is the opposite posture: one line = one verdict naming every rule violated (not just the first), a clean/failed summary, and exit code 1 on any violation so it composes into scripts and CI.
