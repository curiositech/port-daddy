\subsection{What isolation supplies, and what it leaves}\label{app:isolation}

The book's guarantees hold only for mediated events, the ones that pass
through the harbor's gate. In
\pdchapref{swk}{The Single-Writer Kernel},
Theorem~\ref{swk:thm:regimentation-controllability} takes $\Sigma_c$ to be the
set of events \emph{actually} mediated, and
Theorem~\ref{swk:thm:swk-control-game} shows that one unmediated exit, reachable
without any controllable step, makes every protocol unsafe against a
worst-case agent. The isolation layer underneath the gate decides which events
are mediated. That layer sorts an agent's possible effects into three classes.
An \pdterm{absent effect} is one for which no device, path or credential
exists. A \pdterm{gated effect} has a path that passes through a gate the
harbor owns. A \pdterm{residual effect} has a path that goes around the gate.
Guarantees attach to gated effects. A residual channel needs a bound on how
much it can carry, or an explicit statement that the guarantee excludes it; an
absent one needs no governing at all.

Table~\ref{tab:app-isolation-primitives} grades six primitives against that
sorting. The sources are Agache and colleagues on Firecracker, Young and
colleagues on gVisor, Klein and colleagues and Murray and colleagues on seL4,
Lehmann, Kinder and Pradel on WebAssembly, Chuang and colleagues on TEE.fail,
Marchand and colleagues on container escape, and Debenedetti and colleagues
on CaMeL; full references close this subsection.

Three consequences follow for the book's grades.

\paragraph{Confining hostile code needs a VM or microVM.}
The Confined mode requires that the process have no path to the protected
effect other than the paths it was given. A namespace sandbox shares the host
kernel with everything it protects. Marchand and colleagues, whose
SandboxEscapeBench measures how well language models escape container
sandboxes, recommend treating plain Docker isolation as insufficient by
default. The
hardening specified in \pdchapref{swk}{The Single-Writer Kernel}
(\S\ref{swk:sec:merkle}) runs each agent in a \texttt{bwrap} or
\texttt{unshare} sandbox under a throwaway user identity. That stops an agent
from using the daemon's files as if it were the daemon's own user. It does not
stop an agent that exploits the kernel both of them share. For an agent that
runs arbitrary code and may exploit kernel or runtime flaws, a Confined claim
needs a hypervisor boundary, with namespaces and system-call filters inside it
as a second layer of defense. Even a microVM keeps its network device.
Confinement removes the paths an agent was never given; it does not decide
what crosses the gated ones.

\paragraph{Leaks through allowed tools are a matter of content.}
Once isolation has fixed which events exist, an allowed channel carries
whatever data the policy lets through it. CaMeL separates a task's control
flow from its data flow, tags values with capabilities, and checks a policy at
every tool call. On AgentDojo, a benchmark of tool-using tasks with planted
prompt injections, it solves $77\%$ of the tasks with provable security,
against $84\%$ for an undefended agent. It lists text-to-text
attacks as a non-goal and acknowledges side channels. That is the same
structure as the attenuation of \pdchapref{anchor}{The Anchor Protocol} and the
labels and release gate of \pdchapref{sealed}{The Sealed Harbor}. A hypervisor
cannot supply it.

\paragraph{The model provider is a named principal.}
\pdchapref{sealed}{The Sealed Harbor} notes that a remote model interface is a
trusted reader of plaintext, and places the model inside the confidential
domain (\S\ref{sealed:sec:sealed-design}). When the parties cannot hold the
weights, the provider is a third principal and the work order must name it.
Confidential-computing inference moves that trust to the vendor's attestation
keys and to whoever has physical custody of the host. After TEE.fail, an
Attested claim must state physical custody as an assumption, because the
vendors exclude interposition from their threat models.

\paragraph{An enumeration protocol.}
\pdstatus{\Vision}{not yet run}
Run the reference worker under a namespace sandbox, under gVisor and under
Firecracker. For each, attack the channel list of the kernel chapter's
boundary item~(ii): raw sockets, DNS, inherited file descriptors,
\texttt{/proc}, credential helpers, package managers and provider callbacks.
Add escape tasks of the SandboxEscapeBench kind. Record from outside the guest
whether each channel is absent, gated or residual, and measure the capacity of
timing channels over the permitted output in bits per second. Logs written
inside the guest can support a finding but cannot settle it. The result is the
inventory of mediated and unmediated events ($\Sigma_c$ and $\Sigma_u$) that
the kernel chapter says only a red team can supply.
