# Why vocabulary intersection is not a semantic bridge

## What Annex A supports

The informative Annex A warns that overlap among formal models need not mean overlap among intended models. It discusses local intersections and a top-level ontology, presenting a common upper foundation as a useful design direction while acknowledging its difficulty. It is not a required FIPA negotiation protocol.

## Integration procedure

Start with the task inference, not label intersection. Compare axioms and intended conditions on the shared label, then ask whether both ontologies extend or otherwise relate to a named foundation. Where a foundation or declared relationship covers the task, restrict the exchange to that vocabulary. Otherwise retain an unresolved bridge and request curation or select another ontology.

Negative: coriander has a shared name but different properties. Positive: use a shared base `Fruit` vocabulary and exclude extension terms until a mapping exists.

Do not declare integration successful because two local ontologies share a label or syntactic model. The original block-world/coriander contrasts teach the procedure: list the task-relevant inference each party expects from a term, compare axioms and intended domain conditions, and test a shared fixture. Coriander can name one plant while one ontology concerns leaves and another seeds; intersection hides the material difference.

Where broad integration is required, record an explicit shared conceptual foundation or mapping contract and its extensions rather than computing label intersection. This is a design option, not proof that a top-level ontology resolves every mismatch. When no validated bridge preserves a task-essential inference, retain mismatch/escalation rather than silently flatten it.
