# Conversation as coordination with configured control

AutoGen's paper describes a conversable agent as one that can receive, react to, and respond to messages, with LLM, tool/code, or human capabilities. In the direct auto-reply pattern, the receiving agent first applies its termination/human-input/counter behavior; only a permitted path selects `generate_reply` and sends a reply to the sender. Built-in reply paths can use LLM inference, code/function execution, or human input. A developer can use `register_reply` to choose a custom function, including one that starts a nested conversation before returning to the sender (arXiv:2308.08155, §2.2; AutoGen 0.2 behavior is versioned).

**Hand-checkable trace.** Record `Assistant → UserProxy: proposed artifact`; then record which reply function UserProxy selected and the actual executor result/error it emitted; then record whether Assistant used that evidence in a changed reply. For direct pairwise control, this is the relevant auto-reply mechanism. It does not mean every AutoGen topology lacks a controller: group chat has `GroupChatManager`, and application code can add other controls. History is an audit aid, not complete state because tool effects, external resources, hidden model state, and omitted context may be absent. [Paper v2](https://arxiv.org/html/2308.08155v2); [0.2 ConversableAgent API](https://microsoft.github.io/autogen/0.2/docs/reference/agentchat/conversable_agent/), accessed 2026-09-24.
