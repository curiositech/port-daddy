# Human input as a versioned conversation setting

The paper's A1 first shows a two-agent math topology used autonomously, then says its Scenario 2 uses the same system with `human_input_mode='ALWAYS'` in the UserProxyAgent for human-in-the-loop problem solving. That is a paper-specific topology/configuration demonstration, not a general approval design.

In AutoGen 0.2, `NEVER` never requests human input and ends on the termination condition or auto-reply bound; `ALWAYS` requests input on every received message, letting the person skip, intercept, or exit, and ignores `max_consecutive_auto_reply` termination; `TERMINATE` requests input at a termination message or reply limit and can reset the counter when a person intercepts and replies. For a chosen application, record prompt event, input/skip/exit outcome, direct reply cap, and terminal reason. An unanswered prompt has only the behavior documented for the selected mode; human presence is not automatically an approval gate. [Paper v2](https://arxiv.org/html/2308.08155v2) A1; [0.2 human-in-the-loop](https://microsoft.github.io/autogen/0.2/docs/tutorial/human-in-the-loop/), accessed 2026-09-24.
