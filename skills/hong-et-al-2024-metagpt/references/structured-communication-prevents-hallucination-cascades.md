# Structured artifacts expose, not prevent, errors

The paper's software artifacts give a practical inventory: a PRD can carry user story, requirement, source, and open question; a design can carry file/module list, data structures, interface definitions, and interaction flow; a task can carry owner, dependency, and completion evidence; QA can carry fixture, observed result, and affected artifact version. Use ordinary documents before inventing a schema.

**Handoff check.** Before the Engineer acts, identify the consumer, confirm that its task points to the required PRD/design fields, and record what is missing. Before QA reports a result, link the executed fixture to the implementation version and the upstream requirement it exercises. Add a machine-checked schema only when the consumer and validator enforce it. Required fields make missing interfaces, test cases, or ownership inspectable; they cannot make an upstream assertion true or stop a downstream model from misreading it. Preserve source/version and open-question fields so a reviewer can trace a claim. The paper motivates this method; it does not establish automatic validation or hallucination prevention.
