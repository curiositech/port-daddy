# Capabilities, custody, and execution substrate

## Lazy tools and progressive skills

For a large tool catalog, expose a discovery step with name/short purpose, then load the full schema only for a chosen tool. Record the discovery result and selected schema version. Skills follow the same pattern: lightweight metadata can route a request while bodies and references load on demand. These are context-management options to measure, not mandatory architecture components.

## MCP topology

MCP is a protocol/topology choice, not a framework. When used, declare the finite global core and project-specialist split, then measure startup/context impact for the actual workload. A `not-applicable` MCP declaration must not also carry MCP configuration fields.

## Scoped secret custody

Secret-store references, scoped environments, and stdin can reduce exposure in particular paths. Review principal, lifetime, inheritance, logs, argv, transcripts, and revocation; no path is called universally safe. Required secrets in argv or inline text are explicit exposure findings.

## Coding and non-coding substrates

Coding work normally uses isolated worktrees/branches. Advisory claims communicate intended ownership; locking is reserved for a scarce non-mergeable resource and is not equivalent to a claim. A PR or reviewable change/evidence bundle is a useful finish-line policy, not proof of merge or deployment.

For non-coding work, the durable document/image/data artifact and its review evidence are the deliverable. An agent-authored helper needs the same scoped review and effect boundary as any other artifact. External or irreversible effects need authority, control, receipt, replay/compensation policy, and inert negative fixtures for unapproved, stale, duplicate, or receipt-failure inputs.
