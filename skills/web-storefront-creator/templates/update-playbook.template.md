# {{STORE_NAME}} — Update Playbook

Recipes for every routine change. Each one is the same shape: edit the catalog,
validate, dry-run, apply, verify. Commands are copy-paste; run them from
`{{REPO_PATH}}`.

## §1 Change a price

1. Open `{{CATALOG_PATH}}`. Find your product by its `sku` or `name`.
2. Change `price_cents`. **Prices are in cents**: $24.00 → `2400`. (This prevents
   the rounding bugs that decimals cause.)
3. Run:
   ```
   {{VALIDATE_COMMAND}}
   ```
   Expect: `0 errors`.
4. Dry-run the sync and READ the output — you should see one `REPRICE` line for your SKU:
   ```
   {{SYNC_DRY_RUN_COMMAND}}
   ```
5. Apply:
   ```
   {{SYNC_APPLY_COMMAND}}
   ```
6. Verify: product page on the site shows the new price (hard-refresh), and the
   product in {{PROVIDER_DASHBOARD_URL}}/products shows the new price.

> Behind the scenes: old prices are archived, never edited — payment history stays
> intact. {{IF_PAYMENT_LINKS: If you use payment links (QR codes, link-in-bio), they
> are regenerated by the sync — replace any printed QR codes after a price change.}}

## §2 Add a new product

1. In `{{CATALOG_PATH}}`, copy an existing product block that resembles the new one.
2. Change, in order:
   - `sku` — NEW and permanent, scheme `{{SKU_SCHEME, e.g. CNDL-ROSE}}`. Never reuse an old SKU.
   - `name`, `slug` (lowercase-with-dashes, permanent once published), `description`
     (your own words — see the copy checklist at the bottom), `price_cents`,
     `category`, `images`, and `inventory.quantity` if you track stock.
3. Add the photos to `{{IMAGES_PATH}}` — first image listed is the main one.
4. Validate → dry-run (expect one `CREATE` line) → apply → verify, exactly as §1 steps 3–6.

## §3 Sold out / restock

1. In the product's `inventory` block set `quantity` to `0` (sold out) or the new count.
2. Validate → apply. The site shows "sold out" and the Google/Instagram feed flips to
   out-of-stock on its next scheduled fetch (within a day).

## §4 Run a sale

1. Set `compare_at_cents` to the ORIGINAL price and lower `price_cents` to the sale
   price. The site shows the strike-through automatically.
2. Validate → dry-run → apply.
3. To end the sale: restore `price_cents` and delete the `compare_at_cents` line.

{{IF_PROMO_CODES: For discount CODES (e.g. FRIENDS10), create them at
{{PROVIDER_DASHBOARD_URL}}/coupons — set an expiry and a redemption cap. Warning:
if the parent coupon expires or hits its cap, its codes die permanently; make a
fresh coupon for each campaign.}}

## §5 Retire a product

1. Set `"active": false` on the product. **Never delete the block** — your sales
   history references it, and you may bring it back.
2. Validate → apply. It disappears from the site, feed, and checkout.

## §6 Update the words or photos

Descriptions and images live in the same catalog file — edit, validate, apply.
Copy checklist before publishing any new description:
- Would you say this sentence aloud at a market stall?
- At least two concrete specifics (material, hours, grams, process)?
- One honest detail (lead time, quirk, care note)?
- No "elevate", no "whether you're X or Y", no perfect triple bullets.

## §7 Monthly five-minute check

- {{PROVIDER_DASHBOARD_URL}}/payouts — money arriving where expected?
- {{PROVIDER_DASHBOARD_URL}}/disputes — anything needing a response (act within the deadline)?
- Google Merchant Center → Products — any disapproved items?
- `{{VALIDATE_COMMAND}}` — still `0 errors`?
- Low-stock: anything under its `low_stock_threshold`?

## If a step fails

The scripts never half-apply: an error means "fix the reported line and re-run."
The error message names the file and line. If it names something not in this
playbook, see FAQ §Sync errors, then {{SUPPORT_CONTACT}}.
