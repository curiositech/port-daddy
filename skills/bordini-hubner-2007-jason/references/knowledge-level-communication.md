# Communication as bounded evidence input

Retain the useful speech-act distinction: a message can announce, ask, tell, or request a goal. The receiver still needs a local admission rule for sender identity, scope, schema, and freshness. A received claim can become a candidate belief only after that policy; it is not a fact, execution permit, or capability.

For dependent work, correlate every request and response, define an absence deadline locally, and preserve the terminal record. A missing response is not a reason to broadcast an unbounded request or infer that a remote task stopped.

## Jason ACL effects and trust boundary

Jason interprets `tell` as adding a sourced belief, `achieve` as adding a sourced goal, and `unachieve` as asking a receiver to drop that sourced goal. `askOne`/`askAll` query beliefs; `askOne` with its fourth result variable suspends then resumes the sender intention. `tellHow`/`askHow` transfer plans; `signal` adds an event and repeated signals can produce repeated events.

For a request, retain correlation and expected peer locally, admit the received content by identity/schema/freshness policy, then decide whether it may affect a belief or action. `tellHow` expands an executable plan library and needs an explicit application trust policy. These performatives do not authenticate, guarantee delivery, create shared beliefs, or establish interoperability with another protocol. Jason [performatives guide](https://jason-lang.github.io/jason/tech/performatives.html), accessed 2026-09-24, supports the stated effects.
