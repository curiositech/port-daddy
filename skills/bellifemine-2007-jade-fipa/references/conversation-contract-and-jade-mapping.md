# Conversation contract and JADE mapping

## What the sources establish

The Wiley record identifies the 2007 book but not its body content. The JADE 4.6 FIPA Agent Management package documentation identifies an implementation package and maps its ontology to FIPA specification 23 (2001-08-15). That supports a narrow implementation-navigation claim only. It does not establish normative FIPA semantics for every interaction protocol, service availability, delivery guarantees, security properties, or business correctness.

## Preserve the useful Contract Net method

A local manager can use the following five stages: announce a bounded CFP, collect `PROPOSE` or `REFUSE` until its declared reply-by point, apply a predeclared comparator to the recorded proposals, notify selected and nonselected recorded candidates, then record an `INFORM`, `FAILURE`, or missing report. The method is useful because it makes the selection boundary observable. It is not evidence that a market is decentralized, fair, or optimal.

For a local comparator, define a total order only if the application actually needs one. For example, compare a proposal tuple `(formatSupported, quotedCost, completionEvidenceKind)` only after the requester has defined how unknown fields are handled. Preserve rejected and missing replies; do not treat the highest score as an authorization decision.

## Message correlation

Set a conversation identifier before sending; match the identifier and the intended sender/recipient relationship before admitting a reply to a behavior. If the chosen release supports a template helper, verify its exact name and matching semantics in its release documentation. The logical requirement is independent of any helper: a reply belongs to a local state only when its correlation, expected role, and schema version match.

## Negative fixture

A reply with the right performative but another conversation ID is not a bid for this CFP. A correctly correlated `INFORM` with an output digest that fails the application’s byte check is still a failed local verification. Neither condition is repaired by issuing another ACL message.
