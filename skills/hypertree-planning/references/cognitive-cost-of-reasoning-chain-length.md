# Chain length: illustrative arithmetic, not HTP causation

## Conditional calculation

If a hypothetical process has independent constant per-step error `epsilon=.02`, a 60-step all-correct probability is `.98^60`, so failure probability is `1-.98^60≈.7024`. This is ordinary probability arithmetic. It does not measure a model, establish independent errors, or explain HTP benchmark results.

A balanced four-way tree with 60 leaves has illustrative depth `log_4(60)≈2.95`; HTP does not promise a balanced tree, a branching factor of four, or a resulting error reduction.

## Measurement procedure

Before saying depth affects a deployment, define task, model/version, prompts, knowledge access, scoring, and what counts as a step. Compare at least two outline policies with the same acceptance test. Record total work, longest dependency path, retries, integration failures, and outcome quality. Treat shared constraints as dependencies rather than silently converting them to “parallel” work.

## Constructed comparison

A route and lodging outline can reduce a reviewer’s cognitive grouping burden, yet still require joint budget validation. Compare an outline-first run with a direct-content run, holding facts and acceptance criteria fixed. Report observed outcomes; do not extrapolate the result into a 30-step selection rule.
