# First-party protocol scope and formal limits

The three-pass process is first-party planning policy. Its commitment and confidence terms organize review; a confidence number becomes a probability only after a defined outcome, calibration method, and validation set are supplied. A policy may set a node-count, depth, tie, cascade, or schema-completeness threshold, but it must name version, owner, rationale, and abstention path.

[Erol, Hendler, and Nau (1994)](https://www.cs.umd.edu/~nau/papers/erol1994semantics.pdf) is a useful contrast: HTN planning needs task-network and method applicability/solution semantics. A `DecompositionResult` with topological waves has only the stated structural graph properties unless additional semantics are implemented and verified.

Structural checks can establish IDs, edge endpoints, output bindings, acyclicity, and topological order. They cannot establish a skill’s actual output, runtime readiness, capacity, effects, or authorization.
