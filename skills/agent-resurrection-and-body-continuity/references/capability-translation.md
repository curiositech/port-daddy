# Capability and Session Translation Reference

Load this reference when a successor uses a different harness, provider, model,
MCP transport, skill set, hook system, permission model, or session mechanism.

## Translation dispositions

| Disposition | Meaning | Rule |
|---|---|---|
| `EXACT` | same content-addressed contract and semantics | reauthorize exact scope |
| `EQUIVALENT` | different surface with passed semantic fixture | name adapter and evidence |
| `NARROWED` | safe subset | continue only if node remains satisfiable |
| `EMULATED` | broker performs effect outside body | body receives typed result only |
| `OMITTED` | optional capability unavailable | show omission in prompt and UI |
| `BLOCKED` | required capability unavailable | no successor launch |
| `UNKNOWN` | unproved semantics | block autonomous use |

No disposition transfers a bearer. Every destination grant binds person, body
generation, work reference, phase, manifest digest, exact operations/resources,
expiry, rate/capacity ceiling, and approval receipt.

## Surface rules

- **Skills:** content-addressed package and activation tests. Select only what the
  current node needs.
- **MCP/tools:** server and schema digest, operation/resource scope, transport,
  authorization, and effect class. Roots and annotations are not authority.
- **Permissions:** issue fresh destination grants; downgrade only when the plan
  remains satisfiable.
- **Hooks:** map to typed lifecycle events only with a tested adapter. Otherwise
  externalize or omit.
- **Prompts:** trusted identity/constraints, typed node contract, and sanitized
  capsule are separate channels. Historical bytes remain untrusted data.
- **Model settings:** translate intent such as reasoning depth, latency, context,
  and tool reliability. Marketing names are not equivalence evidence.
- **Transcript:** preserve source handle, digest, and bounded tail. Never treat a
  provider store as portable authority.
- **Worktree:** require normalized remote, exact base/head/tree/diff, device
  identity, and current ownership challenge.

## Native continuation truth

Major coding harnesses offer product-specific continuation, but no shared
portable session format is assumed. Native resume is eligible only after the
adapter proves current session retention, workspace binding, and the expected
tail. A provider may drop recent events, omit external filesystem changes, or
re-run an incomplete tool. The capsule and effect ledger remain authoritative.

Cross-family continuation always creates a new backend session and body
generation. The Promptwright renders a destination-specific briefing with:

1. current obligation and non-goals;
2. exact next safe action;
3. verified source/worktree state;
4. plan frontier and acceptance gates;
5. cited decisions and unresolved unknowns;
6. effect reconciliation status;
7. capability report and omissions;
8. capacity state and checkpoint threshold; and
9. explicit predecessor discontinuity.

## Conformance fixtures

For each adapter, prove native resume after clean pause, abrupt process loss,
provider session deletion, host reboot, missing transcript tail, incomplete tool,
worktree move, source-head drift, capability revocation, and context compaction.
If one case is unsupported, mark it. Do not interpolate from another backend.
