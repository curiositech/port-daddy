This fixture checks documentation completeness; it does not simulate a vessel or teach ship handling.

P1–P5 are synthetic row labels for a documentation-completeness fixture, not participant-level records or verbatim data. The thesis describes five selected participants meeting the criteria; this table checks that a local record names those criteria. It does not estimate population confidence.

## Cue test

A reviewer receives an engine-order execution cue card. It passes only if every row names (1) its GOMS goal/selection link, (2) observable form, and (3) its limited indication. It fails when it says “sound proves the ship responded,” because the source card supports an execution check, not that outcome claim.

| Record field | Source-bounded fixture value | Source pointer |
|---|---|---|
| Scenario | Twin-screw ship, empty pier, 1–2 knots of wind and no current; optional tug offered (underway tug or mooring rendezvous tug) | IV.B.1, printed pp. 44–45 |

| Final review | All five selected validators chose the offered tug; all found the no-tug model inaccurate without tug procedures | IV.C.3, printed p. 50 |
| Reported rationale and revision | Participants said no-tug pier-side handling was very rare because of damage consequences; Grassi revised the model to include tug procedures | IV.C.3, printed p. 50 |
| Limit | Five selected validators and two generic/simple simulator evolutions; not universal guidance | VI, printed pp. 113–115 |

A record that says only “tugs considered” fails. A record that suppresses the initial no-tug assumption, omits the final model revision, or denies the reported all-five result also fails. Do not turn this bounded finding into a rule that all ships or operations must use a tug.
